# EasyCode 现有能力深度优化计划

## 目标与边界

本计划只强化 EasyCode 已经具备的 Windows、PC 模拟器、通过 ADB 连接的 Android 真机、
2D 视觉/OCR、页面拓扑、Player 和多实例能力。当前阶段不引入 3D 场景定位、姿态识别、
目标跟踪或手机端独立 Player APK。

所有降级都必须可见、可解释、可阻止。截图、输入或执行结果未经验证时，不得伪报成功；
物理输入回退继续由项目设置显式授权，默认关闭。

## 不可破坏的现有契约

- 子项目资源和配置只写入当前工作区。
- 业务流程与页面拓扑分别自动保存，切换模式前必须完成待保存写入。
- 同一目标窗口或 ADB serial 同时只能被一个执行实例占用。
- 弹窗处理与拓扑导航保持分离；非界面节点不触发页面扫描。
- 捕获模式和逐帧录制不能与运行、调试并存。
- 录制原始帧默认无损、不可被系统自动删除；用户可选择空间配额策略。

## 分阶段实施

### A. 性能与正确性基线

- 建立结构化运行指标：捕获提供器、有效 FPS、帧年龄、预处理、匹配、OCR、输入、队列和资源占用。
- 建立 500/2000/5000 节点合成画布以及 1/2/4/8 实例执行基准。
- 去除文档中的固定测试数量，改为由测试命令生成结果。

### B. 编辑器热路径

- 自动保存防抖结束后才生成快照，连续编辑只深拷贝一次。
- 资源预览只在资源自身变化时失效，不受节点位置、连线和变量变化影响。
- 画布使用节点、任务和选择索引；拖动期间冻结无关连线路由和预览。
- 大规模资源树和画布按视口/展开状态惰性渲染。

### C. Windows 捕获能力

- 捕获能力分为：后台新鲜帧、必须前台、明确不支持。
- 检测黑帧、近似纯色帧、冻结帧、旧帧、尺寸/DPI 异常和最小化状态。
- 接入常驻 Windows Graphics Capture 提供器；保留 PrintWindow、DXGI/dxcam 和前台截图回退。
- 每个目标只建立一个最新帧代理，下游按区域裁剪并共享同一帧。

### D. 输入结果与物理回退

- 统一输入结果：`verified`、`delivered_unverified`、`unsupported`、`failed`。
- 节点可用图像消失、目标出现、页面到达等后置条件验证输入效果。
- 保存按窗口进程/类名/版本生成的能力档案；目标版本变化后重新验证。
- 物理回退只执行一次并持有全局物理输入锁；未授权时阻止执行并给出设置路径。

### E. 视觉与拓扑热路径

- 每帧只生成一次 RGB/BGR/灰度表示。
- 页面特征与图像节点共享模板缓存；同区域 OCR 共享结果。
- AND/OR 默认短路，详细诊断模式才完整评估全部条件。
- 页面特征按成本排序；启动时编译拓扑候选与预加载可能使用的模板。
- 多页面同时命中时输出排序候选，不静默选取第一个。

### F. 多实例隔离

- 每个执行实例运行于独立 Worker 进程，由主进程监督。
- OCR/推理使用有界并发池；捕获和输入由目标资源租约管理。
- 根据节点状态自适应采帧：界面等待高频，纯计算/等待节点降频或停采。
- Worker 异常、ADB 断线和窗口关闭只影响所属实例，并使用有界重试、退避和熔断。

### G. 逐帧录制与离线回放

- 捕获线程和磁盘写入线程分离，使用有界队列并公开写入延迟和丢帧指标。
- 默认保留每张无损原始帧；另提供按变化记录、诊断事件记录、FPS 和空间配额模式。
- 录制会话保存时间轴、屏幕工作区、目标信息、捕获后端和每帧校验信息。
- 历史帧工作台支持缩略图时间轴、键盘逐帧、快速跳转和相似帧折叠。
- 任意历史帧可作为只读冻结帧送入现有原生捕获宿主，无需打开或激活原目标窗口。
- 在历史帧上复用点、图像、OCR、页面和资源录入；保存成功后按当前捕获链语义生成节点。
- 录制会话可离线执行图像、OCR 和页面识别并导出逐帧命中/耗时报告。

### H. Player 运维

- 运行前显示捕获、输入、ADB/OCR 和资源能力报告。
- 每个实例显示 FPS、帧年龄、识别耗时、输入通道、队列、CPU/内存和重连次数。
- 失败诊断包包含最近帧、结构化事件、版本、能力档案和已脱敏配置。
- 账号、密码和 Token 使用秘密字段；日志、导出和诊断包自动脱敏。

## 验收矩阵

### 自动化测试

- Python 单元/API/执行器/资源/Player 测试全通过。
- Vue 组件、Store、API 契约和画布全流程测试全通过。
- 录制写入拥塞、磁盘不足、坏索引、资源撤销和会话切换故障注入。
- 固定历史帧的图像、OCR、页面识别回归结果稳定。

### Windows 与设备测试

- 普通 Win32、Electron、自绘/GPU 窗口、遮挡、最小化、DPI、多显示器。
- 后台输入支持/不支持、物理回退开/关、后置验证成功/失败。
- ADB/scrcpy 断线重连、分辨率旋转、模拟器多开 serial 唯一性。
- 1/2/4/8 实例压力与长时间稳定性；一个 Worker 崩溃不得影响其他实例。

### 编辑器性能测试

- 连续表单输入期间只生成一次最终保存快照。
- 移动节点时未变化资源的缩略图请求为零。
- 大画布拖动只更新选中节点及受影响连线，模式切换不丢失任何修改。

## 2026-08-25 实施与验收记录

### 已落地

- Windows 捕获形成 WGC 常驻后台帧、PrintWindow 兼容、激活目标后 DXGI 前台截图三级链路；
  关闭、最小化、黑帧和尺寸/DPI 裁剪异常均不会静默冒充正常后台帧。
- 输入统一返回投递状态并支持视觉后置验证；能力结论按窗口进程、类名和版本保存；物理输入
  回退默认关闭，显式开启后只回退一次并受全局物理输入锁保护。
- 最新帧单槽缓存、自适应采帧、模板缓存、同帧 OCR 缓存、AND/OR 短路和页面候选歧义报告
  已接入执行热路径。
- 每个 Player 实例使用独立 Worker 进程；OCR 推理有界并发；Worker、ADB 重连和窗口故障只
  影响所属实例。Windows 控制台编码和跨进程停止事件均已验证为不可中断业务执行。
- 画布在大规模项目中只挂载视口附近节点和连线，仍保留完整路由几何、选中和拖动对象；
  资源缩略图按批次惰性加载，资源版本与画布位置修改解耦。
- 逐帧录制提供全部帧、变化帧、变化与手动标记三种策略，捕获/写盘分线程并公开队列、
  写入延迟、丢弃和空间指标；每个落盘帧保存 SHA-256。
- 历史帧工作台提供缩略图时间轴、键盘逐帧、播放、变化帧跳转、相似帧折叠、单帧离线识别、
  整段视觉回归和 JSON 报告导出。任意历史帧可直接送入现有原生捕获链创建点、图像、OCR、
  页面或资源，无需启动、激活原应用。
- Player 保存配置、配置方案和恢复点会加密秘密字段；Worker 日志、状态和诊断包统一脱敏；
  诊断包含最后一帧、失败截图、运行指标、版本与目标能力档案。
