# 颜色值输入与取色规范

状态：已冻结并实施  
适用范围：IDE、Windows/ADB Player、Android 本机 Player、扩展参数默认 Control

## 1. 目标与非目标

颜色是基础强类型值，不应退化为只能引用变量的通用表达式，也不应要求作者先调用 `颜色.读取` 才能填写固定颜色。本切片统一固定颜色输入、系统色板和目标画面取色；不增加调色盘管理、渐变或颜色空间转换。

## 2. 需求

- `REQ-COLOR-001`：`color` 固定值使用唯一的 RGBA Control。界面同时显示色块、十六进制文本和 0–255 透明度；接受 `#RGB`、`#RRGGBB` 与 `#RRGGBBAA`，显示时使用大写规范形式。
- `REQ-COLOR-002`：ProgramDocument 继续以 `record_type=color` 和 `color.field.red/green/blue/alpha` 保存；表达式输入只是该强类型树的投影，不能新增字符串颜色事实。
- `REQ-COLOR-003`：颜色参数可以声明 `pick-color`。动作在当前目标的一张冻结原帧中点选一个像素，返回该像素不透明 RGBA 值；展示缩放不得改变采样坐标。
- `REQ-COLOR-004`：IDE 与 Player 复用同一颜色 Control、动作 ID、结果形状和校验。Player 动作仍由作者逐字段、逐平台发布，并进入签名权限闭包。
- `REQ-COLOR-005`：取消、拒绝、目标离线、宿主失败、会话/revision 变化或点位越界均保留旧值；不得回填黑色、透明色或部分字段。
- `REQ-COLOR-006`：运行时 `颜色.读取` 保持普通函数语义；字段取色是作者/终端用户主动触发的 Control 动作，不能被脚本静默调用。

## 3. 失败语义

固定文本格式错误时保留输入草稿并就近说明格式。冻结帧确认必须同时校验请求、项目或产品、目标、字段、方案 revision、帧尺寸和点位；任一失败拒绝整次提交。Player 运行、暂停或停止过程中禁用取色。

## 4. 验收

- `AC-COLOR-001`：新插入 `颜色.查找` 时无需先造变量，可直接填写 `#616264` 并保存为 RGBA `(97,98,100,255)`。
- `AC-COLOR-002`：系统色板、十六进制和透明度任一修改后，另外两种投影立即一致；八位十六进制保留 alpha。
- `AC-COLOR-003`：IDE 在 Windows/ADB 目标冻结画面取色后原子回填；取消和过期结果不改旧值。
- `AC-COLOR-004`：作者开放 `pick-color` 后，Windows/ADB Player 可从绑定目标取色；未开放、未保存方案或运行中不能执行。
- `AC-COLOR-005`：Android 本机 Player 的冻结画面可取色，并通过同一发布闭包、目标和 revision 校验。
- `AC-COLOR-006`：共享 Control、函数契约、生成类型、Player 预检、发布闭包和冻结运行边界测试全部通过。
