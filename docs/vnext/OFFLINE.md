# 本地优先与离线运行

状态：`Approved`（核心离线边界、官方文本/JSON HTTP 与独立文件上传/下载、无云 LAN 配对/消息/调度、可关闭在线更新与无遥测灰度已冻结；商业授权已移出首版）

最近修订：2026-09-01

本文冻结 Windows 与 Android Player 的本地优先边界。这里的“离线”是指没有公网、没有 EasyCode 云服务、没有活动 IDE 或单独安装的开发后端；Player 包内随程序启动的本地 Runtime/受控 Worker/IPC 属于发布物自身，不属于外部服务依赖。

## 1. 产品结果

没有显式引入公网能力的项目必须作为完整本地应用运行。Windows Bundle 或 Android APK 安装完成后，即使公网不可用、IDE 与开发后端关闭，用户仍能加载运行方案、填写表单、校验、运行、暂停、继续、停止、读取本地文件、执行视觉/OCR/输入并查看日志与诊断。

离线是合法运行状态，不是全局故障。项目只有在实际调用消息、局域网调度、普通 HTTP 请求或 HTTP 文件上传/下载等网络能力时才受对应连接影响；连接失败按当前语句或计划条目的普通错误契约处理，不把 Player 外壳、无关本地函数、运行方案或本地计划标记为不可用。失败的文件下载还必须保留原目标文件，不能把网络故障转化为本地数据损坏。

## 2. 三类网络依赖

Compiler Service 根据真实函数调用、功能扩展和 `easycode-extension.json` 自动形成网络能力清单，开发者不能只靠一个容易失真的手工开关声明“离线”。发布报告与 Player 环境详情使用三类稳定含义：

1. **无网络**：运行闭包不需要套接字、局域网或公网；允许包内进程间 IPC和本机计划触发，但不得连接 IDE、EasyCode 服务或开发机。
2. **本机/局域网**：只为明确的 `消息.*`、配对、LAN 远程计划或指向 loopback/LAN 的 `网络.请求`、`网络.上传文件`、`网络.下载文件`访问本机或 LAN；不依赖公网与 EasyCode 云。
3. **公网**：项目主动调用指向公网的普通 HTTP、文件上传/下载、其他 API/远程服务或声明公网权限的扩展；必须在发布报告中定位到函数/扩展、批准主机范围、文件读写权限和用途。

ADB/USB 是目标或开发通道，不等同于公网。Android 系统权限也不等同于在线授权。

## 3. 稳定需求

- `[REQ-OFF-001]` 未声明公网能力的 Windows Bundle 与 Android APK 必须在无公网、无 IDE、无 EasyCode 云/开发后端时完成本地核心运行闭环。
- `[REQ-OFF-002]` Publisher 必须把 Runtime、Recorder/Replay、函数、官方图像/OCR 回放实现、Control、资源、OCR 模型/字典、字体/图标、原生库和 `easycode.lock` 选择的兼容密封扩展产物全部写入发布闭包；Player 运行时不得补下载必需依赖，兼容扩展不能因此取得首版离线回放入口。
- `[REQ-OFF-003]` 函数、功能扩展和 `easycode-extension.json` 必须声明“无网络 / 本机或局域网 / 公网”能力；Compiler 从真实引用计算最终网络清单、权限和发布报告。
- `[REQ-OFF-004]` 未启用在线维护能力且无公网声明的项目不得在启动、环境检查、任务创建或执行热路径中隐式登录、在线验权、检查更新、上传遥测/崩溃、加载 CDN 字体图标或访问远程模型。
- `[REQ-OFF-005]` Player 可以使用发布包内的本地 Runtime、Worker 和 IPC；这些组件必须随包启动/停止并在证据中与 IDE、单独安装的 FastAPI 后端或远程服务区分。
- `[REQ-OFF-006]` 显式公网函数遇到无网络、DNS、连接、TLS、鉴权、限流或超时异常时，只向当前调用返回结构化失败；HTTP 服务端状态仍按网络函数契约返回正常响应。异常区域可以显式捕获，并且只在策略开启时重试瞬时异常；Runtime 与本地数据保持可用。
- `[REQ-OFF-007]` 同机与局域网消息不得依赖 EasyCode 云。协调器不可达、局域网不可达和收件实例未上线使用不同状态，只影响对应消息副本与等待语句。
- `[REQ-OFF-008]` 更新检查和未来商业授权不作为核心 Runtime 的隐式依赖；平台不提供自动运行遥测或崩溃上传。当前规格未启用的能力不显示入口；未来新公网能力必须单独声明、可定位且失败不终止正在运行的本地任务。
- `[REQ-OFF-009]` 未来若加入商业授权，不得要求每次启动或每次任务联网。Player 使用本地可验证凭据决定是否允许新任务；刷新服务不可达不等于凭据失效，任务运行中到期不得强制中断。有效期、宽限期、换机和吊销另立商业规格。
- `[REQ-OFF-010]` 更新服务不可用时只能显示“尚未检查”或具体失败，不得伪报“已是最新”，也不得阻止当前兼容 Runtime 打开包或中断运行/暂停现场。没有已生效最低版本约束时不得阻止新任务；已缓存且超过宽限期的可信强制策略不能因服务不可用而解除。任务运行网络与在线维护网络必须分别报告。
- `[REQ-OFF-011]` 日志、截图、录制帧、离线分析与诊断默认保存在设备本地；只有用户主动导出或项目显式调用已声明联网能力时才能离开设备，并继续遵守脱敏与权限契约。录制默认导出排除分析快照，高级可重现导出逐类披露其代码/ECIR、资源、模型和参数；更新、托管和普通遥测不得取得录制内容。
- `[REQ-OFF-012]` Android 发布器对完全本地项目不得为更新、遥测或依赖下载引入隐式公网访问；本地视觉、OCR、输入、文件与 Player UI 不依赖 Google Play 服务或 EasyCode 云。
- `[REQ-OFF-013]` IDE 在本地工具链与依赖已安装时可以断网编辑、校验、编译和本地调试。首次缺少 SDK/依赖时报告具体缺失项与安装入口，不能把“工具链尚未安装”描述为项目必须联网运行。
- `[REQ-OFF-014]` 发布报告必须显示“可完全离线 / 需要本机或局域网 / 需要公网”，并列出造成该结论的函数、扩展和服务；Player 只在相关能力即将使用或用户打开环境详情时显示网络信息。
- `[REQ-OFF-015]` 扩展不得绕过 Manifest 发起未声明网络访问；平台无法可靠隔离的受信任原生扩展必须在权限与发布报告中明确标记，不能获得“完全离线”结论。
- `[REQ-OFF-016]` 启用强制更新的发布必须把它列为维护可用性约束：任务执行可以本地完成，但客户端取得并缓存签名最低版本策略后，宽限结束会阻止旧版本新开任务；运行和暂停现场不受影响。
- `[REQ-OFF-017]` 终端关闭“自动检查普通更新”后不得请求可选版本；若作者启用了强制策略能力，独立 Policy Checker 仍以公开说明的低频错峰方式取得签名最低版本策略，但不下载或安装产物。已经验证的策略不因普通开关或断网失效；尚未取得的新策略不能被离线客户端猜测。
- `[REQ-OFF-018]` `网络.请求`、`网络.上传文件`和 `网络.下载文件`必须在调用开始时才访问经过声明的本机/LAN/公网目标；连接失败只返回当前语句，不能让 Runtime、Player 或无关本地任务进入全局离线故障。
- `[REQ-OFF-019]` 同机自动信任、跨设备短期码/二维码配对、普通消息和 LAN 远程调度不得依赖 EasyCode 云、账号、公网发现或公网中继。
- `[REQ-OFF-020]` 本机单次、每日和固定间隔计划不得依赖公网；计划拥有者与远端之间 LAN 不可达时，只影响对应远端条目并按 TTL/错过策略处理。
- `[REQ-OFF-021]` Windows Hub 可以在公网阻断时启动本机已安装项目；Android 本机只能计划当前 APK 的方案，且系统后台/权限限制必须作为本地阻塞而不是网络故障。
- `[REQ-OFF-022]` 未知或未授权 LAN 实例必须立即失败；已知离线消息或派发只能在业务 TTL 内保留原 ID，不得因等待而连接云端。
- `[REQ-OFF-023]` 网络、配对、消息、计划、运行与更新诊断默认保存在设备本地；只有用户主动导出或项目显式网络调用才可离开设备，首版不得自动遥测或建设云端在线设备面板。
- `[REQ-OFF-024]` HTTP 文件上传/下载只因项目显式调用而联网；上传文件内容和下载目标不得成为平台遥测。下载失败必须保留原目标，且任何文件传输失败都不得阻止无关本地任务继续。

## 4. 生命周期与失败语义

```text
Player 读取本地签名包
        ↓ 本地校验格式、签名、权限与依赖闭包
创建运行方案覆盖并启动本地 Runtime
        ↓
执行本地语句 ───────────────────────────────→ 正常继续
        ↓ 遇到显式 HTTP/HTTP 文件传输/消息语句
Runtime 尝试已授权 LAN/公网连接
        ↓ 失败
当前调用返回结构化错误 → 项目错误策略处理

本机计划到期 ───────────────────────────────→ 创建本机普通任务
        ↓ 含远端条目
Plan Service 尝试已配对 LAN 派发
        ↓ 失败
只更新对应条目状态 → 其他实例继续
```

Player 启动和本地包校验不通过“先访问服务器”决定成败。显式网络调用可以等待、超时、失败，或由带策略的异常区域重试被标记为瞬时的异常；这些行为不能让 UI 无响应、损坏本地运行方案、删除未发送消息或把其他本地运行实例判为失败。重试网络副作用前必须经过作者审核，平台不保证远端回滚或幂等。

## 5. 交互规则

- 无网络依赖的项目断网时不显示常驻红色“离线”横幅，也不弹阻塞提示；环境详情可以显示“本地运行就绪”。
- 发布检查显示网络级别和来源，例如“需要公网：扩展函数 `支付.查询订单`”；不能只显示一个无解释的网络图标。
- 联网函数失败时，运行输出显示失败层级、当前语句、目标服务和恢复方式；网络基础设施故障可以汇总到问题中心，但右侧参数表单不被无关错误挤占。
- HTTP `4xx/5xx` 显示真实响应状态；DNS、连接、TLS、重定向、超时、大小和权限错误不得统一写成“网络失败”。文件传输还要区分引用失效、读取失败、临时写入失败和原子提交失败。URL、认证头、正文与文件引用按 [`NETWORK.md`](NETWORK.md) 脱敏。
- 消息状态区分“等待连接协调器 / 局域网不可达 / 收件实例未上线 / 等待读取 / 已过期”，不统一写成“离线”。
- 计划状态区分“拥有者未运行 / 已知远端离线 / 未知或未授权实例 / 目标离线 / 权限不足 / 实例忙 / 已错过”，不把部分条目失败升级为全局离线。
- 更新服务不可达使用安静的就地状态；许可证入口只有对应产品能力真实存在时显示。
- Windows 与 Android 使用相同语义。Android 飞行模式下，本地项目正常运行；只有显式 LAN/公网步骤显示局部失败或等待。

## 6. 验收映射

- `[AC-OFF-PKG-001]` 清空预热缓存并阻断出站公网后，Windows Bundle 在无 Python、无 IDE、无单独后端环境完成本地核心项目。
- `[AC-OFF-AND-001]` Android APK 在飞行模式、断开数据线并关闭 IDE/后端后完成 Player 表单、视觉/OCR、输入、文件、日志和暂停/继续/停止闭环。
- `[AC-OFF-CLOSURE-001]` 发布包内包含全部函数实现、资源、OCR 数据、字体/图标、原生库与扩展；删除任何必需闭包项会在发布或本地加载时明确失败，不触发运行期下载。
- `[AC-OFF-CONN-001]` 完全离线项目运行期间不产生公网 DNS/TCP/HTTP；包内 loopback/IPC 单独记录并证明只连接随包组件。
- `[AC-OFF-NET-001]` 显式公网函数覆盖断网、DNS、连接、TLS、鉴权、限流、服务端和超时失败，诊断定位当前语句，普通错误处理仍能继续执行不受影响的本地步骤。
- `[AC-OFF-MSG-001]` 公网断开但同机/LAN 可用时消息继续传输；协调器或 LAN 不可用时保留消息 ID、有效期和真实副本状态，不伪报已读。
- `[AC-OFF-UPD-001]` 更新端点不可达不影响 Player 打开或运行/暂停现场；没有已生效最低版本约束时可以创建本地任务，已有且超过宽限期的可信策略继续限制新任务；界面不伪报版本已是最新。
- `[AC-OFF-UPD-CONTROL-001]` 关闭普通自动检查后不再请求可选版本；启用强制策略能力时只保留已披露的签名策略请求。作者打包关闭全部更新时，Player 重启、空闲和任务开始均没有任何更新外连。
- `[AC-OFF-LIC-001]` 若未来启用授权，有效本地凭据在断网时允许新任务；任务运行中到期不被中断，具体过期策略由商业授权规格验收。
- `[AC-OFF-IDE-001]` 本地工具链齐全时 IDE 断网仍可编辑、校验、编译和调试；缺少工具链时诊断指出缺失组件而不是项目联网要求。
- `[AC-OFF-EXT-001]` 未声明网络访问的扩展发生外连时被阻止或使发布失败并定位扩展/函数；声明公网的扩展不能获得“完全离线”报告。
- `[AC-OFF-UX-001]` 无网络依赖任务在断网时没有阻塞性错误；每个连接错误都说明失败层级、受影响操作和恢复方式。
- `[AC-OFF-HTTP-001]` 公网 HTTP 被阻断时只让对应请求返回 DNS/连接/TLS/超时结果，本地函数、运行方案、Player 外壳和另一个无网络任务继续工作。
- `[AC-OFF-HTTP-FILE-001]` 公网阻断、连接中断或远端错误只让对应上传/下载语句失败；上传内容不进入平台诊断，下载原目标哈希保持不变，另一个本地任务与 Player 外壳继续工作。
- `[AC-OFF-LAN-PAIR-001]` 公网阻断且无 EasyCode 账号时，同机自动信任和跨设备短期码/二维码配对、消息与 LAN 调度仍可完成；抓包没有公网发现或中继。
- `[AC-OFF-SCHEDULE-001]` Windows Hub 在无公网时按单次/每日/间隔计划启动本机项目；远端 LAN 断开只改变对应条目，Android 本机计划当前 APK 时不访问云端。
- `[AC-OFF-TTL-001]` 未知实例立即失败；已知离线消息和远程派发分别在自身 TTL 内保留原 ID，过期后不继续投递，也不回退公网。
- `[AC-OFF-DIAG-001]` 本地诊断与主动脱敏导出工作正常，网络审计证明没有终端心跳、在线设备列表、消息/HTTP 正文、崩溃或任务结果自动上传。
- `[AC-OFF-REPLAY-001]` Windows 与 Android Player 在阻断公网、关闭 IDE/后端后仍能录制、浏览、官方图像/OCR 离线分析、历史 Capture 和两种显式导出；默认包不含分析快照，高级包内容与披露清单一致，抓包证明平台没有自动上传录制或分析数据。

## 7. 当前不扩大范围

- 首版提供 [`NETWORK.md`](NETWORK.md) 定义的官方类型化普通 HTTP 请求及独立文件上传/下载。浏览器 DOM、WebView 自动化、WebSocket、任意流对象、断点续传协议和任意 Socket 不因这些能力进入范围；文件流式读写只是 Runtime 的有界实现，不成为 ProgramDocument 可编辑数据类型。
- 首版不提供商业授权；该能力保留为后续独立垂直切片。首版提供可关闭的分层在线更新，完整契约见 [`UPDATES.md`](UPDATES.md)。平台自动遥测和云端在线设备面板明确不进入首版；本机诊断只有用户主动导出后才离开设备。任何能力没有完成规格和后端闭环前不显示入口。
- 公网消息/调度中继、云端在线设备面板、云同步、远程项目、在线素材与扩展市场不因“允许显式公网能力”自动进入范围。
- 许可证有效期/宽限期、更新频率与回滚、遥测字段/保留期、网络权限是否精确到域名端口等参数由各专题与 Harness 冻结，不能反向改变核心离线结果。

## 8. 当前 LAN 离线证据（2026-09-01）

- **自动验证通过**：Windows loopback 双进程真实 socket 在没有 EasyCode 云或账号参与的情况下完成配对、消息、已读和远程 dispatch；已知离线消息重启后复用原消息 ID，未知/未授权目标不创建队列，LAN 失败没有公网中继分支。
- **自动边界检查通过**：测试进程的出站连接守卫只允许 loopback/private 地址，HTTP 管理端只通过本机路由暴露，并显式报告 `cloud_relay: not_in_product_scope`。
- **未验证**：真实第二台电脑、Windows 防火墙允许/拒绝、物理断网后重连、操作系统级抓包和 Android 真机。上述自动边界检查不能替代 `[AC-OFF-LAN-PAIR-001]` / `[AC-NET-NOCLOUD-001]` 的真实无公网抓包证据。
