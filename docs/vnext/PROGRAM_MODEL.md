# 结构化程序模型

状态：`Approved`（格式 6 ProgramDocument、稳定 ID、结构语义、值边界与 ECIR 关系已冻结）

最近修订：2026-09-02

## 1. 定位

EasyCode 不把可手写文本源码作为项目函数的编辑入口。项目函数的唯一可编辑事实是版本化的 `ProgramDocument`；IDE 通过纵向结构化语句投影展示该文档，左侧函数库负责创建调用，右侧检查器负责修改参数、返回绑定和当前结构化对象。

`ProgramDocument` 是有类型的项目数据模型，不是一门需要用户学习的语言。它没有关键字、词法、缩进规则、解析器或格式化器。用户界面使用中文显示名和自动语句摘要；持久化字段、类型 ID、函数 ID 与平台契约使用稳定英文标识。

```text
函数库插入 / 语句排序 / 右侧 Control
                  │ 结构化命令
                  ▼
           ProgramDocument
             │          │
             │投影      │确定性编译
             ▼          ▼
       纵向语句编辑器   ECIR
                            │
                            ▼
              Windows / ADB / Android Runtime
```

## 2. 核心要求

- `[REQ-PGM-001]` 每个项目函数拥有稳定 `function_id`，每条语句拥有稳定 `statement_id`，每个局部符号拥有稳定 `symbol_id`，每个持久化可配置值节点拥有稳定 `value_id`；重排、折叠、改名和参数修改不得改变无关对象的稳定 ID。
- `[REQ-PGM-002]` ProgramDocument 使用版本化、确定性 JSON 持久化。相同模型必须产生字节级稳定的字段顺序与值表示；业务文档不得混入滚动位置、选中项和临时展开状态。
- `[REQ-PGM-003]` ProgramDocument 是 IDE 中项目函数的唯一可编辑数据源。语句编辑器、检查器、变量工作区、Player 绑定和调试器均通过结构化命令读写或引用同一模型，不维护平行参数对象或可编辑文本源码。
- `[REQ-PGM-004]` 普通用户不能通过文本编辑器直接修改项目函数。系统可以生成只读伪代码、诊断文本或导出表示，但派生文本不得成为第二个可保存数据源。
- `[REQ-PGM-005]` ProgramDocument 至少支持函数调用、结果绑定/赋值、条件分支、循环、跳出循环、跳过本轮、返回、结束为失败、异常区域、目标作用域和监听声明。新增普通函数只注册函数契约并继续使用 `call`，不得为每个函数增加新的语句种类。
- `[REQ-PGM-006]` 参数值使用带稳定 `value_id` 的类型化值节点表达显式未配置值、常量、项目变量、局部符号、资源、目标、成员访问、容器和纯值表达式。没有默认值的必填参数使用 `unset` 节点保持结构合法和字段可定位；`unset` 会阻止编译/运行/发布，但不会让整份文档不可编辑。显示名不作为执行或长期绑定键。
- `[REQ-PGM-007]` 所有编辑使用结构化命令，并产生可撤销、可重做、可事务保存的模型变更。删除、移动、提取函数和类型变化必须先计算引用影响。
- `[REQ-PGM-008]` 保存先校验模型 Schema 与引用完整性，再写入同目录临时文件并原子替换。失败时内存模型和撤销历史保持可用，磁盘旧版本不得覆盖用户当前编辑。
- `[REQ-PGM-009]` IDE 调试和 Player 发布均先把 ProgramDocument、函数契约、资源与目标编译为同一版本的 ECIR；不得建设“IDE 直接解释 ProgramDocument、Player 执行 ECIR”两套业务语义。
- `[REQ-PGM-010]` ProgramDocument 不进入 Player 发布包。发布包只包含 ECIR、函数契约、依赖闭包、资源、Player Schema、目标配置和发布报告。
- `[REQ-PGM-011]` 条件使用强类型树：布尔值与类型化比较作为叶节点，“全部满足 / 任一满足 / 取反”作为组合节点。条件 Control 可把规范批准的可选值、数值、文本、列表和字典简写物化为显式布尔树；持久化模型与 Runtime 禁止其他隐式真假转换和有副作用操作，`all/any` 按投影顺序短路；正常未命中与异常保持不同语义。
- `[REQ-PGM-012]` 函数调用只有一个逻辑返回值；多项相关结果使用带稳定 `field_id` 的不可变命名记录。“有值 / 无值”使用 `optional<T>` 和明确空状态，用户投影统一为“有结果”。存在性收窄用于把无结果作为正常分支处理；未收窄时直接访问成员表示该值是当前语句的必要前提，空来源在 Runtime 以 `runtime.optional_empty` 结构化异常停止运行，不得伪造默认值。动态字典不得冒充命名记录。
- `[REQ-PGM-013]` 普通官方、项目和扩展函数只能作为独立 `call` 语句执行，不能嵌入参数、条件或另一调用。参数允许使用现有值引用和完整递归的确定性纯值计算；凡是需要普通调用、I/O、等待、目标访问或其他副作用的项目函数，都先以独立语句绑定返回局部符号，后续语句再消费该值。
- `[REQ-PGM-014]` ProgramDocument 支持强类型记录、顺序列表、无业务顺序字典和专用 JSON 值。筛选、转换、排序、分组和统计保存为无副作用集合表达式；需要普通函数或 I/O 的逐项处理使用固定快照循环。
- `[REQ-PGM-015]` 所有经核心批准的纯值操作都可以递归组合兼容值节点；普通函数、I/O、等待、目标访问和扩展私有语法不得进入值表达式。产品不设置人为浅层嵌套上限，完整语义遵循 [`EXPRESSIONS.md`](EXPRESSIONS.md)。
- `[REQ-PGM-016]` 复杂值通过摘要、折叠、聚焦和可撤销提取管理可读性，不以削弱底层组合能力换取界面简洁。Player、诊断和调试按稳定值节点定位；循环引用和资源消耗只由 Harness 安全预算阻止。
- `[REQ-PGM-017]` 重试不是独立语句或函数，而是现有异常区域的可选 `retry_policy`。策略缺省关闭；开启时次数与间隔使用带稳定 `value_id` 的类型化值节点，并在进入区域时求值一次。它只处理契约标记为瞬时的结构化异常，不处理正常无结果、取消或停止。
- `[REQ-PGM-018]` 每次重试从异常区域主体第一条语句开始，不回滚变量、输入、消息、网络或文件副作用。重试耗尽后仅把最后异常交给现有捕获分支或向上传播，最终分支只执行一次；存在直接或传递副作用时，作者确认必须绑定区域主体与锁定函数契约指纹，内容或契约变化后自动失效。
- `[REQ-PGM-019]` `目录.递归删除` 等经函数契约标记的危险调用继续使用普通 `call` 语句，但 ProgramDocument 必须保存独立作者审核指纹。指纹绑定稳定语句、危险参数规范化值树、锁定函数契约和权限版本；任一输入变化后失效并阻止编译/发布。审核不是函数参数，也不能代表 IDE 调试或 Player 已确认实际 `authorization_root_id`。
- `[REQ-PGM-020]` `break`（跳出循环）与 `continue`（跳过本轮）只在当前项目函数的词法循环体内合法，分别终止或继续最近一层循环；嵌套条件、目标作用域与异常区域不改变其目标循环，异常区域的最终分支仍必须执行。普通项目函数调用不能控制调用者的循环。
- `[REQ-PGM-021]` `fail`（结束为失败）保存静态稳定 `error_id`、类型为 `string` 的消息值节点和可选 `json_value` 详情值节点。运行时按投影顺序各求值一次并产生永久结构化异常；现有异常区域可按错误 ID 捕获，未捕获时任务失败并记录函数、语句、错误 ID、消息和脱敏详情。它不是不可捕获的进程终止，也不触发仅限瞬时异常的自动重试。
- `[REQ-PGM-022]` 返回 `bool` 或 `optional<T>` 的独立调用语句提供“根据结果添加条件”结构化快捷操作。该操作在一个版本事务中建立或复用稳定结果绑定，并紧邻调用插入引用该局部符号的 `if`；布尔结果直接作为条件，可选结果使用与空值比较的“有结果”条件。它不得把普通调用嵌入条件、改变调用次数或保存新的组合语句类型。
- `[REQ-PGM-023]` 条件分支按“如果 → 零到多个否则如果 → 可选否则”的顺序求值，并且只执行第一个满足条件的分支。没有语句的否则不作为已存在分支展示；编辑器只提供弱化的“添加否则”插入入口。多个条件需要分别执行时，开发者使用多个独立的如果语句，不把它们伪装成单选分支。
- `[REQ-PGM-024]` 检查器和聚焦值编辑器优先显示当前语句与字段上下文，不重复“函数调用”等由位置已明确表达的信息。自由标量值槽使用一个统一输入器承接直接值、变量、结果和常用纯计算，不再显示“填写 / 变量 / 计算”来源模式；固定候选参数只显示契约下拉且不能改为变量或计算。坐标、区域、资源、控件、文件、目标和集合等继续使用类型化专用 Control。条件根使用同一布尔输入器及专用条件构造能力，不自动进入与当前条件无关的通用操作目录。
- `[REQ-PGM-025]` 局部赋值检查器显示变量名称与中文类型。局部目标类型变化和匹配的新值必须由一个结构命令原子提交；引用或计算结果改变赋值类型时，局部目标类型随结果同步更新。项目变量类型保持项目定义，不允许从赋值语句中改变。
- `[REQ-PGM-026]` “提取为项目函数”只接受同一语句块内的连续选择，并作为跨两份 ProgramDocument 的可撤销事务提交。选择引用的外部局部值自动提升为强类型参数；至多一个仍被后续流程引用的局部结果自动成为返回值。依赖调用者 `return`、外层循环控制、外部局部变量写回或多个逃逸结果的选择必须在写盘前拒绝并说明原因。提取、撤销和重做同步创建或删除配套函数，不能留下不可用调用或孤立半成品。
- `[REQ-PGM-027]` 调用返回绑定使用一个输入框完成三种结果：留空表示不保存，普通名称表示新建当前函数局部变量，键入 `@` 或 `[` 后从当前位置可见且类型兼容的已有局部变量中选择。项目变量不能作为调用返回写入目标，任意文本也不能伪造已有引用；提交仍使用强类型 `set_result_binding` 命令。

## 3. 最小结构

下面的 JSON 只说明模型边界，字段名称和完整 Schema 由契约生成阶段冻结：

```json
{
  "schema_version": 1,
  "document_id": "doc_login",
  "function": {
    "function_id": "func_login",
    "display_name": "自动登录",
    "parameters": [],
    "statements": [
      {
        "statement_id": "stmt_wait",
        "kind": "call",
        "function_id": "builtin.vision.wait_image",
        "arguments": {
          "image": { "value_id": "value_login_image", "kind": "asset_ref", "asset_id": "asset_login" },
          "timeout": { "value_id": "value_login_timeout", "kind": "duration", "milliseconds": 3000 }
        },
        "result_binding": {
          "symbol_id": "symbol_login_result",
          "display_name": "登录结果"
        }
      }
    ]
  }
}
```

内部类型 ID 使用稳定英文标识，例如 `string`、`int64`、`float64`、`bool`、`duration`、`date`、`datetime`、`point`、`rect`、`path`、`json`、`asset_ref`、`control_ref`、`target_ref`、`frame_ref`、`file_ref`、`directory_ref`、`list<T>`、`map<K,V>`、`optional<T>`、`record` 和 `symbol_ref`；`unset` 是缺失值状态而不是用户可声明的数据类型。`TargetInfo`、`FrameReference`、`ImageMatch`、`OCRResult` 与 `OCRLine` 等官方记录类型使用稳定类型/字段 ID，IDE 只投影中文名和可用成员。IDE 根据类型注册表显示中文名称并选择默认 Control；用户不需要接触内部类型 ID。

## 4. 纵向语句投影

中央编辑区不是自由画布，也不是文本编辑器。它把 ProgramDocument 展开为按执行顺序排列的紧凑语句行：

```text
 1  等待 2 秒
 2  等待图像「登录按钮」出现 · 超时 3 秒  → 登录结果
 3  点击「登录结果.中心」· 左键
 4  如果 登录结果.已找到
 5      输出日志「登录成功」
 6  否则
 7      输出日志「未找到登录按钮」
```

- 普通语句默认只占一行。函数契约提供摘要模板，编辑器根据当前参数自动生成可读摘要。
- `step_label` 是可选备注，不参与运行且默认留空；不得要求用户为每条语句维护“节点名称”。
- 中央区负责选择、顺序、层级、折叠、多选、复制、移动、提取函数、断点与运行状态；完整值编辑只进入右侧检查器。
- 复制粘贴是同一项目内的类型化结构快照操作，可跨项目函数复用；剪切移动在粘贴前只是当前 ProgramDocument 的 IDE 临时状态。所有批量写操作必须在目标 Program Service 中原子完成，不能产生可见的中间文档或多个撤销条目。具体契约见 [STRUCTURED_BATCH_EDITING.md](./STRUCTURED_BATCH_EDITING.md)。
- 当前函数查找覆盖语句摘要、可选备注与稳定语句 ID；调试日志和问题项通过稳定 ID 跳回语句。运行快照中的局部结果与项目变量由编译调试映射投影为名称、类型和值，不在普通界面暴露内部槽位。
- 条件、循环、异常和监听通过缩进、区块标题与作用域轨道表达，不使用端口或连线；跳出、跳过和显式失败保持单行结构语句，并由当前位置决定是否合法。
- 返回布尔或可选结果的调用在检查器中提供“根据结果添加条件”。用户操作一次即可得到相邻的“调用 → 如果结果成立/有结果”两行；中央投影可以用连续轨道表达关联，但两条语句仍可分别选择、移动、调试和删除，不能伪装为一次隐藏调用。
- 键盘必须支持插入、删除、复制、撤销、重做、上下移动和层级调整；不得退化为纯鼠标卡片编辑器。

## 5. 函数实现与组合

- 官方原子函数和扩展函数可以由 Python、C++、Kotlin 或平台驱动实现。
- 官方标准函数和项目函数使用 ProgramDocument 组合，从而保持可查看、可调试、可引用和可跨平台编译。
- 性能敏感的官方标准函数可以声明经过等价性测试的融合实现；编译器可以把其结构化定义降低为 Python、原生或平台操作码，但返回值、超时、取消、错误和日志语义必须与结构化定义一致。
- 高级开发者可以把完整 Python 业务实现注册为项目范围扩展函数；它仍通过普通函数契约进入项目，不改变项目函数模型。

## 6. ECIR 边界

ECIR 是确定性构建产物，不是第二个编辑模型。编译器解析所有稳定引用、验证类型与平台、计算资源和扩展依赖闭包，并生成运行时需要的操作码、槽位、控制流、异常区域、可选重试策略、调试映射和权限需求。没有 `retry_policy` 的异常区域保持普通捕获语义；同一策略必须在 IDE、Windows/ADB Player 与 Android 本机产生相同的尝试次数、间隔、过滤、捕获、最终分支和取消行为。

首版可以使用显式版本的 JSON ECIR；若性能和 Android 体积测试证明需要更紧凑编码，可以在保持同一字段语义和兼容规则的前提下增加 Protobuf。不同编码不得产生两套执行含义。

## 7. 明确非目标

- 不提供项目函数的可编辑源码视图。
- 不生成并反向解析 Python 作为结构化编辑协议。
- 不建设通用投影式语言平台或允许普通插件任意注册语法。
- 不把每个函数做成新的语句类型。
- 不把画布位置、卡片尺寸、颜色或连线保存进 ProgramDocument。

## 8. 规格状态

ProgramDocument 的核心语义已经关闭：条件树、单一逻辑返回、命名记录、可选结果、成员收窄、独立普通调用、完整集合和递归纯值表达式均已冻结。官方函数名称与结果类型以 [`FUNCTIONS.md`](FUNCTIONS.md) 为准；Control 像素布局和 Harness 数值预算可以在不改变这些能力边界的前提下由实现与证据收束。
