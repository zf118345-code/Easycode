# 文件能力

状态：`Approved`（文件与目录函数、受控递归删除、Windows/Android 强类型引用、IDE/Player 授权及 HTTP 文件传输边界已冻结；完整跨平台闭环属于首版完成门）

## 1. 目标与非目标

文件能力让脚本读取、生成和修改用户可见的真实文件，用于与 Windows、Android 文件系统、外部软件或同一设备上的其他脚本交换数据。它不是持久变量系统，也不提供通用键值存储。

文件可以被开发者用于自定义的同机数据交换，但平台不把文件轮询宣传为可靠消息服务。跨实例或局域网消息的投递、确认、超时和离线补发由独立 `消息.*`规格处理。

HTTP 文件上传与下载不作为 `文件.*`的模式塞进下表，也不扩张为通用二进制变量。网络函数负责 HTTP 协议、远端响应与网络权限；File Integration Service 只向它提供已授权 `FileReference` 的流式读取、临时写入和原子提交。完整网络契约见 [`NETWORK.md`](NETWORK.md)。

## 2. 首版函数集合

| 函数 | 输入 | 可观察结果 |
| --- | --- | --- |
| `文件.存在` | 文件引用 | 返回文件是否存在 |
| `文件.读取文本` | 文件引用、编码 | 返回文本；文件不存在或无法解码时返回明确错误 |
| `文件.写入文本` | 可写文件引用、内容、编码 | 不存在时创建，存在时原子覆盖 |
| `文件.追加文本` | 可写文件引用、内容、编码 | 不存在时创建，存在时在末尾追加 |
| `文件.替换文本` | 可写文件引用、查找内容、替换内容、范围、编码 | 在最新文件内容中替换并返回替换数量 |
| `文件.读取JSON` | 文件引用 | 解析并返回类型化列表、字典或基础值 |
| `文件.写入JSON` | 可写文件引用、数据 | 验证可序列化后原子覆盖目标文件 |
| `文件.删除` | 可写文件引用 | 删除文件并返回是否实际删除 |
| `文件.复制` | 来源文件引用、目标文件引用、覆盖策略 | 复制成功后返回目标文件引用 |
| `文件.移动` | 来源文件引用、目标文件引用、覆盖策略 | 移动成功后返回目标文件引用 |

目录操作使用独立 `目录.*` 命名空间，不塞进文件万能函数。首版集合固定为：

| 函数 | 输入 | 可观察结果 |
| --- | --- | --- |
| `目录.存在` | 目录引用 | 返回目录是否存在；引用失效与无权访问返回明确错误 |
| `目录.创建` | 已授权父目录引用、相对位置、已存在策略 | 在授权树内创建目录并返回新的目录引用 |
| `目录.列出` | 目录引用、筛选和是否递归 | 返回有界、类型化的文件系统条目列表 |
| `目录.复制` | 来源目录引用、目标父目录引用、目标名称、冲突策略 | 复制完整目录树并返回目标目录引用与处理报告 |
| `目录.移动` | 来源目录引用、目标父目录引用、目标名称、冲突策略 | 移动完整目录树并返回目标目录引用与处理报告 |
| `目录.删除` | 可删除目录引用 | 只删除空目录并返回是否实际删除 |
| `目录.递归删除` | 获得递归删除授权的目录引用 | 删除该目录及全部后代并返回删除报告；作者/执行宿主确认属于平台审核事实，不是函数参数 |

文件系统条目是固定字段记录，包含“名称、类型、大小、文件引用、目录引用”。文件项只填写文件引用，目录项只填写目录引用，不把完整路径降级为普通文本，也不读取文件正文。调用者可以在后续语句中直接选择“条目.名称 / 文件引用 / 目录引用”，不需要猜测 JSON 键。

`目录.列出` 的“筛选”同样是可编辑的固定记录：名称模式支持 `*` 与 `?` 通配符，最大条数为空时使用宿主安全上限；填写时必须为 1 以上的整数。Windows 与 Android 使用同一字段 ID、匹配语义和确定性排序。列表规模、分页/流式枚举与预览上限由函数契约和 Harness 冻结，不能通过一次调用把任意目录树全部装入内存。

目录复制、移动和递归删除是树操作；中途失败不能宣称事务回滚。复制/移动统一返回 `目录操作报告`（是否完整、已处理文件、已处理目录、跳过项、失败项、目标目录），递归删除返回独立的 `目录删除报告`。Python 与 Android 的稳定字段完全一致。调用方可以依据报告决定后续动作，平台不得把部分完成伪报为全部成功。

`目录.复制` 与 `目录.移动` 的首版冲突策略只允许 `报错`（默认）、`跳过` 和 `自动重命名`。目标位置已经存在时不得合并、覆盖、清空或替换其内容；`跳过`返回未执行报告，`自动重命名`由宿主在授权父目录内生成不存在的新名称。任何“替换非空目标”都必须由开发者显式组合受控删除与复制/移动，不能借冲突策略绕过 `目录.递归删除` 的独立权限和确认。

## 3. 替换部分内容

`文件.替换文本`只处理普通文本精确匹配，默认替换全部命中并返回整数数量。检查器中的一次调用配置示例如下：

| 字段 | 类型化值 |
| --- | --- |
| 文件 | 文件引用 `配置.ini` |
| 查找内容 | 文本 `自动领奖=false` |
| 替换内容 | 文本 `自动领奖=true` |
| 范围 | 枚举 `全部` |
| 编码 | 枚举 `UTF-8` |
| 返回绑定 | 整数局部符号 `替换数量` |

找不到目标文本时返回 `0`，不伪报写入成功。只替换第一个命中使用明确的“第一个”范围。正则替换不混入首版普通替换；若后续进入范围，使用独立函数或明确契约。

修改 JSON 字段时，脚本先用 `文件.读取JSON`取得结构化值，修改字段后再调用`文件.写入JSON`，不为每种层级路径增加一批专用函数。

## 4. 路径与平台

- 文件函数不接受用普通文本伪装的路径。文件参数使用判别式 `FileReference`，目录参数使用 `DirectoryReference`；两者至少携带平台、来源种类、显示名、读取/写入访问模式和宿主载荷。应用私有位置与外部用户授权位置属于不同来源种类，但使用同一高层函数契约。
- HTTP 上传只能打开声明为可读的 `FileReference`，下载只能提交到声明为可写且支持原子提交的 `FileReference`。网络权限不能扩大引用范围，文件权限也不能隐式授权网络目标。
- 应用数据文件引用属于当前发布包或 IDE 测试环境，可以在已批准目录内读写；IDE 测试数据与正式 Player 数据隔离。相对位置必须通过明确的应用数据基准生成，不能依赖进程当前工作目录。
- 外部文件/目录来自 IDE 或 Player 的系统选择器。外部读取与写入必须进入发布权限报告，不能隐藏在普通文本参数中绕过检查；开发者若为 Windows Player 字段显式开放手工路径输入，仍必须在提交时转换并验证为 `FileReference/DirectoryReference`，Android 不提供盘符式手工路径输入。
- 项目开发数据目录与 Player 运行数据目录是不同边界；发布后的程序不得假设用户电脑存在 IDE 项目路径。
- 应用私有/Player 数据目录的正常文件函数是本地能力，不依赖公网、EasyCode 云或开发后端；平台返回的第三方文档提供者若自身需要网络，文件函数必须保留其真实失败原因，不能把它伪报为本地文件成功。
- Windows 外部引用使用规范化绝对路径及访问模式；Android 本机外部引用使用 Storage Access Framework 返回的文档 URI 与持久化授权，不把 Windows 盘符或 `file://` 语义带入 APK。
- 文件选择固定分为三种动作：`选择要读取的文件`（稳定动作 ID `choose-file-read`）返回可读 `FileReference`，`选择保存位置`（`choose-file-save`）返回可写 `FileReference`，`选择文件夹`（`choose-directory`）返回具有作者指定读取/写入模式的 `DirectoryReference`。三种动作不能合并成一个含糊“选择路径”，作者可以声明文件类型/MIME 与扩展名约束。
- 文件/目录选择是 Player 宿主能力，不依赖图像或输入目标；因此无操作目标方案也可使用。Windows 及 Windows/ADB Player 返回 Windows 主机引用，Android 本机 Player 返回 SAF 引用。必填引用没有安全默认值，在终端选择前保持未设置。
- Android 系统选择器只授予用户选定文档或目录树的范围。即使已取得持久 URI 授权，文件移动、删除、提供者失效或用户撤销仍可使引用失效；Player 保留原引用并标记不可用，提供重选，不静默清空。
- 应用私有目录、系统授权文件引用、授权撤销和内容引用失效的完整闭环属于首个正式版本放行条件，不能推迟为占位接口。图片字段从相册选择后的内容按资源规格复制到 Player 私有覆盖目录，不长期保存为普通外部文件引用。

## 5. 写入正确性与并发

- 覆盖、JSON 写入和文本替换先在同目录生成完整临时文件，刷新成功后再原子替换目标，进程中断不得留下半个文件。
- HTTP 下载先写入应用控制的临时文件；网络响应完整、大小检查与刷新成功后，才通过与普通覆盖写入相同的原子提交边界替换目标。失败、取消或进程退出时原目标保持不变，临时文件不得作为成功结果暴露。
- File Integration Service 在网络请求前验证目标引用、写入授权、可用空间的可检查部分和原子提交能力。Windows 目标使用同卷临时文件与原子替换；Android 应用私有目标使用私有临时文件，外部 SAF Provider 只有在宿主能保证暂存后原子提交时才允许作为下载目标。无法保证时返回“不支持该保存位置”，不能退化为直接截断旧文件。
- HTTP 上传通过只读流分块读取引用，HTTP 下载通过只写临时流分块落盘；两种交接都必须支持取消和有界缓冲，文件大小不能决定 Runtime 一次性内存占用。
- 同一设备上的 EasyCode 进程对规范化路径使用共享写锁；`替换文本`取得锁后读取最新内容，再计算并提交替换。
- 追加操作持有写锁直到内容刷新完成，避免多个 EasyCode 实例把字节交叉写入。
- 显式覆盖写入按调用顺序生效；两个调用都要求覆盖同一文件时，最后完成的完整写入成为最终内容，不宣称自动合并。
- 外部程序不遵守 EasyCode 写锁时，文件服务只能依赖操作系统锁与错误。权限不足、文件被占用、磁盘已满、编码失败和外部变化必须返回真实错误。
- 上述锁由文件服务自动管理，不向普通脚本暴露 `租约.*`。

## 6. 安全与交互

- 破坏性文件操作在 IDE 检查器中显示目标路径和覆盖/删除语义；路径来自表达式时显示运行期权限要求。
- Player 文件/目录字段的系统选择动作由作者逐字段、逐动作、逐平台显式开放，默认全部关闭。开放动作只允许终端用户在运行方案编辑状态主动选择该字段的值，不允许脚本静默打开选择器、扫描目录或扩大到其他字段。
- Player 实际动作必须同时通过作者发布、字段类型、发布包能力闭包、当前宿主/平台能力和当前权限状态。结构上不支持的动作不显示；授权撤销、引用失效等可恢复状态保留字段旧值并显示重选入口。
- 权限按需请求：用户触发动作后才进入系统选择器或授权流程。取消、拒绝、永久拒绝、系统返回、应用被终止或授权结果不完整时保持原值和 Control 草稿；永久拒绝不得循环弹框，恢复后返回原字段。
- Player 只获得发布清单声明的文件能力。用户选择的文件引用只能用于获批字段与函数调用；读取引用不能用于写入、单文件引用不能扩大为父目录访问，目录引用不能越出用户选择的树。
- `文件.删除`只删除文件；删除目录、递归删除和通配符批量删除不复用该函数。
- `目录.删除`只删除空目录；`目录.递归删除`是独立危险函数，不能隐藏为普通删除的布尔开关，也不接受通配符、绝对路径字符串、父目录推导或未解析变量作为授权依据。
- `DirectoryReference` 分别声明列举、创建、写入、移动、删除空目录和递归删除能力。普通“选择文件夹”不会自动授予递归删除；作者在 IDE 中必须查看受影响调用并确认危险权限，发布报告必须单独列出。
- `目录.创建`、`目录.列出`或其他目录函数返回的新引用只能继承来源引用与当前函数共同允许的能力，绝不能通过创建子目录或重新枚举升级为递归删除。危险确认的单位是用户明确选择的授权根 `authorization_root_id`，不是运行时某个不可预测的子路径；由该根派生的引用只能缩小到树内。确认页必须明确说明“允许此调用删除该授权树内最终解析到的目录”，运行时仍记录实际子目标并逐项验证 containment。应用私有目录也必须由作者声明固定授权根并由执行用户首次确认危险能力，不能因为位于沙箱就静默取得递归删除。
- 每个实际执行宿主都把递归删除确认绑定到稳定语句/参数、`authorization_root_id`、执行配置 revision 与函数契约指纹。IDE 调试必须在解析出真实授权根后进行运行前危险确认；Player 也由终端用户在当次运行前确认。该确认仅对当次执行有效，不写入运行方案、计划或 ProgramDocument；作者静态审核不能替代任何实际执行确认。
- 平台拒绝文件系统根、盘符根、用户主目录、项目工作区根、Player 数据根及其他宿主保护根作为递归删除目标。Windows 规范化路径、符号链接与重解析点，Android 文档树与 Provider 返回的子项都必须逐项证明仍在获授权树内；链接本身可以按契约删除，但不得跟随到树外目标。
- 递归删除开始后如遇权限撤销、外部占用、Provider 失败、目标变化或进程中断，立即停止后续遍历并返回部分完成报告。平台不承诺恢复已删除内容；日志记录稳定操作 ID、目标摘要和计数，但按脱敏规则不泄漏完整私有路径。
- Android Provider 不能证明后代边界或不支持所需删除语义时，在执行前返回“不支持该目录位置”，不能退化为逐个猜测删除。Windows 与 Android 使用同一上层结果和失败分类。
- 相对路径必须相对于明确的应用数据或项目数据基准解析，不能依赖进程当前工作目录。
- 文件/目录引用、授权与系统选择器状态属于终端 Player 数据，不写入 ProgramDocument、签名 ECIR、项目 `player/form.json` 或发布包。Player Schema 只保存作者允许的动作、访问模式和文件类型约束。

## 7. 验收基线

- `REQ-FILE-001`：覆盖写入不存在文件时创建，存在文件时以完整新内容原子替换。
- `REQ-FILE-002`：追加写入保留原内容，并在并发 EasyCode 写入时保持每次提交完整。
- `REQ-FILE-003`：文本替换支持第一个/全部精确匹配并返回替换数量；零命中不修改文件。
- `REQ-FILE-004`：JSON 读取失败区分文件不存在、编码失败与语法错误；写入拒绝不可序列化值。
- `REQ-FILE-005`：同一设备上的 EasyCode 写入按规范化路径互斥；所有失败返回真实原因。
- `REQ-FILE-006`：IDE 测试数据、Player 私有数据和外部用户文件具有不同路径与权限边界。
- `REQ-FILE-007`：文件函数可在 Windows 与 Android 本机使用同一类型化函数契约，由平台宿主替换路径和授权实现。
- `REQ-FILE-008`：文件和目录使用判别式强类型引用；读取文件、保存文件和选择目录具有不同动作与访问模式，不能由普通文本或一个万能路径动作替代。
- `REQ-FILE-009`：Player 文件动作默认关闭并由作者逐字段、逐平台发布；运行端只执行通过作者、类型、闭包、宿主和权限五方交集的动作。
- `REQ-FILE-010`：取消、拒绝、权限撤销、引用移动/删除和提供者失效时保留旧值与草稿；必填引用不可用时阻止运行并提供重选，不伪报成功。
- `REQ-FILE-011`：Android 外部引用使用系统选择器和持久文档 URI；Windows 外部引用使用规范化路径。两端都必须执行声明的读写模式和范围，不能扩大授权。
- `REQ-FILE-012`：HTTP 上传只能流式读取可读 `FileReference`，下载只能流式写入临时文件并原子提交到可写 `FileReference`；文件内容不得成为 ProgramDocument、项目变量或普通日志值。
- `REQ-FILE-013`：下载目标在请求前不具备有效授权或原子提交能力时必须拒绝；请求、取消、网络、磁盘、权限或提交失败均不得改变原目标或留下可见半文件。
- `REQ-FILE-014`：Windows 与 Android 本机的 File Integration Service 必须向网络函数提供相同的打开、取消、刷新、提交和错误契约；Android Provider 差异不能改变上层函数语义。
- `REQ-FILE-015`：Player 文件/目录字段使用类型化摘要和系统选择器，不展示可手改的 JSON/路径框。系统选择器确认后自动二次验证字段、方案 revision 与发布权限并原子回填；取消和失败不修改旧值。
- `REQ-DIR-001`：首版提供目录存在、创建、列出、复制、移动、删除空目录和递归删除七项独立能力，不复用文件删除或万能路径函数。
- `REQ-DIR-002`：全部目录函数只接受具有相应能力的 `DirectoryReference`；相对位置必须留在已授权树内，普通文本、绝对路径、通配符和父目录推导不能扩大权限。
- `REQ-DIR-003`：目录列出返回有界的类型化条目；复制、移动与递归删除返回完整/部分完成报告，任何中途失败都不能伪报事务回滚或全部成功。
- `REQ-DIR-004`：递归删除具有独立函数、权限和作者审核；IDE 调试与 Player 都必须在当次执行前对真实授权根进行绑定语句、执行配置 revision 和契约指纹的终端确认；确认不持久化，派生引用只能缩小到确认树内。
- `REQ-DIR-005`：根目录、用户主目录和平台保护根不能成为递归删除目标；符号链接、重解析点与 Android Provider 子项不能越出授权树。
- `REQ-DIR-006`：权限撤销、目标变化、外部占用、Provider 失败或进程中断时停止后续删除，保留可诊断的部分完成报告，不自动重试具有破坏性的树操作。
- `REQ-DIR-007`：Windows 与 Android 本机使用同一目录函数契约；宿主无法验证范围或删除语义时必须在执行前拒绝，不提供假兼容。
- `REQ-DIR-008`：目录复制/移动的冲突策略只允许报错、跳过或自动重命名；首版不合并、不覆盖且不能借冲突处理清空已存在目标。

Harness 至少覆盖：创建、读取、覆盖、追加、第一个/全部/零命中替换、JSON 往返、复制、移动、删除、并发写入、进程中断、文件占用、权限不足、磁盘不足、非法编码、路径穿越、IDE/Player 隔离、发布权限拒绝，以及 Windows/Android 的文件/目录选择取消、拒绝、授权撤销、引用移动/删除、远程文档提供者断网和重选恢复。目录专项还要覆盖七项函数、三种复制/移动冲突策略、禁止合并覆盖、空/非空目录、深层与宽目录树、循环/越界链接、Windows 重解析点、根目录保护、Android Provider 不支持、作者审核、IDE 调试与 Player 实际授权根确认及其失效、派生引用缩权、部分完成报告、进程中断和确认后计划运行。网络文件交接还要覆盖大文件有界缓冲、上传读取中断、下载临时文件、旧目标哈希不变、原子提交失败，以及不支持原子提交的 Android Provider 在联网前拒绝。

## 8. 由实现与 Harness 冻结的默认值

- 首版支持的文本编码集合与读取时自动检测规则。默认使用UTF-8；增加其他编码必须有真实文件样例和往返测试，不要求用户逐个审批编码名称。
