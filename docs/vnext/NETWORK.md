# 网络、HTTP 与设备配对

状态：`Approved`（首版官方文本/JSON HTTP、独立文件上传/下载原子能力、本机/LAN/公网分级、无云配对、远程启动授权和本地诊断边界已冻结；实现证据和数值预算仍由 Harness 管理）

最近修订：2026-09-03

## 1. 产品结果与边界

EasyCode 首版提供三项互相独立的官方 HTTP 原子能力：`网络.请求`、`网络.上传文件`和 `网络.下载文件`。它们使项目可以调用普通 HTTP API 或传输真实文件，而不要求开发者为每个接口编写 Python 扩展，也不把所有协议形态塞进一个万能请求函数。`HTTP.*` 只允许作为搜索别名，不进入 ProgramDocument、Player 绑定或函数契约身份。Compiler 根据函数的实际 URL 来源、文件访问模式和网络策略形成发布权限闭包与“无网络 / 本机或局域网 / 公网”能力报告；Runtime 只在执行对应调用时建立连接，网络或文件失败只返回当前语句的结构化错误。

首版不提供浏览器 DOM、JavaScript 注入、页面元素选择、Cookie 浏览器会话、验证码绕过或 WebView 自动化。需要浏览器级行为时，后续以独立宿主/功能扩展和权限模型讨论，不能把 HTTP 响应文本伪装成浏览器页面。

同机/LAN 消息和运行计划共享本文件定义的设备身份、配对与加密传输，但业务协议相互独立：普通消息不能获得远程启动权限，HTTP 函数也不能访问设备控制通道。

## 2. 官方 HTTP 原子契约

`网络.请求` 是独立语句的类型化 HTTP 请求原子能力。它至少接受：

- 方法：`GET / HEAD / POST / PUT / PATCH / DELETE`；
- URL：`http` 或 `https` 类型化 URL；
- 查询参数：有序键值列表，允许同名键，不要求用户手工拼接和转义；
- 请求头：不区分大小写的文本键值列表；
- 请求正文：`无 / 文本 / JSON` 判别式值；`GET / HEAD` 只允许“无”，携带正文在联网前稳定失败为 `network.body_not_allowed`；
- 重定向策略：`不跟随 / 仅同源 / 允许跨源`，默认仅同源；
- 总超时和最大响应正文大小。

开发者在项目网络配置中批准动态 URL 可以访问的主机/端口范围。Compiler 将对应策略 ID 写入调用的权限闭包，Runtime 使用它验证请求；普通 Player 用户不会把权限 ID 当成业务参数填写，也不能通过 Player 表单扩大作者发布的网络范围。

函数返回一个不可变 `HTTPResponse` 命名记录：状态码、响应头、最终 URL、Content-Type 和文本正文。JSON 正文仍是文本，可以通过核心纯值操作 `core.json_parse_text.v1` 得到 `optional<json>`；平台不得根据 Content-Type 静默改变返回类型。`网络.请求`不接受文件、二进制缓冲区或流作为正文，也不把二进制响应静默按乱码文本返回；文件传输只能进入下文两项独立原子能力。

HTTP `4xx/5xx` 是已经取得的正常响应，函数返回真实状态码和正文；DNS、连接、TLS、代理、重定向、超时、取消、响应过大、编码和权限失败是结构化异常。Runtime 不因为响应状态码自动重试，也不在函数内部重试可能产生副作用的请求。状态码业务分支使用条件/循环；DNS、连接等被契约标记为瞬时的异常只有在外层异常区域显式开启重试时才会再次请求，并可以显式提供服务端支持的幂等请求头。

每次调用默认使用独立请求上下文，不维护跨调用 Cookie Jar、浏览器缓存或登录会话。调用取消后 Runtime 停止继续读取响应并释放连接；已经送达远端服务器的请求不能伪报为“未执行”。

### 2.1 文件上传原子能力

`网络.上传文件`只处理明确的 multipart 上传。它复用 HTTP 请求的 URL、查询、请求头、重定向、TLS、超时、网络授权与文本响应契约，并额外接受一个有序 multipart 字段列表。每个字段必须明确选择以下一种类型：

- 文本字段：字段名、文本值与可选 Content-Type；
- 文件字段：字段名、可读 `FileReference`、可选对外文件名与可选 Content-Type。

Runtime 通过 File Integration Service 打开已授权文件流并边读边发送；文件字节不得进入 ProgramDocument、项目变量、普通日志或一次性内存缓冲区，也不能用普通路径文本绕过 `FileReference` 的读取权限。字段顺序和同名字段必须保留。文件在发送前失效、授权撤销、读取中断或大小超过 Harness 上限时返回可区分异常；远端已经收到的部分内容不能伪报为“完全未发送”。

上传返回与 `网络.请求`相同的 `HTTPResponse` 文本响应记录。HTTP `4xx/5xx` 仍是正常响应；文件读取、网络和协议问题是结构化异常。Runtime 不在函数内部重试上传；作者用外层异常区域显式开启重试时，副作用审核必须提示远端可能已经收到上一请求，并优先使用服务端提供的业务幂等键。

首版不把 multipart、原始二进制、分片、断点续传和任意流回调混合成一个通用正文编辑器。需要原始二进制上传或服务专用分片协议时，后续增加独立契约或扩展函数。

### 2.2 文件下载原子能力

`网络.下载文件`复用 HTTP 请求的 URL、查询、请求头、重定向、TLS、超时和网络授权契约，并接受一个可写 `FileReference` 和最大下载大小。Runtime 在发起请求前验证目标引用仍有效、写入权限存在且宿主能够提供原子提交；验证失败时不建立网络连接。

Runtime 把成功响应边接收边写入应用控制的临时文件，不把完整正文装入内存。只有响应完整、大小限制与本地刷新全部通过后，File Integration Service 才把临时文件原子提交到目标引用。取消、断网、进程退出、响应截断、大小超限、磁盘不足、权限撤销或提交失败都必须保留原目标文件，并清理或隔离临时文件供诊断；不能直接截断目标后再开始下载。

只有 HTTP `2xx` 响应进入文件提交；未跟随的 `3xx` 与 `4xx/5xx` 返回真实状态、响应头和受限文本错误正文，并明确标记“未提交文件”，不覆盖原目标。下载返回不可变 `HTTPDownloadResult` 命名记录，至少包含状态码、响应头、最终 URL、Content-Type、是否提交、提交后的文件引用和已写入字节数；未提交时文件成员为明确无结果，而不是伪造路径。

Windows Runtime（包括操作 ADB 目标的 Windows Player）与 Android 本机 Runtime 使用同一函数契约。平台只替换 `FileReference` 的打开与原子提交实现；Android 文档提供者无法保证原子替换时，函数必须在请求前返回“不支持该保存位置”，不得静默退化为可能留下半文件的直接写入。

## 3. URL、权限与重定向

- URL 只允许 `http/https`，拒绝 `file:`、自定义协议、内嵌凭据和控制字符。
- HTTPS 使用系统或应用受信任证书并验证主机名。发布 Player 不提供“忽略证书错误”开关；开发调试需要自签名证书时，用户把相应 CA 明确加入受控信任配置。
- 静态 URL 由 Compiler 提取 scheme、host 和 port。动态 URL 必须引用开发者在发布配置中批准的主机/端口规则；未声明或无法证明边界时发布检查阻止，而不是自动授予任意公网。文件上传还必须声明读取引用，文件下载还必须声明写入引用；网络许可不能替代文件许可。
- Runtime 在 DNS 解析后重新分类 loopback、LAN 和公网地址，并在每次重定向后重新执行 URL、目标范围和权限检查。域名解析到未授权地址、DNS rebinding 或跨范围重定向时拒绝继续。
- 跨源重定向不得转发 `Authorization`、Cookie、代理认证或开发者标记的敏感请求头，除非目标源也在独立授权范围且函数契约明确允许。
- 明文公共 HTTP 在发布报告中显示安全警告；局域网设备 API 可以显式允许 HTTP。网络报告必须列出静态来源；动态规则显示开发者批准的范围，不能只写“需要联网”。
- Android APK 允许传输栈建立明文 HTTP 的技术通道，但这不构成全局业务授权：每个 HTTP 请求仍必须通过签名 ECIR 中精确的 scheme、host、port 与解析后地址范围检查。缺少规则、越权地址或重定向时必须在连接前阻止；Manifest/Network Security Config 不得以全局禁用明文的方式破坏作者明确批准的本机/LAN HTTP。

## 4. 请求值、敏感数据与诊断

请求 URL、查询、头和正文都来自普通强类型值或 Player 已发布字段，不产生“网络变量”。检查器按字段类型编辑并校验，不要求用户手写 JSON 字符串、百分号转义或逗号列表。上传与下载的文件值使用文件 Control 选择 `FileReference`；检查器不展示二进制文本框，也不允许把文件内容绑定为项目变量。

函数契约与 Player Schema 可以把 API Key、Bearer Token、Cookie 或正文成员标记为敏感。IDE、Player、结构化日志、问题中心和诊断导出默认只记录字段存在、长度/哈希摘要和脱敏主机，不记录敏感值。普通日志级别不记录请求/响应正文；用户在本地显式开启单次详细诊断时，界面先显示将包含的非敏感字段，并在导出前再次脱敏。

每次请求诊断至少包含 `run_id`、`statement_id`、请求 ID、方法、脱敏 URL、网络级别、开始/结束时间、DNS/连接/TLS/首字节/总耗时、状态码、收发字节数、重定向次数和结构化错误。文件传输只额外记录脱敏显示名、引用来源种类、声明大小、实际字节数、临时文件/提交阶段和提交结果，不记录文件内容、外部绝对路径或 Android URI。诊断默认留在设备本地，EasyCode 不自动上传请求、响应、文件、在线状态或失败统计。

## 5. 本机实例身份与自动信任

每个运行端点拥有稳定随机 `host_id` 和 `instance_id`。显示名用于选择和日志，重命名不改变身份。同一操作系统用户、同一设备、同一签名产品信任域中的 Player 实例通过当前用户本机目录自动信任普通消息；信任域至少绑定项目命名空间与已验证发布签名身份，只有项目名相同或显示名相同不足以建立信任。它们不显示配对码，也不经过 LAN 广播。

本机自动信任只授予同一签名产品域内的普通消息。它不自动允许跨项目或不同签名域消息、远程启动、读取其他方案值、修改计划或访问其他进程文件。Windows Hub 由当前本机用户显式创建跨项目计划时，使用宿主安装注册表和本机启动权限，不借用消息自动信任。

## 6. 跨设备短期码与二维码配对

跨设备配对完全在本机/LAN 内完成，不依赖 EasyCode 云、账号或公网发现：

1. 接收设备生成一次性短期配对会话，显示二维码和可手工输入的短期码。会话绑定接收设备公钥、随机 nonce、允许的 LAN 地址、创建时间和过期时间。
2. 发起设备扫描二维码或输入短期码，通过 LAN 连接接收设备并校验会话内容。
3. 两端展示设备名、平台和相同的短指纹；用户在接收端确认后，双方保存长期设备公钥和新 `host_id` 关系。
4. 用户分别授予普通消息、查看运行状态和远程启动权限。远程启动还要限定允许的产品/实例；未选择的权限保持关闭。
5. 后续连接使用双向认证、会话密钥、单调计数/nonce 和请求有效期。短期码在首次成功、用户取消或到期后立即失效，不能转为长期口令。

设备私钥进入操作系统或应用安全存储，不进入项目、ProgramDocument、发布包、二维码、日志或诊断。发现广播只帮助找到待配对设备，不建立信任；无法发现时可以通过短期码携带的 LAN 地址或手工地址连接。用户撤销配对后，本机删除长期授权和会话，远端未来请求立即失败；已经运行的普通任务不被远程强杀。

## 7. 已知、未知与离线

- **未知实例**：稳定 ID 不存在、从未配对、配对已撤销、项目命名空间不符或权限不包含当前动作。消息发送和远程派发立即失败，不创建等待队列。
- **已知在线实例**：身份、权限和会话验证通过。服务把请求交给对应消息或调度协议，并返回协议自己的接纳状态。
- **已知离线实例**：可信注册仍有效，但连接暂不可达。普通消息按消息有效期保留；远程调度按条目 `start_deadline` 保留。恢复连接后使用原消息 ID 或 `dispatch_id` 投递，超过 TTL 后标记过期/错过。

“协调器不可达”“LAN 不可达”“设备在线但实例未运行”“实例在线但目标离线”“权限被撤销”必须使用不同状态。LAN 功能不得在本地失败后自动改用 EasyCode 云或公网中继。

## 8. 远程启动特权协议

远程启动请求只能引用目标设备已经安装且签名有效的 `product_id`、本机 `profile_id`、`instance_id`、`occurrence_id`、`dispatch_id`、请求有效期和计划摘要。协议拒绝 ECIR、Python、扩展、任意文件路径、shell 命令和运行方案值；目标设备使用本机保存的方案并完成自己的签名、Schema、目标、权限和更新预检。

目标 Agent 原子保存 `dispatch_id` 与 `run_id` 关系。重试和重放返回原结果或拒绝过期请求，不能启动第二任务。普通消息权限、消息内容、消息已读和 HTTP 请求都不能调用该协议。完整调度语义见 [`SCHEDULES.md`](SCHEDULES.md)。

## 9. 状态与诊断边界

Player 可以在本机“配对设备”页显示已保存设备、授权范围、最近一次 LAN 连接和真实错误；这只是本地视图，不是云端在线设备面板。设备不可达时显示“最近一次连接”和“当前未知”，不能根据历史心跳伪报在线。

配对与传输诊断记录主机/实例稳定 ID、公开指纹摘要、权限变化、连接阶段、消息/dispatch 关联 ID 和错误码。短期码、二维码原始内容、私钥、会话密钥、认证头、消息正文、HTTP 正文和运行方案值不得进入普通日志或自动导出。

用户可以从相关 IDE/Player 主动导出脱敏诊断包。首版没有自动遥测、自动崩溃上传、云端运行历史、云端在线设备列表或远程设备管理后台。

## 10. 稳定需求

- `[REQ-NET-001]` 首版必须提供官方强类型 `网络.请求` 原子函数；HTTP 调用必须作为独立语句执行并返回命名响应记录。
- `[REQ-NET-002]` HTTP 只允许 `http/https`，请求方法、查询、请求头、正文、重定向、超时和响应上限必须使用类型化参数，不能要求用户拼接自由请求脚本。
- `[REQ-NET-003]` `4xx/5xx` 必须返回真实 HTTP 响应；DNS、连接、TLS、重定向、超时、取消、大小、编码和权限问题必须返回可区分异常。
- `[REQ-NET-004]` Runtime 不得自动重试可能产生副作用的 HTTP 请求，也不得把取消后已经可能送达的请求伪报为未执行。
- `[REQ-NET-005]` Compiler 必须从静态 URL 或开发者批准的动态主机规则派生网络权限和发布报告；未授权动态目标必须阻止发布或执行。
- `[REQ-NET-006]` Runtime 必须在 DNS 解析和每次重定向后重新检查地址分类与授权范围，拒绝协议绕过、DNS rebinding 和未授权跨范围跳转。
- `[REQ-NET-007]` 发布 Player 必须验证 HTTPS 证书和主机名，不能提供忽略证书错误的普通开关。
- `[REQ-NET-008]` HTTP 请求上下文默认无持久 Cookie Jar；浏览器 DOM、脚本注入和 WebView 自动化不得伪装成 HTTP 能力。
- `[REQ-NET-009]` HTTP 日志与诊断必须默认脱敏敏感头、查询、正文和响应内容，并保留请求 ID、耗时、状态与结构化错误。
- `[REQ-NET-010]` 同机同用户同一签名产品信任域的 Player 实例只能自动信任普通消息；该信任不得扩大到跨项目、不同签名域、远程启动或文件访问。
- `[REQ-NET-011]` 跨设备必须使用一次性短期码或二维码在 LAN 内配对，双方确认公开指纹后保存设备公钥；短期码成功、取消或到期后失效。
- `[REQ-NET-012]` 长期连接必须双向认证并防重放；设备私钥和会话密钥不得进入项目、发布物、日志、二维码或诊断。
- `[REQ-NET-013]` 普通消息、查看状态和远程启动必须分别授权；远程启动权限还必须限制产品/实例，撤销后未来请求立即失败。
- `[REQ-NET-014]` 未知或未授权实例必须立即失败；已知离线实例只能在业务 TTL 内保留原 ID，恢复后幂等投递，过期后不得继续。
- `[REQ-NET-015]` 协调器、LAN、设备、实例、目标和权限状态必须分离，任何 LAN 失败不得自动回退 EasyCode 云或公网中继。
- `[REQ-NET-016]` 远程启动只能引用目标已安装产品和本机方案，必须拒绝下发 ECIR、代码、任意参数、文件或系统命令。
- `[REQ-NET-017]` LAN 在线状态与运行诊断只能在本机/配对连接中查看；首版不得自动上传遥测或建设云端在线设备面板。
- `[REQ-NET-018]` 网络、配对、消息和调度必须共享稳定 host/instance 身份与关联 ID，但各协议的权限、状态和成功语义不能互相替代。
- `[REQ-NET-UPLOAD-001]` 首版必须以独立 `网络.上传文件` 原子函数提供 multipart 文件上传；文本字段与文件字段必须使用判别式有序结构，文件字段必须引用可读 `FileReference`，不能混入普通 `网络.请求` 正文。
- `[REQ-NET-UPLOAD-002]` Runtime 必须从文件引用流式读取并发送，不得把完整文件写入 ProgramDocument、项目变量、普通日志或一次性内存缓冲区；读取或传输失败必须报告已知阶段且不得自动重试。
- `[REQ-NET-DOWNLOAD-001]` 首版必须以独立 `网络.下载文件` 原子函数提供文件下载；Runtime 必须先写应用控制的临时文件，完整成功并刷新后才原子提交到可写 `FileReference`。
- `[REQ-NET-DOWNLOAD-002]` 取消、截断、超限、磁盘、权限、进程或提交失败，以及 HTTP 非 `2xx` 响应，都不得覆盖原目标或留下可被误认为成功的半文件。
- `[REQ-NET-FILE-PARITY-001]` Windows 与 Android 本机必须使用相同的上传/下载参数、返回、取消、超时和错误契约；平台差异只能由 File Integration Service 的强类型引用、授权和提交实现承接。
- `[REQ-NET-FILE-BOUNDARY-001]` 发布器必须同时闭包文件访问与网络权限，普通请求、multipart 上传和文件下载保持三个独立函数；首版不得以万能正文类型、路径字符串或任意流对象绕过边界。

## 11. Harness 验收

- `[AC-NET-HTTP-001]` 真实服务覆盖六种方法、重复查询键、文本/JSON 请求体、响应头、重定向和文本响应；类型化值往返不依赖手工字符串拼接。
- `[AC-NET-HTTP-ERROR-001]` `4xx/5xx`、DNS、拒绝连接、TLS/主机名、代理、超时、取消、响应过大、非法编码和未授权目标逐项返回不同结果。
- `[AC-NET-HTTP-SEC-001]` 非 HTTP 协议、内嵌凭据、DNS rebinding、跨范围重定向、敏感头跨源转发和关闭证书校验均被阻止。
- `[AC-NET-HTTP-RETRY-001]` 服务端收到 POST 后客户端丢失响应时，Runtime 不自动生成第二请求；只有作者在外层异常区域显式开启重试并确认副作用风险后才产生下一次请求，项目可以携带同一业务幂等键。
- `[AC-NET-HTTP-DIAG-001]` 结构化诊断包含阶段耗时、状态和字节数，但项目扫描、日志和导出均不出现认证头、敏感查询或正文。
- `[AC-NET-UPLOAD-001]` 真实服务接收有序文本/文件 multipart 字段、同名字段和非 ASCII 文件名；Windows 与 Android 从可读 `FileReference` 流式上传相同文件哈希，峰值内存不随文件大小线性增长。
- `[AC-NET-UPLOAD-FAIL-001]` 上传覆盖引用失效、授权撤销、读取中断、网络断开、取消和服务端已收部分内容但响应丢失；每种情况返回真实阶段且 Runtime 不自动发出第二请求。
- `[AC-NET-DOWNLOAD-001]` Windows 与 Android 把真实 `2xx` 大文件流式写入临时文件并原子提交，返回的字节数与文件哈希匹配；普通 HTTP 请求函数从不接收或返回该二进制文件值。
- `[AC-NET-DOWNLOAD-ATOMIC-001]` 预置旧目标后注入 `4xx/5xx`、截断、取消、超限、磁盘满、权限撤销、进程退出和提交失败，旧目标哈希保持不变且无可见半文件；不支持原子提交的 Android Provider 在联网前被拒绝。
- `[AC-NET-FILE-CLOSURE-001]` 发布报告分别定位网络范围、上传读取和下载写入权限；删除任一函数实现、文件宿主能力或权限闭包都会在发布前失败，Windows/Android 不进行运行期补下载。
- `[AC-NET-LOCAL-TRUST-001]` 同用户同机同一签名产品信任域的 Player 实例无需配对即可收发普通消息；跨用户、跨项目、不同签名域、伪造本机身份和远程启动请求均不获得自动信任。
- `[AC-NET-PAIR-001]` 二维码与手工短期码均可在无公网 LAN 完成配对；错误、过期、重复使用、中间人指纹不一致和接收端拒绝均失败且不留下半配对。
- `[AC-NET-REVOKE-001]` 分别撤销消息、状态或远程启动权限只影响对应动作；撤销整个设备后旧会话、重放和离线队列都不能恢复权限。
- `[AC-NET-OFFLINE-001]` 未知实例立即失败；已知离线消息/dispatch 使用原 ID 在 TTL 内恢复，过期后保持终态且不自动转公网。
- `[AC-NET-DISPATCH-001]` 远程启动请求尝试携带代码、任意方案值、文件路径或 shell 命令时被拒绝；合法请求由目标本机预检并幂等创建一个 run。
- `[AC-NET-NOCLOUD-001]` 阻断公网后同机、Windows↔Windows、Windows↔Android 和 Android↔Android 配对通信按授权工作；抓包没有云端发现、设备心跳、遥测或公网中继。
- `[AC-NET-DIAG-001]` 本机配对页离线时显示状态未知和最近连接，不伪报在线；脱敏导出不包含短期码、二维码载荷、私钥、会话密钥、正文或方案值。

## 12. 首版不包含

- 浏览器 DOM、WebView 自动化、网页 JavaScript、浏览器 Cookie 会话与验证码绕过；
- 后续浏览器 DOM 能力按 [`AUTHORING_AUTOMATION.md`](AUTHORING_AUTOMATION.md) 由独立第一方签名扩展提供；它拥有自己的宿主、选择器、权限和发布闭包，不改变本文件 HTTP 原子契约。
- WebSocket、SSE、任意流回调、原始二进制请求/响应值、可恢复分片/断点续传协议、FTP、邮件和任意 Socket；
- 云端设备发现、云端在线面板、公网中继、远程桌面和无人确认的跨机管理；
- 通过配对下发项目、扩展、代码、文件、凭据或任意系统命令；
- 自动上传请求/响应、消息正文、崩溃、运行结果或设备在线状态。

请求/响应大小、连接池、重定向次数、超时范围、配对码长度/有效期、设备数量、TTL、密钥轮换与诊断保留期由 Harness 冻结。默认值必须有界、可取消并在界面中可解释，不能改变无云、显式权限和不自动重试副作用请求的语义。

## 13. HTTP 垂直切片实施证据（2026-09-01）

本节只记录当前代码事实，不把本文件中的设备配对、远程启动或 Android 本机计划提前宣称为完成。

### 13.1 已自动验证

- 官方目录、Compiler、ECIR 适配器、Windows Runtime 与 Android Kotlin Runtime 已闭环 `网络.请求`、`网络.上传文件`、`网络.下载文件`；Windows 宿主操作 ADB 目标与无目标实例复用 Windows 实现。Android 本机函数契约仍保持 `planned`，直到签名 APK 在物理设备完成全部文件/网络故障矩阵后才提升为 verified。
- 查询参数、请求头和 multipart 字段均为有序记录列表，保留同名项；普通请求正文只接受文本/JSON，`GET / HEAD` 携带正文时 Windows 与 Android 均在联网前返回 `network.body_not_allowed`，避免宿主库差异；文本响应使用稳定 `http_response.field.*`，文件响应不进入普通请求值。
- 字面量 URL 由 Compiler 生成精确 scheme/host/port 授权；动态 URL 没有项目 `network_policies` 时编译失败。Runtime 拒绝非 HTTP(S)、内嵌凭据和越权端口，在每次请求/重定向前解析并分类地址，并把已经批准的数值 IP 固定到传输连接，Host/SNI/证书验证仍使用原主机名。
- 重定向默认仅同源；已授权跨源跳转会移除认证、Cookie 和标记为敏感的请求头。HTTPS 始终使用系统信任并验证主机名，没有关闭验证的参数。每次调用使用独立 HTTP 上下文，不保存 Cookie，也不自动重试。
- 上传在联网前验证可读 `FileReference` 并由传输层按需读取文件流。下载在联网前验证可写 `FileReference`，写入同目录受控临时文件，刷新成功后再 `os.replace` 原子提交；非 `2xx`、取消、中断、超限和提交失败均不改写旧目标。
- Publisher 从实际 ECIR 调用生成 `network_level / sources / calls / file_permissions`，缺少目标授权、`network`、上传读取或下载写入闭包时阻止发布；公网明文 HTTP 产生明确警告。报告只包含 origin 规则，不包含查询、正文、认证头或文件绝对路径。
- `tests/test_vnext_network_runtime_v6.py` 使用本机真实 TCP/HTTP 服务覆盖六种方法、重复键、文本/JSON、同源/跨源重定向、敏感头剥离、`4xx/5xx` 正常结果、无自动重试、总超时、响应上限、二进制拒绝、自签名 TLS 拒绝、DNS 范围越权、multipart 文件上传、流式下载、取消、中断、超限、提交失败、旧目标保护、Compiler→ECIR→Runtime 和 Publisher 闭包。签名 Bundle 回归由 `tests/test_vnext_bundle_signing_v6.py` 覆盖。

## 14. LAN 配对与控制面实施证据（2026-09-01）

### 14.1 已自动验证

- `core/vnext/lan_control_v6.py` 持久保存当前用户的 Ed25519 设备身份，Windows 私钥使用 DPAPI 保护；跨机配对使用短期码认证请求与响应并固定设备公钥/指纹，后续连接使用临时 X25519、HKDF 和 ChaCha20-Poly1305 完成双向认证加密。请求携带唯一 ID、时间与 TTL，并由持久 replay ledger 返回相同结果或拒绝同 ID 不同载荷。
- UDP 发现只返回待配对设备提示，不建立信任；二维码和手工地址进入同一认证配对流程。普通消息、状态查看和远程启动分别保存权限，远程启动另有限定产品/实例范围；撤销设备后旧固定身份不能继续请求。
- `api/routers/vnext_player_lan_router.py` 把 packaged Player 所需的监听、发现、配对、权限、撤销、刷新和诊断接口从 IDE/Hub 作者管理路由中独立出来。该 HTTP API 只应绑定 loopback；真实 LAN 流量使用上面的认证 socket，不能把 FastAPI 暴露到局域网代替设备协议。
- `tests/test_vnext_lan_control_v6.py` 使用真实 TCP/UDP、截断半连接和 Windows spawn 双进程覆盖身份重启、发现/手工地址、短期码过期、响应篡改、指纹不一致、重放、撤销、三项权限、可靠消息和 dispatch 幂等。测试出站连接守卫只允许 loopback/private 地址，结束后停止监听并回收子进程。
