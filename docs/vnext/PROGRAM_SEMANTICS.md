# 结构化程序语义

状态：`Approved`（核心语句、作用域、条件、结果、集合、值表达式与异常区域重试已冻结）

最近修订：2026-09-02

> 本文件不定义可手写语言，只定义 ProgramDocument 必须表达的程序语义。

## 1. 定位

用户通过函数目录、纵向结构化语句和右侧 Control 组织程序。系统把操作保存为版本化、强类型 ProgramDocument，并确定性编译为 ECIR。

ProgramDocument 没有关键字、缩进、引号、括号、词法或 Parser。中文函数名、区块标题和摘要是派生投影；持久化字段、类型 ID、函数 ID 与运行契约使用稳定英文标识。只读伪代码可以帮助理解，但不能编辑、保存或反向导入。

## 2. 项目函数与语句

每个项目函数包含稳定 `function_id`、`document_id`、有类型的输入/返回、局部符号表和按顺序组织的语句树。项目入口由 `project.json` 的稳定函数 ID 指定；显示名、目录和投影位置不参与长期绑定。

首版只提供以下通用语句：

| 语句 | 主要结构 |
| --- | --- |
| 函数调用 | 函数引用、参数映射、可选结果绑定 |
| 变量赋值 | 目标引用、值节点 |
| 条件分支 | 布尔条件、成立分支、附加分支、可选否则分支 |
| 循环 | 模式、条件/集合、循环体、循环符号 |
| 跳出循环 | 结束当前函数最近一层词法循环 |
| 跳过本轮 | 跳到当前函数最近一层词法循环的下一轮 |
| 返回 | 可选返回值 |
| 结束为失败 | 稳定错误 ID、字符串消息、可选 JSON 详情 |
| 异常区域 | 主体、可选重试策略、捕获分支、可选最终分支 |
| 目标作用域 | 目标引用、语句体 |
| 监听声明 | 事件源、可选条件、处理函数引用 |

普通函数始终使用“函数调用”语句，不因新增函数而增加语句种类。首版不支持 `goto`、自由连线、任意控制流图或两个并发操作目标的执行流。

## 3. 值节点与未配置状态

参数、赋值、条件和返回都使用有类型的值节点。基础范围包括：

- `unset`；
- 文本、整数、小数、布尔、空、日期、时间点和持续时间；
- 坐标、区域和路径；
- 局部符号、项目变量、资源、目标、应用配置、控件、实例和函数引用；
- 当前运行内的进程引用、窗口引用，以及不可变、带来源目标与空间版本的帧引用；
- 列表、字典、可选值和命名记录；
- 成员访问及递归、强类型、无副作用的纯值表达式。

集合纯值表达式使用封闭的词法选择器：列表只绑定当前项/当前序号，字典只绑定当前键/当前值；每个绑定使用稳定 `symbol_id`，同名内层绑定只遮蔽显示名，不会改变外层引用身份。选择器只能出现在核心集合操作声明的输入槽，不能成为普通调用参数根、逃逸为局部变量或承载普通函数/I/O。

首版官方记录类型包括 `TargetInfo`、`FrameReference`、`ImageMatch`、`OCRResult` 与 `OCRLine`；其稳定字段契约见 [`FUNCTIONS.md`](FUNCTIONS.md)。从授权目录派生文件引用与解析 JSON 文本分别使用核心纯值操作 `core.file_ref_child.v1` 和 `core.json_parse_text.v1`，不是隐藏 I/O 或普通函数调用。

`unset` 表示必填值尚未配置，不是运行时类型。包含 `unset` 的文档可以保存和继续编辑，但 Compiler Service 必须拒绝编译、运行和发布，并把诊断定位到 `function_id + statement_id + value_id`，同时提供可读字段路径。

每次函数调用只有一个逻辑返回值；该值可以是简单值、列表、字典、可选值或命名记录。函数需要返回多项相关信息时使用命名记录，不使用位置不明的元组或多个互不关联的输出槽。命名记录字段由契约声明稳定 `field_id`、类型和显示信息；记录值在脚本中不可原地修改。

只有“有值 / 无值”两种正常结果的函数使用 `optional<T>`，无值使用明确空状态而不是空记录 `{}` 或伪造默认字段。用户投影统一显示“有结果”，不要求用户理解 `optional`；条件确认有结果后，类型系统在成立作用域内把该值收窄为 `T`，用于表达无结果是正常业务分支。未收窄的可选值也可以通过成员选择器严格消费：编译后的成员结果保持字段声明类型，Runtime 若发现来源为空则以 `runtime.optional_empty` 结构化异常停止当前运行，并定位到消费语句；不得静默变成假值、空文本、零或伪造结构。

图像匹配、OCR、消息等多字段结果使用命名记录；动态字典继续通过有类型的字典读取操作访问，不伪装成记录成员。正常无结果与资源缺失、权限不足、目标断开等异常保持分离。坐标、区域、控件和帧等空间值携带来源目标，成员访问不能绕过跨目标校验。

## 4. 作用域与变量

前台只显示两类变量：

- **局部变量**：函数参数、调用结果、赋值、循环项和异常捕获产生，只在当前函数调用中有效。
- **项目变量**：项目显式定义；任务启动时由默认值和 Player 运行方案创建会话副本，所有项目函数共享，任务结束后释放且不回写。

引用使用稳定 `symbol_id` 或 `variable_id`。重命名修改显示属性并更新投影，不做文本搜索替换。时间、目标尺寸和项目目录由类型化函数返回；长期数据显式通过 `文件.*` 操作，不给项目变量增加持久模式。

## 5. 调用、结果与异常

函数契约声明稳定参数 ID、类型、默认值、返回、正常空结果、异常、平台、权限、超时和取消语义。调用按参数 ID 保存值节点，不依赖参数顺序或显示名。

- 没有默认值且未填写的必填参数保存为 `unset`。
- 调用结果可以不绑定，或绑定到新建/已有的兼容局部符号。
- “图像未找到”“OCR 没有文字”等可预期情况返回正常结果。
- 图片、文字或控件等待到期同样返回正常的明确空结果，不产生异常或伪造默认值。
- 资源缺失、权限不足、目标断开、驱动或扩展崩溃返回结构化异常。

应用配置引用可以作为项目/Player 的类型化输入；进程、窗口和帧引用只在当前运行中由函数结果创建并绑定为局部符号，不能保存为项目变量默认值、Player 字段或跨运行数据。应用启动返回进程引用，等待退出只消费该引用；窗口查找返回可选窗口引用，激活、关闭和状态读取在使用前重新验证窗口身份，不能只信任可能被系统复用的句柄。

视觉函数没有显式帧参数时，在调用开始后从当前目标取得新帧；不能消费上一条调用的隐式缓存。显式取帧调用产生当前运行内的不可变帧引用，后续多个图像/OCR 调用使用该引用时分析完全相同的像素，并使结果继承帧的来源 `target_id` 与空间版本。帧引用不是图片资源。

官方标准函数和项目函数使用 ProgramDocument 组合。官方标准函数可以有融合实现，但必须通过返回、错误、超时、取消、日志和调试语义的等价性测试。扩展函数通过契约调用，其 Python/原生实现不进入 ProgramDocument。

标准函数的规范 ProgramDocument 可使用普通结构语句和已批准纯值操作，不因“官方”取得隐藏控制流。`core.duration_poll_count.v1` 只把有界超时和检查间隔确定性投影为最大检查次数；`core.text_matches.v1` 只实现 `exact / contains / regex` 文本匹配。两者均是无 I/O、无时钟读取、无隐式等待的纯操作，编译器对未知版本或类型不匹配继续使用 `PGM-OP-001..004` 阻断。融合 Runtime 可使用真实单调截止时间减少调度误差，但必须与规范文档的可观察返回和原子调用轨迹等价。

视觉动作标准函数采用“先观察、必要时动作、再观察”的固定语义。`standard.image.click_position_until_visible / hidden` 不拥有新的输入能力：每轮调用 `vision.find` 获取新帧，条件未满足时调用一次 `input.click` 点击作者给定坐标，并使用可取消间隔继续；条件已经满足时不产生输入。超时是带 `reached=false` 的正常结果，目标、权限、资源和驱动错误仍保留原结构化异常。

普通函数调用始终是独立 `call` 语句，不能嵌入参数、条件或另一个函数调用。项目函数即使只返回坐标、文本或布尔值，也先执行为一条语句并把结果绑定为局部符号；后续语句再使用该符号。返回值保证存在时可直接使用；可能无结果时，作者可以用“有结果”处理正常分支，也可以直接读取成员并接受空值时当前运行结构化失败。

参数可以包含只基于现有值进行、无截图/输入/等待/文件/消息/目标访问的确定性值计算，例如数值运算、文本组合、时间与坐标计算、条件取值、结构构造和明确类型转换。所有经核心批准的纯操作允许递归组合兼容值节点；值计算不是隐藏的普通函数调用。完整类型、稳定 ID、提取、Player 绑定和安全预算遵循 [`EXPRESSIONS.md`](EXPRESSIONS.md)。

记录、列表、字典和 JSON 的完整语义遵循 [`COLLECTIONS.md`](COLLECTIONS.md)。筛选、转换、排序、分组和统计属于无副作用集合表达式；逐项需要普通函数或 I/O 时使用显式循环。循环在进入时固定集合快照，并为循环体提供有类型的当前项/序号或当前键/值局部符号。

## 6. 控制流与监听

条件使用强类型条件树，叶节点只能是布尔值或类型化比较，组合节点只能是“全部满足”“任一满足”和“取反”。文本、数值、记录、列表等非布尔值不参与隐式真假转换；比较操作由左右值类型决定，不兼容的比较在编译前诊断。

“全部满足”和“任一满足”按投影顺序短路求值。“全部满足”遇到首个不成立项后停止，“任一满足”遇到首个成立项后停止。输入、文件写入、目标切换等有副作用操作不得成为条件值；正常未命中与结构化异常不得折叠为同一个 `false`。需要连续帧、等待窗口、顺序事件或多步骤计算的判断使用普通官方、项目或扩展函数产生有类型结果，不把时间状态机塞入条件树。

循环声明明确终止方式和安全检查点；异常区域只捕获契约、平台或“结束为失败”语句产生的结构化异常，未捕获异常沿调用栈传播。

“跳出循环”与“跳过本轮”只能放在当前项目函数词法上实际包含它们的循环体内；嵌套条件、目标作用域和异常区域不另建循环边界。两者分别结束或继续最近一层循环，穿过异常区域时仍先执行最终分支，且绝不能跨项目函数调用边界控制调用者循环。结构命令拒绝在循环外创建或移动这两种语句；Schema/语义校验仍会阻止外部损坏文档进入编译、运行与发布。

“结束为失败”求值字符串消息和可选 JSON 详情后，使用语句保存的稳定错误 ID 抛出永久结构化异常。现有异常区域可以按错误 ID捕获；未捕获时当前任务失败并记录稳定函数、语句、错误 ID、消息和经过脱敏/限长的详情。它不绕过捕获或最终分支，也不触发仅处理瞬时异常的重试策略。

重试只作为异常区域的可选策略存在，不增加 `retry` 语句、`重试.*` 函数，也不给普通函数统一复制“重试次数/失败策略”参数。没有策略时，异常区域保持普通捕获语义。开启策略时默认“首次失败后最多再试 2 次、固定间隔 500ms、仅瞬时异常”；次数与间隔在进入异常区域时求值一次，`最多再试 2 次`表示包括首次执行在内最多尝试 3 次。

函数契约为每类异常声明稳定异常 ID 与 `transient / permanent` 重试分类；未知异常按永久异常处理。主体正常完成、图片/OCR/控件/窗口无结果、等待到期和 HTTP `4xx/5xx` 正常响应都不触发重试。永久异常直接进入匹配捕获分支；瞬时异常在仍有次数时记录本次失败，可取消地等待，再从主体第一条语句重新执行。耗尽后只把最后异常交给匹配捕获分支，没有匹配时向上传播。失败尝试期间不运行捕获或最终分支；异常区域最终离开时，最终分支只执行一次。

重新执行不恢复运行快照，也不回滚已发生的点击、输入、项目/局部变量修改、消息、HTTP、上传或文件写入。区域包含直接或传递副作用时，IDE 必须列出风险并要求作者显式确认；确认绑定规范化区域主体和锁定函数契约指纹，主体或契约变化后失效并阻止运行/发布，直到重新审核。取消与停止是控制信号，永不重试；主动暂停不是异常，暂停期间冻结当前尝试或剩余间隔，继续后恢复同一现场。

作者确认通过受约束的 `review_retry_risk` 结构命令提交。客户端只提交异常区域的稳定 `statement_id` 和当前文档 `expected_revision`；Program Service 从该 revision 对应的主体与锁定函数契约计算审核指纹，并把指纹写入 `retry_policy.author_review_fingerprint`。客户端不能提交、覆盖或复用指纹。没有重试策略或主体没有已声明副作用时，服务以可修复请求错误拒绝审核。审核写入产生新 revision，进入同一撤销/重做历史并返回完整 ProgramDocument 快照；并发 revision 不一致返回冲突，不修改磁盘。主体或相关函数契约变化后，编译器重新计算的预期指纹与旧值不同，因此保存仍允许，但编译、运行和发布返回定位到该异常区域的 `PGM-TRY-003`，直到作者重新审核。

消息投递、更新下载和幂等派发的内部技术重试继续由对应服务契约治理，不成为 ProgramDocument 异常区域，也不在函数库产生重复入口。

“执行前观察—必要时执行—执行后验证”是推荐的项目函数写法，不是特殊语句或 `任务.确保完成` 官方函数。

监听是结构化语句与运行时调度机制，不是消息函数的别名。监听声明包含事件源、可选无副作用条件和普通项目处理函数。运行时只在存在候选事件时判断条件；条件成立后，在安全检查点挂起主流程并串行调用处理函数，函数正常结束后从主流程下一条语句继续。

监听条件不得执行输入、目标切换或文件写入。一次点击、拖拽、输入和事务写入不可中途打断；长操作必须提供安全检查点。监听器不重入，同一监听器按到达顺序处理。停止、取消、进程退出或崩溃不恢复旧调用栈。

## 7. 编辑与诊断

左侧创建调用或结构，中央选择、排序和嵌套语句，右侧修改全部参数与返回绑定。每个动作提交结构命令；不存在文本光标、补全、格式化或“先写错再解析”的工作流。

缺少必填值、类型不兼容、引用失效和平台不支持属于可定位语义诊断，检查器仍可编辑并修复。损坏 JSON、未知 Schema 或重复稳定 ID 属于项目结构损坏，只允许只读恢复，不由 IDE 猜测修复。

`[REQ-PGM-RECOVERY-001]` 调用语句缺少当前锁定函数契约中的参数节点时，属于可恢复的结构草稿，不得要求前端按控件类型猜值，也不得在读取项目时静默改盘。检查器把重复的逐字段错误合并为一个就近恢复动作；作者确认后，Program Service 通过 `repair_missing_arguments` 命令一次补齐该调用的全部缺失参数：有契约默认值时生成对应强类型值节点，没有默认值时生成显式 `unset`。命令必须保留已有参数及其全部稳定 ID，新的值节点使用新 ID，危险调用审核失效，并在单一 revision 内完成校验、原子保存和一次撤销记录。未知/多余参数不由该命令删除，继续交由诊断处理。

`[REQ-PGM-RUNTIME-RECOVERY-001]` IDE 页面刷新、渲染器重建或前端临时断线不得取消、复制或遗弃仍由本机 Runtime 持有的运行。工作区重新载入后，前端必须按 `workspace_id + generation` 解析出的权威项目路径查询当前 `queued / running / paused` 会话，优先接回本标签页记录的准确 `execution_id`，否则接回该项目最新活动会话，并恢复事件游标及暂停、继续、单步和停止控制。没有活动会话时只回到可运行状态，不得自动重跑；后端进程已经重启或会话被清理时不恢复旧调用栈，只明确说明原会话已结束并允许创建新运行。

`PGM-TRY-003` 与未配置值一样属于可修复草稿诊断：结构命令可以继续修改区域主体，Compiler Service 仍把它作为执行与发布阻断项。这样作者能够先完成副作用主体，再对最终内容执行审核，不需要客户端伪造中间审核状态。

模型可保存不等于 Runtime 已承接。Compiler Service 对全部已批准语句和值执行闭环检查：`assignment / if / loop / return / try / target_scope / listen` 已进入 ECIR 与进程内 Windows Runtime及隔离 Worker。`target_scope` 必须把引用到的强类型目标定义锁入 ECIR 闭包，缺失、重复、Android 本机跨宿主引用分别在编译期以 `PGM-TARGET-001..003` 阻止；Windows Runtime 仅串行切换 Windows/ADB，进入前验证首帧，退出、异常或取消均恢复上一逻辑目标并释放作用域驱动。`listen` 把普通项目处理函数一并链接进执行闭包，在语句边界和可取消长等待的周期性安全检查点串行调度；与 `消息.等待接收` 的静态重叠由 `PGM-MSG-001` 阻断，动态范围无法证明互斥时由 `PGM-MSG-002` 保守阻断。纯值操作必须存在于版本化核心注册表；未知 ID 返回 `PGM-OP-001`，已批准但尚未闭环的操作返回 `PGM-OP-002`，输入槽或类型不匹配返回 `PGM-OP-003 / PGM-OP-004`。尚未承接的模型仍只能保存和编辑，不能生成 ECIR、运行或发布。

## 8. 值表达式边界

值表达式不设置面向产品的人为浅层上限。固定值、已有值和计算值共享同一类型化值节点模型；界面通过摘要、折叠、聚焦和显式提取保持可读。普通函数、任意文本、Python 片段和扩展自定义语法仍不得绕过该模型。循环引用及节点数量、编译时间、ECIR 体积和运行内存由 Harness 的高位安全预算治理，并必须产生可定位诊断。
