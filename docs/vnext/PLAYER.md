## 1. Player Schema 与参数覆盖

Player 表单保存渲染器无关的 Schema，包含响应式布局、Control、稳定绑定、类型、默认值、校验、显示条件、平台动作和权限。IDE 设计器与 Player 运行端共用强类型参数契约和 Control 原子组件；Windows 与 Android 运行 Player 共用同一编译后页面实现，由宿主适配器提供平台动作。

首个可执行的 Player Schema 固定为 **schema 3**。开发者当前可以显式发布项目变量、项目函数入口参数、某个函数调用语句的静态根参数、绑定具体 `target_id` 且由目标驱动真实消费的运行设置，以及项目函数按钮；默认不发布任何字段。`variable` 旧绑定、参数显示名补全和 schema 2 均不兼容、不双读、不迁移。

schema 3 的持久绑定只允许以下精确形状：

| 绑定 | 必填稳定字段 | 当前执行语义 |
| --- | --- | --- |
| `project_variable` | `variable_id` | 覆盖本次运行的项目变量初始值 |
| `function_parameter` | `function_id + parameter_id` | 为可执行项目函数提供入口参数 |
| `statement_parameter` | `function_id + statement_id + parameter_id` | 覆盖一条调用语句的静态根参数 |
| `function_action` | `function_id` | 将本次运行入口切换到该项目函数 |
| `setting` | `target_id + setting_id` | 只覆盖该具体目标的已验证驱动设置 |

每个非按钮控件同时保存权威 `source_type` 与后端生成的 `type_fingerprint`。指纹覆盖值类型和来源约束；类型、约束、语句、参数、函数、变量或目标任一失效时，保存、发布、方案保存和运行均明确失败，不从显示名、参数名或旧默认值猜测。表单根级 `bindings` 已移除；两个控件不能重复绑定同一来源，按钮值不能进入方案或 `player_values`。

运行值按“开发者在 Player 字段上声明的默认值 < 当前方案值 < 本次运行临时值”合并，合并和校验都在后端完成；前端不需要为了让默认值生效而把所有字段重复提交。标记为必填且没有字段默认值的入口参数，只在其所属项目函数成为本次实际入口时阻止运行；其他项目函数的参数不应误伤当前动作。具体目标设置只对当前选择目标校验和生效。

`map<string,bool>` 的键值复选清单允许开发者在单个选项上声明 `fixed_value: true | false`，并可附带 `fixed_reason`。`true` 表示固定必选，`false` 表示固定不可选；没有该字段的选项仍由终端用户编辑。固定状态属于 Player 表单契约而非视觉提示：IDE 设计器负责配置，Player 使用锁标识、状态文字和禁用交互进行投影，后端在表单保存、方案保存及每次运行前把默认值、方案值和临时提交值归一到固定值，不能通过旧方案或直接请求绕过。

- `[REQ-PLY-OPTION-001]` `fixed_value` 只允许用于 `key-value` Control 绑定的 `map<string,bool>`，选项值必须是默认字典中的字符串键；其他控件、类型或缺失键以 `PLY-OPTION-001` 明确拒绝。
- `[REQ-PLY-OPTION-002]` Player 对固定选项同时显示锁图标和“必选/不可选”文字，保留原复选框位置且不可交互；`fixed_reason` 进入 tooltip 和可访问名称，不只依赖颜色表达状态。
- `[REQ-PLY-OPTION-003]` 固定状态对字段默认值、已保存方案和本次运行临时值采用同一服务端归一规则；固定值必须进入最终项目变量覆盖，不能只在前端置灰。
- `[REQ-PLY-OPTION-004]` 未声明固定状态的既有 schema 3 表单和方案保持原语义，不引入迁移层或隐式锁定。

验收：`[AC-PLY-OPTION-001]` 设计器可把每个布尔字典键设为“用户可选 / 固定必选 / 固定不可选”并保存往返；`[AC-PLY-OPTION-002]` 桌面与窄屏 Player 均显示可读锁定状态且键盘/指针不能改变；`[AC-PLY-OPTION-003]` 伪造相反的方案值或临时值后，运行覆盖仍为作者固定值；`[AC-PLY-OPTION-004]` 非布尔字典或不存在的键声明固定状态时保存、发布和运行一致失败。

IDE 设计器只能消费工作区范围的 Player 绑定来源目录。目录由后端从当前 Linked ECIR、项目变量和完整目标注册表生成，返回稳定 `binding`、层级路径、推荐 Control、默认值、约束、来源必填性、`source_type` 和 `type_fingerprint`；前端不得复制指纹算法、推导参数 ID 或展示目录中不存在的来源。函数契约声明的必填参数不能被表单字段降级为可选；动态表达式、引用和资源/目标根引用不会伪装成普通语句参数进入目录。项目草稿未通过检查时，目录以 `available=false`、空 `sources`、可读 `unavailable_reason` 和编译诊断正常返回；这是可恢复的作者状态，不得误报为工作区冲突或降级为手填绑定。

每个已发布字段还拥有独立的终端动作策略。动作按字段、动作种类和目标平台分别配置；新加入 Player 的字段由同一 `parameter_ui` 契约预选该类型安全且已有真实宿主承接的推荐动作，作者可逐项关闭，保存后仍以字段上的显式动作集合为唯一发布事实。既有表单缺少动作时继续等价于关闭，不存在项目级“允许 Player 捕获全部内容”总开关。作者开放动作只表示终端用户可以在编辑运行方案时主动发起该动作，不等于预先取得操作系统权限，不允许脚本静默触发截图、控件读取或文件浏览，也不扩大该字段之外的访问范围。

运行端实际可用动作严格取以下五方交集：作者在字段上发布的动作、字段类型允许的动作、发布包声明并携带的能力、当前宿主/目标驱动真实能力，以及当前权限与生命周期状态。未发布或结构上不支持的动作不进入发布闭包且不显示；权限被撤销、目标暂时离线等可恢复状态保留动作位置并说明原因。任何情况下都不能把坐标、区域、图片、控件、手势路径、文件或目录降级为普通文本绕过检查。

绑定使用判别式契约并只引用稳定 `function_id / statement_id / parameter_id / value_id / variable_id / asset_id / target_id`，不使用行号、显示名、树路径或投影位置。开发者可以暴露完整参数，也可以精确暴露表达式内选定的可配置值节点。运行前，Player 按 Schema 对终端用户值进行类型、约束、权限和平台校验，生成一层有类型参数覆盖/执行计划。**签名 ECIR 始终不变**；不建立可被表单改写的“私有 ECIR 副本”。

嵌套值、专用资源覆盖和专用目标引用仍采用“Compiler 签名覆盖槽”方向，但 **不属于当前 schema 3 可执行表面**。在 Compiler 为每个 `value_id / asset_id / target_id` 生成不可变覆盖槽、类型指纹、引用闭包和重叠关系之前，后端分别以 `PLY-BIND-010 / PLY-BIND-011` 拒绝，设计器不显示入口。不得用根参数覆盖、普通文本或 Player 私有 ECIR 绕过这个边界。

未来放行这些槽至少满足：Compiler 在 ECIR 中生成稳定且不可伪造的 override slot；Publisher 验证槽与资源/目标闭包；Bundle Loader 验证签名和类型指纹；Runtime 只向签名槽写最终值且不能更换操作、来源种类或结构；根与后代重叠覆盖被拒绝；复制、删除、提取和类型变化均有事务引用影响；Windows 与 Android Player 真实宿主通过方案保存、运行、失效和权限恢复 Harness。在这些验收项全部通过前，不得删除当前稳定拒绝。

运行时从发布包中的签名 ECIR 创建本次运行的深拷贝，再把已验证值写入上述稳定槽；发布包中的原始 ECIR 始终只读。IDE Player 预览必须复用同一表单、来源校验、运行适配和目标覆盖计划，不允许回退旧 `.easy` 或旧 `run-project`。预览端点只有在真实 Runtime 已创建运行 ID 后才能向界面返回启动成功。

## 2. 设计器与运行端

颜色字段使用共享 RGBA Control，可直接通过色板、十六进制和透明度编辑。字段可声明 `pick-color`；它从当前目标的一张冻结原帧点选像素并原子保存 RGBA。该动作只有作者逐字段、逐平台开放并进入签名权限闭包后才可由终端用户主动触发。取消或确认失败保留原值。

设计器使用左侧字段/区块树、中央响应式预览和右侧属性，不使用绝对像素自由摆放。局部变量不能成为长期绑定；需要终端用户配置的值应提升为项目变量或函数入口参数。

Player 根级“应用设置”保存应用名称和可选图片图标。名称显示在设计预览、正式 Player 标题栏和 Windows 原生窗口标题；图标显示在标题栏、任务栏和原生窗口。图标只引用项目资源库中的 PNG、JPG、JPEG 或 BMP，删除资源前按真实 Player 引用阻止；未设置名称或图标时使用 EasyCode 默认外观。发布时从已经验证的 `.ecplayer` 派生显示元数据，不能由命令行临时替换签名表单含义。

- `[REQ-PLY-BRAND-001]` 应用名称与可选图标属于 schema 3 Player 表单唯一事实；IDE 预览、Vue Player 和 Windows 原生宿主不得分别保存另一份名称或图片选择。
- `[REQ-PLY-BRAND-002]` 未配置品牌时回退 EasyCode 默认外观；配置无效、资源缺失或不受原生窗口支持时保存或发布明确失败，不生成半品牌包。
- `[REQ-PLY-SCROLL-001]` 桌面 Player 的页面导航、参数区和运行区在各自高度内纵向滚动并隐藏横向溢出；窄于 760px 时由页面主体承担一条连续纵向滚动，所有字段与操作保持可达。
- `[REQ-PLY-WINDOW-001]` Windows Player 使用无浏览器页头的原生可缩放窗口，提供最小化、最大化/还原和关闭；关闭可见 DWM 描边与圆角时仍保留不可见边缘缩放热区。
- `[REQ-PLY-WINDOW-002]` Windows Player 的标题栏关闭与 `Alt+F4` 必须走同一受控退出路径。无活动运行时释放 Capture、录制、Runtime、本地 HTTP 服务和原生宿主后完整退出；存在运行、暂停或排队任务时先显示应用内确认，取消保持窗口与现场，确认后安全停止任务并完成清理再关闭。任何停止或清理失败都必须保持窗口可见并给出恢复动作，不能只关闭 WebView 而留下 `EasycodePlayer.exe`。
- `[REQ-PLY-NAV-001]` Player 页面导航位于参数内容顶部并使用共享页签；只有一个页面时不占用导航空间。页签超出可用宽度时保留当前页和可容纳的前序页，其余页面进入“更多页面”菜单，不建立第三条固定侧栏，也不产生横向页面滚动。
- `[REQ-PLY-RUNTIME-001]` 运行面板只在发布包包含多个运行目标时显示“运行目标”选择；单目标项目直接使用唯一目标，不重复展示已经由 Player 字段承担的目标窗口实例配置。
- `[REQ-PLY-FEATURE-001]` 运行录制是作者按项目显式发布的可选 Player 能力，表单缺省为关闭。关闭时终端不显示录制设置、状态或历史，不允许方案经 API 开启录制，不启动帧订阅、编码、清理轮询或写盘；开启时保留完整的方案 revision 确认、本机历史、配额保护和显式导出能力。共享 Windows Runtime 可以携带经过闭包验证的实现，但小项目的签名产品契约、权限与运行活动不得隐式启用它。

验收：`[AC-PLY-BRAND-001]` 设置名称和图标、保存、发布并直接双击交付目录中的 EXE 后，原生标题、任务栏与 Player 标题栏一致；清空图标后重新发布恢复默认图标。`[AC-PLY-SCROLL-001]` 使用超出窗口高度的真实表单，在桌面三栏和窄屏中均可滚动到最后一个字段及运行控制，页面不产生横向滚动。`[AC-PLY-WINDOW-001]` 独立 EXE 不显示浏览器地址栏，四个窗口动作和边缘缩放均在真实 Windows 宿主通过。`[AC-PLY-WINDOW-002]` 在冻结 Player 中分别验证空闲关闭、活动任务取消关闭、确认停止并关闭、停止失败四条路径；成功关闭后进程、loopback 端口、捕获宿主和发布目录文件锁全部释放，立即重新打开与重新打包均成功。

`[AC-PLY-NAV-001]` 以 1、3、12 个页面分别验证：单页无导航占位；多页使用顶部页签；缩窄窗口后当前页仍可见、溢出页面可从“更多页面”选择，切换不清空未保存字段。`[AC-PLY-RUNTIME-001]` 单目标包不显示重复运行目标选择，多目标包仍能明确选择本次运行目标。`[AC-PLY-FEATURE-001]` 同一项目分别发布关闭与开启录制的候选；关闭候选无录制 UI/API 启用/运行活动，开启候选完成录制、停止、历史和导出闭环。

- `[REQ-PLY-AUTHOR-001]` Player 绑定选择器以“来源类型 → 项目函数 → 语句 → 参数”的可读上下文展示目录。重复函数调用不能只显示相同函数名；优先显示可选步骤备注和关键资源名，仍无法区分时显示稳定 `statement_id` 的短投影。短投影只用于识别，绑定仍保存完整稳定 ID。
- `[REQ-PLY-AUTHOR-002]` 语句检查器提供低噪的“复制语句 ID”动作；绑定选择器搜索同时覆盖显示名、层级路径、完整稳定 ID 和短投影。粘贴完整或短语句 ID 时，结果收束到该语句真实可发布的参数，不允许根据文本临时构造绑定。
- `[REQ-PLY-AUTHOR-003]` 图片资源参数在语句投影和绑定选择器中使用紧凑缩略图与资源名称辅助区分；缩略图按需加载，失败时退化为统一图片图标和名称，不阻止绑定、编辑或键盘操作。
- `[REQ-PLY-AUTHOR-004]` 稳定 ID 是精确定位的备用路径，不是普通用户的主操作。语句检查器提供“在 Player 中查找可发布参数”主路径：跳转后由 Player 设计器筛选同一后端 `binding-sources` 目录，开发者仍需选择具体参数并显式添加。不得绕过目录直接生成控件。
- `[REQ-PLY-AUTHOR-005]` 直达 Player 、打开绑定选择器和搜索不得改写表单。全新项目可在尚无 Player 页面时浏览绑定；只有开发者显式点击“添加”后，才创建第一个页面和字段。

Control 至少覆盖文本、整数/小数、布尔、枚举、时长/时间点、颜色、坐标、区域、图片资源、控件选择器、目标、实例多选、手势路径、列表、字典、记录对象和递归纯值表达式。IDE 与 Player 复用同一强类型 Control 原子、值形状和动作元数据；两端可以采用不同页面布局和权限宿主，但不得为 Player 重写一套只显示内部字符或 JSON 的弱类型表单。目标平台在结构上不支持某个捕获动作时不发布也不显示该动作；已经发布但因权限、未保存方案或目标状态暂时不可用时保留在字段旁、禁用并解释原因。两种情况都不能降级字段的真实数据结构。

- `[REQ-PLY-CONTROL-001]` 暴露到 Player 的字段必须由共享强类型 Control 投影并可按其类型编辑；颜色使用 RGBA/颜色预览，坐标与区域允许数值微调，图片、窗口、控件、路径和文件引用显示可读摘要，不能把内部 ID、选择器 JSON、URI 或伪路径当作用户编辑界面。
- `[REQ-PLY-CONTROL-002]` 设计器新加入字段时，从权威 `parameter_ui.actions` 与字段/宿主平台交集生成推荐终端动作并显式保存；作者可以逐项关闭，Publisher 仍只签名最终显式集合，旧字段不因打开项目被隐式改写。
- `[REQ-PLY-CONTROL-003]` 已签名动作因未保存方案、目标未保存、权限撤销、目标离线或运行中而暂时不可用时，Player 必须在所属字段旁保留禁用入口和可读原因；不得因为平台推导失败让动作无声消失。

终端动作使用以下稳定语义，不以笼统的“捕获”或同名“路径”混在一起：

| 字段类型 | 作者可开放的动作 | 类型化结果 |
| --- | --- | --- |
| 坐标 | 拾取坐标 | 带来源目标和坐标空间的坐标 |
| 区域 | 框选区域 | 带来源目标和坐标空间的区域 |
| 图片资源/覆盖 | 从当前画面截取图片、从设备选择图片 | Player 私有图片覆盖引用 |
| 控件选择器 | 捕获控件 | 当前目标驱动定义的控件选择器 |
| Windows 目标窗口实例 | 捕获目标窗口 | 当前方案私有的版本化窗口绑定 |
| 手势路径 | 录制手势路径 | 带来源目标和坐标空间的路径点列表 |
| 文件引用 | 选择要读取的文件、选择保存位置 | 带读取或写入访问模式的文件引用 |
| 目录引用 | 选择文件夹 | 带读取或写入访问模式的目录引用 |

“从当前画面截取图片”是图片字段的录入动作，不建立独立截图值类型；“录制手势路径”与文件系统路径使用不同名称、图标和类型。控件捕获只有在当前目标驱动能返回契约认可的稳定选择器时才可用，不能因为平台名为 Windows 或 Android 就推断一定支持。

设计器右侧为每个字段生成“允许终端用户操作”区，只列该字段类型可能支持的手动编辑、清空、恢复开发者默认值和捕获/选择动作，并显示 Windows、ADB 与 Android 本机的平台可用性。文件字段还必须明确读取文件、创建/选择保存文件或选择目录，以及读取/写入模式和文件类型约束。发布前检查动作、平台、宿主、权限和闭包；没有实现或返回类型不兼容的动作阻止发布，不产生仅供预览的假入口。

集合字段根据 Schema 投影为多选、逐项编辑、重复卡片、记录表格、键值表格或嵌套子表。开发者可以分别授权新增、删除、重排、键修改、字段修改和 JSON 导入；大型字段虚拟化并使用有界预览。任意 JSON 只有在开发者显式提供 JSON 字段或完成 Schema 转换后才能进入 Player 表单。

最终 Player 只显示项目/版本、运行方案、开发者发布的表单、真实状态、开始/暂停/继续/停止和选定日志。目标替换、资源替换和诊断只在开发者发布且当前平台支持时出现。

终端动作紧邻所属字段。单一高频动作使用一个低噪按钮，多个动作使用主动作与“更多”菜单；永久不可能使用的动作不显示，暂时不可用但可以恢复的动作禁用并在原位说明。用户触发需要权限的动作时，Player 先用一句话说明用途和访问范围，再进入当前平台的系统授权或选择流程，不在普通参数区堆放权限开关。系统返回、取消、拒绝或恢复权限后回到原字段并恢复焦点、滚动和未提交草稿。

`control_selector`、手势路径、文件和目录等强类型配置只显示可读摘要与终端动作，不显示可编辑 selector、JSON、URI 或伪路径。控件捕获保存可跨运行重新定位的选择器；`control_ref` 仅由 `控件.查找` 在一次运行中产生，不能进入 Player 方案。坐标和区域允许数值微调并同时提供取点/框选；图片允许选择发布资源并按授权提供截取或设备选图。Player 重新打开时优先恢复上次仍存在的运行方案，否则选择首个保存方案；没有保存方案时才进入“当前配置（终端采集关闭）”。

Windows 目标的冻结帧按真实客户区屏幕位置对齐；ADB/Android 画面采用当前显示器安全工作区内的等比居中适配。两者都把显示坐标反算为目标原始帧坐标后再提交，显示缩放和多显示器布局不得改变结果语义。切换目标或尚未保存方案时，已经发布且平台适用的终端动作必须保留禁用入口，并在字段原位与运行准备区解释“先保存当前目标/方案”，不能让按钮无声消失。

Windows IDE 的设计器可以切换桌面与 Android 预览视口。Android 运行端加载与 Windows 相同的编译后 Player 页面，但使用其移动响应式投影而非复刻桌面三栏：顶部承载项目/方案/权限与目标状态，中部按区块渲染字段，底部在系统安全区内保留主要运行操作；日志与高级诊断按页面或抽屉展开。横竖屏、字体放大和方向变化不得丢失字段草稿或重建正在运行的任务；系统捕获/选择器返回后必须回到原字段并刷新权威方案。

## 3. 运行方案和资源替换

运行方案保存在当前用户的 Player 数据目录，不修改 `.ecplayer`。它们只保存已发布 Control 的可序列化值和目标选择；项目变量覆盖只是任务初始值，运行期修改不回写方案。

Windows 作者可把 `target.window_binding` 作为“目标窗口实例”字段发布，并逐平台授权 `capture-window`。终端用户必须先保存方案，再点击字段旁的窗口捕获图标，从全桌面冻结帧选择具体窗口；确认只更新当前 Player 实例的该方案并递增 revision。运行、环境检查以及点/区域/图片/控件等后续终端捕获统一使用合并后的有效目标。标题、目标类型、工作区域或其他未发布目标字段不能借此被任意替换；稳定特征无法唯一恢复时原位要求重新捕获。

方案保存阶段即复用 schema 3 的完整绑定、类型、来源约束、控件约束、目标作用域和失效校验；未知控件、按钮值、错误类型、越界值、过期指纹和不属于当前目标的设置均拒绝，且失败不得覆盖同名旧方案。运行前再次防御性复验。设置值按 `target_id -> setting_id` 隔离；为目标 A 发布的窗口标题不能污染或静默忽略在目标 B 的方案中。

图片字段可允许客户导入替换图并恢复开发者默认资源。替换文件位于这个 Player 实例的独立数据目录，只通过资源覆盖层生效，不修改发布包、ECIR 或 IDE 项目。

终端用户选择或截取的图片先写入当前 Player 实例的暂存区，校验格式、体积和哈希后再与字段值作为一个事务提交到受控覆盖目录；失败时保留旧值且不留下可见半资源。图片不长期绑定相册路径或 Android 临时 URI。恢复开发者默认值只移除该字段的覆盖引用，发布包内默认资源始终保持只读。

普通文件和目录字段与图片覆盖不同：它们保存强类型外部 `FileReference` 或 `DirectoryReference`，因为脚本需要继续访问用户选择的外部对象。引用携带平台载荷、读取/写入访问模式和可显示元数据；Windows 使用规范化路径引用，Android 使用系统授权的文档 URI。引用失效、权限撤销或外部对象被移动/删除时保留原配置并标记不可用，要求用户重选，不静默清空或改写为字符串。

普通目录选择只授予作者发布的基础能力。若该字段将进入 `目录.递归删除`，Player 在用户选择授权根后单独展示“此调用可删除该树内最终解析目录”与不可回滚风险，并把确认绑定到稳定调用、`authorization_root_id`、方案 revision 与函数契约指纹；派生引用只能缩小到该树内，任一绑定变化后阻止运行并要求重新确认。同一次实际执行内相同确认范围可以避免重复弹框；确认不写入运行方案或计划，跨运行及每次计划触发都必须重新取得。根目录、用户主目录、Player 数据根和其他保护根始终不能授权。

## 4. 运行状态

Player 展示等待、运行、暂停、完成、失败和停止的真实状态。主动暂停在同一 Player 进程内保留运行 ID、调用栈、局部值、项目变量、目标和监听状态；继续使用同一现场，不允许更换运行方案。

Capture Session 和文件/目录选择只允许在运行方案编辑状态发起；运行、暂停、停止处理中或任务排队时不得修改方案。一个 Player 实例同一时刻最多存在一个活动 Capture Session，第二次触发应聚焦现有会话或明确说明冲突，不能把结果回填到另一个字段。

若浏览器页、原生宿主或系统选择器在候选返回后失联，活动字段会话必须有界过期并释放，过期不修改方案值。Android Activity 因方向变化或系统重建时保存精确目的地和滚动锚点；系统动作返回后重新校验并滚回原字段，不能回到表单顶部让用户重新寻找。

Player 使用专属 `PlayerControlDestination` 标识回填目的地，精确包含 `product_id`、`release_id`、`profile_id`、`control_id`、`action_id`、`profile_revision` 和 `target_id`。只有已保存且拥有稳定 `profile_id + profile_revision` 的运行方案能发起终端动作；新建或尚未保存的草稿不创建临时 Capture 身份。点、区域、图片、控件和路径动作的 `target_id` 必须指向真实已保存目标；文件/目录系统选择器是主机动作，无操作目标方案可使用空 `target_id`。宿主启动前与返回结果后均重新验证全部身份、发布权限、字段类型、平台能力和方案 revision；任一身份或目标已变化时拒绝旧结果。确认只原子更新当前运行方案或私有资源覆盖，不修改 ProgramDocument、签名 ECIR 或发布包。

Capture 与文件选择日志只记录产品/发布/方案/字段/动作/目标身份、状态、耗时和结构化错误码；默认不记录图片内容、完整本机路径/URI、控件文本或文件正文。候选内容只有用户确认后才进入该 Player 实例的方案或私有覆盖目录，不因诊断、更新或普通遥测离开设备。

停止、取消、关闭 Player 或进程崩溃会释放现场。重新运行创建新运行 ID，按当次选择的方案从入口开始；不根据日志自动恢复旧调用栈。失败诊断可展示最后稳定语句和结果未知动作，但不伪造成功/失败结论。

### 4.1 运行录制与本机记录

Windows 与 Android Player 均提供首版运行录制能力，但默认关闭。终端用户可以在运行方案/诊断设置中选择全部帧、变化帧或诊断策略并确认到当前方案 revision；作者更新不能静默开启。运行中显示录制、空间、丢帧和停止原因，并允许“停止录制但继续任务”。

录制会话、历史帧和分析报告保存在当前 Player 实例的隔离数据目录，不修改 `.ecplayer`、ECIR 或运行方案业务参数。Player 提供会话列表、帧浏览、显式导出、删除和空间管理；Android 使用独立小屏页面。默认“画面与报告”导出排除 `AnalysisInputBundle`；高级“可重现分析包”逐类披露并由用户选择项目逻辑、资源、模型与参数依赖，排除秘密后无法重现时必须降级标记。未确认数据不离开设备。录制停止或失败不触发崩溃续接，也不改变当前任务结果。

## 5. 发布产物与加载

发布分为三个可验证边界：

1. **`.ecplayer`**：包含签名 ECIR、函数契约、调试映射的必要稳定 ID、目标配置、Player Schema、资源闭包、`easycode.lock` 选择的已构建/已签名 `ecx-runtime-1` 扩展闭包和发布报告。
2. **Windows Player Bundle**：包含一次构建、可复用的 Windows Runtime、轻量 Player 前端、`.ecplayer` 和原生宿主。客户不需要 Python、IDE 或项目目录。
3. **Android Player APK**：包含签名 Android Runtime、小屏 Player UI、`.ecplayer` 的平台适配内容、资源与 `easycode.lock` 选择的 Android 本机 `ecx-runtime-1` 扩展闭包。首个正式版本要求可安装签名 APK；AAB 只有在未来明确要求应用商店分发时才进入发布门。

三类产物都不得包含 ProgramDocument、结构化编辑元数据、可编辑伪代码、扩展源码/测试、外部 IDE 项目文件或 EasyCode IDE 组件。无法生成源码隔离运行产物的扩展必须阻止发布，不能静默携带开发源码。

Bundle Loader 在创建任务前验证格式版本、签名、哈希、路径穿越、符号链接、体积上限、目标平台、ABI、权限、`easycode-extension.json` / `easycode.lock`、密封产物和依赖闭包。终端客户只能提交开发者已发布的 Control ID；未知 ID、类型错误和越权动作在运行前被拒绝。

Publisher 从程序实际调用和已发布字段动作共同计算平台能力与权限闭包。未开放的终端动作不能增加 Manifest 权限、Android 服务、原生宿主模块或包体；开放动作也只能获得完成该动作所需的最小能力。Player Schema 不保存终端操作系统授权状态、临时 Capture Session、用户选择的本机路径/URI 或捕获候选。

### 5.1 独立 Windows Player 最小边界

Windows Player 使用专用进程入口、应用工厂、Runtime Router 和 Player-only Web 构建，不从 IDE 应用删菜单后复用。普通进程必须先固定 `.ecplayer` 与外部信任根，再导入应用或 Bundle Runtime；capability/extension worker 与 Player Hub agent 在更早的专用分支启动。HTTP 只监听 loopback，并以精确 OpenAPI 白名单暴露终端运行、Capture、更新、计划、Hub 与 LAN 管理能力。

Hub 打开的每个 Windows Player 实例使用系统原子分配的独立 loopback 端口，且以稳定实例数据根隔离方案、日志、图片覆盖和 WebView2 用户数据。实例窗口标题显示实例名，便于多开时确认正在配置哪个账号。固定端口不得成为第二实例失败原因，两个实例也不得共享可变浏览器会话或诊断文件。

专用 Runtime Router 不导入完整 vNext Router 或 Workspace Manager。终端 Capture 只公开 SSE、字段动作/ACK 和关闭；工作区、ProgramDocument、设计器、编译、作者发布/打包、扩展管理、旧 Capture/Replay、全局热键与 IDE 设置路径必须是 `404`，且对应模块不进入创建应用后的导入图。

Player Web 只生成 `player.html` 与 `capture.html`，不生成 IDE `index.html`，不交付 Vue/TypeScript 源或 source map。组装器从该目录复制编译产物，并在写入交付前扫描 Runtime、Web 和签名包文件清单，拒绝 `.easy`、ProgramDocument、`programs/` 及前端/Python 源。完整规范、失败语义与放行边界见 [`PUBLISHING.md`](PUBLISHING.md)。

## 6. 平台边界与 Android 完成门

Windows Player 支持 Windows 桌面/窗口与 Android ADB 目标的串行切换，任意时刻只有一个当前目标。纯逻辑、文件、消息和日志任务可使用无操作目标。Android 本机 Player 只操作当前手机，不切换到 Windows 或外部 ADB 目标。

Windows IDE 通过 USB/ADB 向真实设备部署或更新测试 APK、连接本机调试通道并读取结构化日志。测试报告必须明确标注运行 ECIR 的宿主；Windows Runtime 通过 `adb screencap/input` 操作设备属于 ADB 目标测试，不能作为 Android 本机 Player 证据。

Android 本机 Player 使用 MediaProjection 获取帧、AccessibilityService 执行输入，并以应用私有目录和 Android 系统授权文件引用处理文件。权限首次请求、拒绝、永久拒绝、被系统撤销、重启失效和前台服务中断都必须产生真实状态、恢复动作和结构化诊断。平台动作不可用时保持字段原值并解释原因，不把区域、图片、路径或目标降级为普通文本。

权限仅在用户主动触发相关字段动作或运行期真正需要该能力时请求。用户取消、拒绝、系统撤销、宿主终止或授权返回失败时，Player 保持字段旧值与草稿，只阻止受影响动作；永久拒绝不得循环弹出系统对话框，而应提供明确的设置恢复入口。恢复后返回原字段继续，不要求重新创建运行方案。Android 控件捕获按宿主对 Accessibility 节点选择器的真实支持条件开放，不属于首个正式版本的全设备硬门；点、区域、图片和手势路径 Capture Session 仍属于 Android 首版完成门。

Player 的业务成功、失败、确认、取消与可恢复警告统一使用 EasyCode 内的 Dialog、Toast、字段错误或原生捕获宿主 Notice；不得调用 Windows `MessageBox`或浏览器默认 `alert / confirm / prompt`。只有文件/目录选择、Android 权限/设置和 APK 安装等真实操作系统授权边界使用系统界面；返回后的说明、错误和恢复动作继续在 Player 内承接。Android 字段捕获由 EasyCode 悬浮按钮承接准备与开始动作，系统前台服务通知不得再提供倒计时、立即冻结、进入选择或取消等产品交互；冻结后直接在原始分辨率截图上叠加选区与确认控件，显示层不得进入保存像素。

首个正式版本的 Android 放行要求签名 APK 在断开数据线并关闭 IDE、后端后独立启动，完成运行方案加载、Player 表单校验、真实帧、图像/OCR、点击/滑动/拖拽/长按/文本输入、暂停/继续/停止、文件授权、消息和诊断。Android 垂直切片未通过前，APK 发布入口保持不可见或明确禁用，整个首个正式版本不得标记完成。

Player “环境检查”只由用户显式触发，依次验证包、目标绑定和一次真实画面获取，并立即释放临时驱动；空闲时不持续截图或轮询。

## 7. 本地优先与联网能力

- `[REQ-PLY-OFF-001]` 未声明公网能力的 Windows Bundle 与 Android APK 在无公网、无 IDE、无 EasyCode 云或单独开发后端时仍能打开、加载方案、运行、暂停/继续/停止并查看本地日志。
- `[REQ-PLY-OFF-002]` 发布包携带全部 Runtime、函数实现、Control、资源、OCR 数据、字体/图标、原生库和兼容扩展；Player 不在运行时补下载必需内容。
- `[REQ-PLY-OFF-003]` Compiler/Publisher 从实际调用和扩展权限派生“无网络 / 本机或局域网 / 公网”报告。Player 不依赖开发者手工维护的全局联网开关。
- `[REQ-PLY-OFF-004]` 无公网项目不隐式登录、在线验权、检查更新、上传遥测/崩溃或连接 CDN/远程模型。包内本地 Runtime、Worker 与 IPC 可以使用，但必须随包管理生命周期并与 IDE/远程服务区分。
- `[REQ-PLY-OFF-005]` 显式网络调用失败只影响当前调用和项目定义的普通错误处理；Player 外壳、本地运行方案和无关本地能力保持可用。
- `[REQ-PLY-OFF-006]` 更新和未来商业授权均不是运行热路径前置；平台不提供自动运行/崩溃遥测。若未来启用授权，Player 使用本地可验证凭据决定是否允许新任务，不能要求每次启动或任务联网，也不能因任务中途到期强制终止当前运行。

发布报告显示网络级别及其函数/扩展来源。完全本地项目断网时不显示阻塞性“离线”错误；需要网络的语句只在执行、预检或用户打开环境详情时显示对应状态。日志与诊断默认保存在设备本地，只有用户主动导出或项目显式调用声明过的联网能力时才能离开设备。

## 8. 在线更新

Player 应用更新与项目内容更新分别配置并默认关闭。关闭全部更新时发布包不携带更新端点、调度器或入口，也不发起检查请求。开启后，发布报告将它列为“在线维护服务”，不能把本地任务误报为必须联网。

项目内容更新只替换签名 ECIR、资源、Player Schema 和兼容项目数据；Runtime、宿主、原生扩展、权限或 ABI 变化必须发布新的 Windows Bundle 或 Android APK。每次运行固定一个不可变 `release_id`；运行和暂停期间可以检查与暂存，但不能切换。下载和验证失败保留当前版本，Windows 与内容包至少保留上一正常槽；运行方案和用户覆盖独立保存并按稳定 Control 兼容迁移。

Android 内容包在应用私有目录原子切换；APK 更新交给系统安装流程，用户取消或安装失败时旧 APK 继续可用。完整契约见 [`UPDATES.md`](UPDATES.md)。

Player 对 EasyCode 官方托管和作者自建兼容源使用同一 Feed 与验证状态机。终端公开更新不要求作者账号；源迁移或镜像变化必须经现有信任根签名。作者托管配额、VIP 或上传状态不得出现在终端 Player，也不能影响已经安装版本执行。

可选更新允许终端延后并继续新开任务。签名强制策略在宽限期结束后只阻止低版本开始新任务；已经运行或主动暂停的任务继续到终态。受限状态下 Player 仍可打开、查看原因/版本/日志、导出诊断、维护方案并重试更新。未取得新策略的离线客户端不猜测；已经取得的最后可信策略不能因断网、普通缓存清理或系统时钟回拨失效。

作者启用更新后，终端用户可以分别关闭普通可选更新的自动检查、自动下载和自动应用，手动检查始终可用；这些偏好跨版本保留且不能被作者普通发布重置。关闭“自动检查普通更新”不关闭已明确披露的轻量签名强制策略检查。已取得并验证的强制策略不受普通更新开关影响，用户只能在宽限期内选择更新时间。作者打包时关闭更新的 Player 不显示更新设置或入口，也不携带更新端点或任何更新调度器。

启用更新的 Player 为当前产品安装生成匿名“测试分组码”，正常升级后保留且不包含硬件、账号或运行数据。稳定版终端没有自行加入测试通道的开关；用户可以复制代码交给作者，只有作者把对应哈希加入测试白名单后才取得测试发布。移出白名单或重置代码不会自动降级已安装版本，客户端等待序号更高的兼容稳定发布追平。可选更新是否命中白名单/百分比由本机根据签名策略计算，未命中时显示“当前暂无面向此安装的更新”，不能伪报全局最新版。

## 9. 终端捕获与文件动作验收

- `[REQ-PLY-CAP-001]` Player 字段动作默认集合为空；只有作者逐字段、逐动作、逐平台发布且通过五方能力交集的动作才可见和可执行。
- `[REQ-PLY-CAP-002]` IDE 与 Player 对点、区域、图片、控件和手势路径复用同一结果类型；Player 通过 `PlayerControlDestination` 原子更新运行方案或私有资源覆盖，不修改 ProgramDocument、ECIR 或发布包。
- `[REQ-PLY-CAP-003]` 取消、系统返回、拒绝、永久拒绝、权限撤销、宿主崩溃、目标变化和过期结果都保持旧值与草稿；恢复后返回原字段，不发生跨字段回填。
- `[REQ-PLY-CAP-004]` 运行、暂停和任务排队期间不能进入终端捕获或修改方案；同一 Player 实例的 Capture Session 串行且具有可诊断冲突。
- `[REQ-PLY-CAP-005]` 图片选择和截取原子导入 Player 私有覆盖目录；复制、校验或空间不足失败不留下半资源，并可恢复开发者默认值。
- `[REQ-PLY-FILE-001]` 读取文件、保存文件和选择目录使用不同强类型动作与访问模式；Windows 路径引用和 Android 文档 URI 在同一高层契约下由各自宿主实现。
- `[REQ-PLY-FILE-002]` 文件/目录权限或引用失效时保留配置并显示重选入口；必填引用不可用时阻止运行，不能伪报成功或退化为普通文本。
- `[REQ-PLY-FILE-003]` 无操作目标方案仍可调用当前 Player 宿主的文件/目录系统选择器；必填强类型引用在授权前保持 `unset`，不写入伪造的 `null` 默认值。系统选择器的确认按钮就是用户确认，Player 返回后自动完成二次身份校验与原子回填，不再重复弹出“是否使用”。
- `[REQ-PLY-DIR-001]` 递归删除确认绑定稳定调用、`authorization_root_id`、方案 revision 与函数契约指纹；派生目标只能缩小到树内，确认缺失、变化、越界或指向保护根时运行前阻止。
- `[REQ-PLY-CAP-006]` 发布包只携带程序调用和已发布终端动作实际需要的权限与宿主能力；未开放动作不增加权限闭包，也不会在 Player 中产生入口。
- `[REQ-PLY-CAP-007]` 字段动作只能由终端用户显式触发；未确认候选和外部文件内容不进入运行方案、发布包或网络，结构化日志不得泄露完整内容。
- `[REQ-PLY-CAP-008]` Android 字段采集使用悬浮准备与原地冻结编辑：开始时完整隐藏 EasyCode 悬浮层并只接受之后的新原始分辨率帧；冻结光效、遮罩、选区和控件不进入图片；确认按原帧坐标原子回填，通知栏和页面跳转不承担采集交互。
- `[REQ-PLY-CAP-009]` 作者发布的 Windows“目标窗口实例”字段通过全桌面取点生成与 IDE 相同的版本化窗口绑定；确认只更新当前实例当前方案，取消、过期、歧义和跨方案结果保持旧值。运行及其他终端捕获统一消费方案合并后的有效目标。
- `[REQ-PLY-INSTANCE-001]` Hub 并行打开的 Player 实例使用互不冲突的系统分配 loopback 端口，并隔离方案、覆盖资源、日志和 WebView2 用户数据；每个实例独立申请管理员权限并显示实例名。
- `[REQ-PLY-UX-001]` Player 和原生 Capture 的业务反馈不调用 Windows/Browser 默认提示框；系统界面仅限真实授权、文件/目录选择和平台安装，取消或失败返回后保持原值并在 EasyCode 内提供恢复动作。
- `[REQ-PLY-CAP-003]` Windows 捕获层按目标工作区对齐；ADB/Android 捕获层等比居中适配并反算原始帧坐标。目标草稿与保存方案不一致时，终端动作状态和保存要求必须在原位可见。
- `[REQ-PLY-REPLAY-001]` Player 录制默认关闭且更新不能开启；用户可以按方案启用、运行中单独停止，并浏览、导出和删除本机录制。
- `[REQ-PLY-REPLAY-002]` 录制故障只停止 Recorder 并显示真实原因，不停止任务或伪造完整帧序列；两种导出明确区分是否包含分析快照，录制和分析数据不进入发布、更新或自动网络传输。
