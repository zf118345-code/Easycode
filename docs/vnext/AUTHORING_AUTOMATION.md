# 作者效率自动化能力

状态：Implemented（代码与自动验证完成；真实宿主发布门待执行）  
日期：2026-09-07  
主用户：脚本作者  
次用户：扩展作者、Player 操作者

## 1. 产品结果

作者可以用一次控件捕获获得可解释的稳定定位，可以把真实基础操作录制为可编辑的 ProgramDocument 骨架，可以为现有入口配置系统触发器，并可以在不进入第二套编辑器的前提下通过可导入扩展包使用浏览器 DOM 自动化。

这些能力缩短首次搭建时间，但不推断业务意图，不改变 ProgramDocument、ECIR、Player 字段或扩展信任的唯一事实来源。

## 2. 范围

### 2.1 可靠控件选择器

一次捕获只选择一个目标控件。捕获宿主从同一控件快照中生成一个主策略和有序后备策略；每个策略保存稳定属性、适用宿主、创建证据与最近测试结论。

```text
ControlSelectorV2
├─ selector_id
├─ target_id
├─ provider
├─ primary_strategy_id
├─ strategies[]
│  ├─ strategy_id
│  ├─ kind
│  ├─ predicates[]
│  ├─ relation_path[]
│  └─ stability_hints[]
└─ captured_space_version
```

Runtime 按冻结顺序解析策略。只有唯一候选完整满足当前策略时才能继续；零候选尝试下一策略；多候选、空间不匹配或稳定属性冲突立即停止并返回结构化异常。系统不使用概率性静默自愈。

实现位于 `control_selector_v2.py` 与 `control_selector_repair_v2.py`。Windows UIA 和 Android UIAutomator 共用策略顺序、即时测试结论和歧义停止语义；重新捕获先查询引用影响，再携带全部受影响函数 revision 和明确确认，通过项目事务一次更新或完整回滚。

- `[REQ-AUTH-SEL-001]` 用户一次捕获只选择一个控件，系统从同一快照生成主策略和后备策略。
- `[REQ-AUTH-SEL-002]` 捕获完成前，宿主必须重新定位并返回每条策略的成功、无结果、歧义或不可测试状态。
- `[REQ-AUTH-SEL-003]` Runtime 只按持久化顺序使用确定性策略，并在日志记录采用的 `strategy_id`。
- `[REQ-AUTH-SEL-004]` 歧义、目标变化和低质量快照不得产生点击或输入副作用。
- `[REQ-AUTH-SEL-005]` 重新捕获先计算引用影响，用户确认后通过项目事务替换同一 `selector_id` 的内容；取消或失败保留旧值。

### 2.2 结构化操作录制

操作录制与既有帧录制是两种不同会话：帧录制保存画面用于离线分析；操作录制监听作者明确开始后的输入和目标事件，停止后生成临时语句草稿。

首期记录单击、双击、右键、按住/释放、文本输入、按键/快捷键、滚动、拖动、应用启动、窗口激活和动作间等待。

存在可靠控件树时，录制器优先生成控件函数和 `ControlSelectorV2`。游戏、画布或远程画面没有可靠控件树时，录制器保存目标空间坐标、路径和时间关系，并可根据前后帧提出“等待图片/文字、图片点击或 OCR”的替换建议。建议不会自动创建资源或改写草稿。

录制器不推断条件、循环、异常处理、项目函数或扩展私有函数。作者在停止后的轻量审阅中删除噪声等待、合并连续文本、确认资源建议，然后把全部草稿作为一个 ProgramDocument 命令插入，可一次撤销。

- `[REQ-AUTH-REC-001]` 操作录制只有用户明确开始时才订阅事件，停止、取消、项目关闭和宿主退出均释放订阅。
- `[REQ-AUTH-REC-002]` 录制期间只写临时 `OperationRecordingSessionV1`，不得逐事件修改 ProgramDocument。
- `[REQ-AUTH-REC-003]` 控件树路径和目标空间路径生成现有官方函数调用，不新增宏源码或录制专用语句种类。
- `[REQ-AUTH-REC-004]` 无法可靠表达的事件标为需要处理，不伪造成功语句。
- `[REQ-AUTH-REC-005]` 确认插入使用一个原子命令；校验失败、并发 revision 冲突或取消时 ProgramDocument 不变，草稿可继续审阅。
- `[REQ-AUTH-REC-006]` 扩展函数不参与首期自动识别；作者可在生成骨架后通过统一快捷插入替换或补充。

### 2.3 统一触发器

`TriggerDefinitionV1` 是 IDE 项目级版本化控制面事实，只决定何时启动，不包含可执行脚本。首期只绑定已有项目函数；Player 继续使用自身签名运行方案和计划控制面，IDE 触发器不会静默进入发布包。

```text
TriggerDefinitionV1
├─ trigger_id / revision / enabled
├─ kind + kind_config
├─ entry_function_id
├─ target_id
├─ debounce_ms / cooldown_ms
├─ concurrency_policy
└─ permission_requirements[]
```

第一阶段支持 Windows 全局快捷键、应用启动/退出/获得焦点、文件或目录变化、系统启动或用户登录。第二阶段再评审热字符串、剪贴板、Webhook 和消息入口。

- `[REQ-AUTH-TRG-001]` 触发器只绑定稳定入口 ID，不复制 ProgramDocument。
- `[REQ-AUTH-TRG-002]` 禁用或项目未打开的 IDE 触发器零订阅；首期发布闭包明确排除 IDE 触发器，Player 只加载自己的签名运行方案和计划。
- `[REQ-AUTH-TRG-003]` 每个定义必须声明防抖、冷却和并发策略；事件风暴不得无限创建运行。
- `[REQ-AUTH-TRG-004]` 快捷键冲突、权限不足、目标缺失和入口失效原位显示恢复动作，不伪报已启用。
- `[REQ-AUTH-TRG-005]` 入口改名不影响绑定；删除入口必须先显示触发器引用并阻止或由用户确认修复。

### 2.4 浏览器 DOM 扩展

浏览器 DOM 首期以第一方签名功能扩展包交付，支持本机 Edge 与 Chrome。扩展贡献浏览器宿主、DOM 选择器类型、普通函数契约、元素捕获和发布模块；不修改 ProgramDocument Schema。

作者仍从函数库搜索并插入普通调用，在中央阅读语义摘要，在右侧使用共享 Control 配置，在 `@` 和 `.` 候选中使用返回值。浏览器连接与元素捕获可以有轻量管理表面，但不存在第二套脚本编辑器。

首期函数覆盖浏览器启动/连接/关闭、导航与页面等待、元素查找/等待/点击/输入/选择、文本/属性/表格读取、标签页、窗口、iframe 与下载。Cookie/会话属于高级参数。Firefox、Safari、远程浏览器、任意 JavaScript 注入、网络拦截和验证码绕过不在本期。

- `[REQ-AUTH-DOM-001]` DOM 函数使用与官方函数相同的契约、调用、摘要、参数、返回、日志和错误机制。
- `[REQ-AUTH-DOM-002]` `DomSelectorV1` 与桌面/Android 控件选择器是不同强类型，不允许互相隐式转换。
- `[REQ-AUTH-DOM-003]` 包未启用时零浏览器宿主、零后台连接、零运行期下载和零发布依赖。
- `[REQ-AUTH-DOM-004]` 页面、标签页或 iframe 目标不明确时停止，不在相似页面上猜测执行。
- `[REQ-AUTH-DOM-005]` 首期包必须从真实导入、信任、启用、调用、发布、禁用和卸载路径验收，不能由源码直连代替。
- `[REQ-AUTH-DOM-006]` 未声明公网能力的发布必须携带浏览器宿主所需离线依赖，运行期不得下载驱动。

## 3. 扩展包统一分发规则

官方、用户和项目扩展使用同一 `easycode-extension.json`、签名、密封产物与运行契约。来源只决定安装范围和治理：官方包由 IDE 发行到只读范围，用户包对本机用户可见，项目包只对当前项目可见并进入 `easycode.lock`。

- `[REQ-AUTH-PKG-001]` 新增领域扩展先作为普通签名包完成手动导入生命周期，再评审是否把同一产物提升为官方随附包。
- `[REQ-AUTH-PKG-002]` 自动验收必须从复制/导入包开始，不能把仓库源码路径当作已安装扩展。
- `[REQ-AUTH-PKG-003]` 项目创建向导若推荐扩展，必须显示名称、版本、体积、权限和目标支持并由用户勾选；不得静默导入。
- `[REQ-AUTH-PKG-004]` 导入版和官方随附版不得维护两份实现或两种 Manifest。
- `[REQ-AUTH-PKG-005]` 当前签名目录就是可验收的包载体；单文件安装格式需另立版本化规格。

## 4. 状态、权限与性能

所有会话覆盖 idle、preparing、active、stopping、review、committing、complete、failed 和 cancelled 中适用的状态。失败必须说明发生了什么、保留了什么以及下一步操作。

操作录制和控件捕获只在编辑状态启用；触发器和浏览器宿主按项目、运行及扩展生命周期启动。未启用能力空闲 CPU 应接近零，不持续截图、不轮询控件树、不监听全局输入。

权限在发生具体动作前按需申请。录制输入、全局快捷键、文件监视、浏览器控制与下载分别进入权限和发布闭包，不以安装一个扩展取得所有权限。

## 5. 完成门

- `[AC-AUTH-SEL-001]` 一次捕获生成多策略，主策略失效后唯一后备成功；歧义时无输入副作用。
- `[AC-AUTH-REC-001]` 控件树和游戏/画布两条录制路径均生成可运行的 ProgramDocument 骨架，确认前不修改文档，确认后可一次撤销。
- `[AC-AUTH-TRG-001]` 四类第一阶段触发器在禁用、冲突、事件风暴、入口删除和 Player 发布排除场景保持确定性。
- `[AC-AUTH-DOM-001]` 浏览器包从真实导入开始完成 Edge/Chrome、标签页、iframe、表格、下载、失败恢复和离线闭包。
- `[AC-AUTH-PKG-001]` 最小 Python 包与第二个真实业务包在用户/项目范围完成相同生命周期，证明平台未为浏览器特制。
- `[AC-AUTH-UI-001]` 上述所有界面只使用统一 UI 原语、工作区组合和 Control 子系统，没有页面私有基础控件样式。

自动验证、浏览器验证、Windows 原生宿主、Android 真机和真实人类可用性必须分别报告；任一层不能替代另一层。
