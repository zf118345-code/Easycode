# EasyCode 1.0 作者语言与高效编排规格

状态：`Implemented; automated validation passed, real-host acceptance pending`

最近修订：2026-09-12

## 1. 目标

EasyCode 继续使用强类型 `ProgramDocument` 作为项目函数唯一可编辑事实，但不要求作者为了结构安全反复手写样板流程。中文负责发现、摘要和语义提示；键盘意图输入、快捷组合和右侧 Control 都只生成同一份结构化程序，不形成第二套源码。

本规格解决四类真实问题：

1. 调用一个返回结果的函数后，为了判断“有结果”需要手工创建变量、绑定结果和条件。
2. “执行某个动作，直到某个状态成立”需要手工搭建循环、查询、跳出、动作和等待。
3. 项目函数已有参数与返回模型，但作者端没有完整契约编辑入口。
4. 坐标、颜色、画面区域与前后帧比较等常用计算存在发现困难或真实能力缺口。

## 2. 不变边界

- `ProgramDocument` 仍是唯一可编辑事实；不增加可保存的中文源码、英文源码或 Monaco 编辑入口。
- 普通函数调用与 I/O 仍是独立语句。输入、截图、等待、文件、消息或目标操作不能隐藏进值表达式。
- 正常无结果与权限、目标、驱动、资源或内部失败继续分离。便捷条件不能把结构化异常吞成 `false`。
- 所有便捷输入最终产生可撤销、可检查、可调试的 Program 命令；同一调用只执行一次。
- IDE、Windows Player、ADB 与 Android 本机继续执行同一 ECIR 语义。

## 3. 三层作者表面

### 3.1 语义投影

中央区域只展示流程骨架和理解流程所需的关键值。复杂参数留在右侧检查器。投影可以把一组由同一作者事务生成的普通结构显示得更紧凑，但不能隐藏运行顺序、失败边界或额外调用。

### 3.2 类型化检查器

右侧检查器保留全部真实参数、返回绑定、超时、间隔和失败语义。项目函数头部提供参数与返回类型编辑入口；调用该函数的检查器继续由同一契约自动生成参数 Control。

### 3.3 临时意图输入

现有行内插入器扩展为键盘优先的临时意图输入。作者可输入函数名，也可输入结构意图，例如：

- `查找 出战 并判断`
- `重复 20 次`
- `向左拖动 直到 出战出现`
- `调用 战斗-刷图 最大次数 8`

意图输入只在候选明确、参数类型兼容时预览将创建的结构。确认后由 Program Service 一次提交；取消、歧义、参数不足或 revision 冲突均零写入。意图文本不持久化，也不反向解析既有 ProgramDocument。

## 4. 条件简写

### 4.1 明确的类型化布尔适配

条件字段允许提交以下简写；保存时立即规范化为显式布尔值树：

| 输入值类型 | 条件含义 | 规范化语义 |
| --- | --- | --- |
| `bool` | 原值 | 直接引用 |
| `optional<T>` | 是否有结果 | `结果.有结果(value)` |
| 整数、小数、百分比 | 是否非零 | `value != 0` |
| 文本 | 是否非空 | `value != ""` |
| 列表、字典 | 是否包含元素 | 明确的非空纯操作 |

任意记录、图片资源、目标、文件、控件、坐标、区域、颜色和未知 JSON 没有通用真假语义，不能隐式提交。界面原位给出最短可选谓词，例如“有结果”“颜色接近”“区域有效”，而不是猜测。

JavaScript 的空对象 `{}` 实际为真，Python 的空字典为假；EasyCode 不复制任一宿主语言的偶然规则，而采用上表跨平台固定语义。

### 4.2 调用并判断

普通查询函数仍不能直接成为表达式。作者在条件位置选择 `图像.查找` 等函数时，编辑器提交一个原子结构事务：

1. 插入一次函数调用；
2. 建立类型正确的局部结果绑定；
3. 紧邻插入 `如果`；
4. `bool` 结果直接判断，`optional<T>` 结果使用“有结果”；
5. 自动选中新条件的“那么”插入位置。

中央可以摘要为“如果找到图像 [出战]”，但展开或检查器必须能看到调用、结果和失败语义。函数失败仍停止或进入作者明确的异常处理，不能进入“否则”。

## 5. 执行直到

“执行直到”是结构化编排模板，不增加第二套 Runtime 语义。首版由一次 Program Service 事务生成现有结构：有界循环、每轮新查询、条件命中时跳出、动作语句、可选间隔和到期处理。

默认采用“先观察，再决定是否动作，再重新观察”的顺序：目标状态已经成立时零动作。作者必须设置最大次数或超时；取消和暂停沿用普通循环检查点。动作可以是一个或多个普通语句，因此支持点击、拖动、滑动、项目函数或扩展函数。查询只允许 `bool` 或 `optional<T>` 返回，且每轮只执行一次。

高频且参数稳定的组合仍可进入官方标准函数，例如“点击位置直到图片出现”。它们必须有规范 ProgramDocument 组合并通过融合等价性测试。任意动作使用通用结构模板，不为“拖动直到、滚动直到、输入直到”逐个复制官方函数。

## 6. 项目函数契约

项目函数必须能在作者端编辑：

- 参数名称、类型、是否必填及可选默认值；
- 参数顺序；
- 单一返回类型；
- 删除或改型前的函数体引用与跨函数调用影响。

参数使用稳定 `parameter_id + symbol_id`。重命名和重排不破坏引用。新增必填参数使既有调用进入可定位的“缺少参数”恢复状态；删除或改型时，只要函数体或调用方仍在消费该稳定身份就阻止提交，并返回需先解除的引用数，不静默删除调用实参。默认值和返回类型也在提交前执行类型验证。整个修改可一次撤销，不允许前端直接改 JSON。

返回类型为 `unit/null` 时不允许带值返回；其他类型必须由所有正常结束路径返回兼容值。调用方可以绑定返回值并继续使用。函数参数可直接作为 Player 字段绑定来源，不要求复制为项目变量。

## 7. 高频值与视觉能力

### 7.1 已有能力优先提升发现

- `坐标.偏移`：根据基准坐标与偏移坐标得到新坐标。
- `坐标.区域中心 / 按中心生成区域 / 缩放 / 缩放区域`。
- `颜色.颜色接近`：比较两个强类型 RGBA 颜色与容差。
- `画面.保存`：把可选画面和裁剪区域保存到文件。

这些能力进入 `坐标.`、`颜色.`、`画面.`候选、自然语言别名和意图输入，不再以新增同义函数解决发现问题。

### 7.2 真实缺口

已增加运行期短生命周期的 `image_sample`：

- `画面.截取区域`：从指定 `FrameReference` 裁剪为只在当前运行有效的图片样本；
- `图像.比较`：比较两个图片样本，返回包含相似度、尺寸关系和差异区域的命名记录；
- 同一帧不同区域、操作前后两帧都复用上述契约。

图片样本不能进入项目变量、Player 方案、JSON 或持久文件；需要长期保存时显式使用 `画面.保存`。尺寸不一致时必须选择明确策略（严格拒绝、缩放后比较或取交集），不能静默猜测。

## 8. 需求与验收

- `[REQ-AUTH-LANG-001]` 中文摘要、检查器和意图输入只编辑同一 ProgramDocument，不存在第二份可保存源码。
- `[REQ-AUTH-LANG-002]` 条件简写按类型规范化为显式布尔树，结构化异常不转换为假值。
- `[REQ-AUTH-LANG-003]` “调用并判断”一次事务创建单次调用、结果绑定和相邻条件，失败零写入。
- `[REQ-AUTH-LANG-004]` “执行直到”一次事务创建有界、可取消、先观察的普通结构，并支持任意一个或多个动作语句。
- `[REQ-AUTH-FSIG-001]` 作者可以完整编辑项目函数参数与返回类型，稳定身份和跨函数影响由 Program Service 事务维护。
- `[REQ-AUTH-DISC-001]` 已有几何、颜色和结果操作在点号候选、搜索别名和意图输入中可发现，不新增同义运行能力。
- `[REQ-AUTH-IMG-001]` 运行期区域截取与图片比较使用短生命周期强类型值，Windows/ADB/Android 本机语义一致。

## 9. 分阶段实施

1. 阶段 0：稳定版本快照、`main` 推送和独立 `v1.0.0` 工作树。
2. 阶段 1：项目函数参数/返回契约编辑闭环。
3. 阶段 2：条件类型化简写与“调用并判断”原子命令。
4. 阶段 3：键盘意图输入和“执行直到”结构模板。
5. 阶段 4：已有能力发现性收束、运行期区域图片与图像比较。
6. 阶段 5：大型项目、IDE/Player、Windows/ADB/Android 分级验收与性能报告。

每阶段只在对应自动测试通过后进入下一阶段；真实宿主未验证必须明确标记，不能由替身结果代替。
