# vNext 变量模型

状态：`Approved`（作用域、生命周期、稳定引用、开发默认值、临时运行覆盖与 Player 运行方案语义已冻结）

## 1. 目标与边界

变量模型服务于函数内计算、跨函数共享和 Player 运行方案配置。前台只向用户呈现“局部变量”和“项目变量”两个概念，不再为配置、本次运行、持久状态、系统环境或运行上下文建立变量模式或并列分类。

函数参数与返回值属于函数契约。时间、日期、目标信息、项目目录和运行错误分别通过内置函数、词法局部值或异常对象进入脚本。需要读取或生成长期文件时使用显式文件函数，不属于项目变量生命周期。

## 2. 场景映射

| 场景 | 示例 | 使用对象 |
| --- | --- | --- |
| 函数临时计算 | 当前副本、识图结果、循环项 | 局部变量 |
| 可复用函数输入输出 | 副本名称、执行次数、成功结果 | 函数参数/返回值 |
| 跨项目函数共享 | 启用副本、识图阈值、本轮失败次数、待执行列表 | 项目变量 |
| Player 保存的运行选项 | 副本多选、体力下限、重试次数 | 运行方案对项目变量初始值的覆盖 |
| 本机长期数据或文件交换 | 外部配置、导出结果、长期采集文件 | 显式文件函数 |
| 外部环境查询 | 当前时间、工作区尺寸、项目目录 | 内置函数 |

## 3. 局部变量

- 局部变量由函数参数、赋值、循环项、异常捕获或函数返回结果产生。
- 作用域为当前函数调用；函数返回后释放。
- 局部变量直接参与类型推导、补全、跳转、引用、重命名、断点和快照。
- 局部变量不进入项目变量注册表，不能直接成为 Player 长期绑定。
- 当一个值需要跨多个项目函数共享或由 Player 配置时，开发者将其提升为项目变量或入口参数。

## 4. 项目变量

每个项目变量至少具有稳定 `variable_id`、显示名、强类型、开发者默认值、约束和说明。重命名只修改显示名；ProgramDocument 中的 `variable_ref` 值和 Player 绑定继续指向同一 `variable_id`。

项目变量定义使用独立的版本化注册表 `program/variables.json`，其网络与磁盘契约至少包含：

- `schema_version`：变量注册表版本；
- `variable_id`：项目内唯一且创建后不变的稳定 ID；
- `display_name`：可修改的用户显示名，项目内不区分大小写地唯一；
- `value_type`：与 ProgramDocument 共用的强类型 ID；
- `default_value`：具有稳定 `value_id` 的静态 ProgramDocument 值节点；
- `constraints`：数值、长度、项数、唯一性、候选值或文本格式等可重建校验规则；
- `description`：面向作者的说明。

默认值不允许引用局部符号、其他项目变量、运行时结果、帧、窗口、进程、收件消息或文件授权引用。这些值必须在每次运行中显式取得，不能被伪装成可跨运行的开发默认值。

每次任务启动时，运行时按以下流程创建项目变量副本：

1. 读取项目中保存的开发者默认值。
2. 对 Player Schema 已绑定的变量应用当前运行方案覆盖值。
3. 为本次执行会话创建独立、可读写的变量副本。
4. 所有项目函数在本次执行中共享该副本。
5. 任务成功、失败、取消或进程结束时释放副本，不把运行期修改写回项目默认值或 Player 运行方案。

初始值优先级固定为：开发者默认值 < 当前 Player 运行方案覆盖 < 本次 IDE 调试的临时覆盖。IDE 临时覆盖只属于当次新建的运行 ID，不保存到项目或运行方案；未明确提供时不产生隐式覆盖。三种来源都必须在运行前通过同一类型和约束校验。

不同执行会话和多开实例不得共享项目变量副本。项目变量不提供“配置”“本次运行”或“持久”模式；配置只是初始值来源，读取或生成长期文件必须通过显式文件函数表达。

## 5. Player

- 默认不向 Player 暴露任何项目变量。
- 开发者在 Player 设计器中按稳定 `variable_id` 选择变量，再配置标签、帮助、Control、候选值、校验和布局。
- Player 保存的是运行方案覆盖值；它不修改开发者默认值、ProgramDocument 或发布包。
- Player 启动任务时将覆盖值写入新的运行副本；脚本对副本的修改不回写运行方案。
- 列表和字典使用类型化 Control；普通用户不应被迫编辑 JSON。副本列表等有限集合优先使用多选控件。
- 项目数据可以使用记录列表和强类型字典；固定字段由项目/函数 Schema 声明，动态外部 JSON 先验证转换或使用专用 JSON 操作。集合在任务会话中按值更新，Player 运行方案继续只提供初始值。

## 6. 文件与协作边界

- 与本机文件系统或外部软件交换数据时，脚本使用 `文件.*`显式读取、写入、追加、替换或删除真实文件；变量工作区不把文件内容伪装成项目变量。
- 同机或局域网内多实例的可靠数据传递使用 `消息.*`。开发者可以通过文件自定义同机交换协议，但平台不保证文件轮询具有投递、确认或离线补发语义。
- 同一设备上多个 EasyCode 项目修改同一文件时，文件服务自动使用路径级写锁和原子写入；普通脚本不需要`租约.*`。
- 外部目标当前是否完成任务必须由脚本重新观察。历史日志、运行报告和存储值不得自动成为跳过外部任务的依据。
- 文件和消息的权限、事务、故障恢复及首版范围在各自功能规格中冻结，不在变量规范中猜测。

## 7. 环境值

- `时间.现在()`、`时间.今天()`等函数返回调用时的时间值。
- 目标尺寸、设备、项目目录等通过对应命名空间函数获取，并声明平台、权限和错误。
- 循环索引是局部变量；最近错误由捕获的异常对象提供；当前指令和执行 ID 属于调试元数据。
- Harness 可以替换时间、目标和文件系统来源，使测试结果可重复。

## 8. 交互要求

- 脚本工作区提供项目变量入口，不新增活动栏一级入口。
- 项目变量使用一份可搜索列表，不展示存储模式标签或系统/上下文分类。
- 新建与编辑使用类型生成的 Control，支持约束、候选值和结构化列表/字典编辑。
- 重命名、删除和类型变化必须计算 ProgramDocument、Player Schema 与扩展数据中的稳定引用影响，并以事务提交。
- “提供给 Player”属于 Player Schema，不是变量列表中的常驻开关。
- 调试器可以同时显示局部变量与项目变量的当前值、上个暂停点值和变更状态。

## 9. 需求与验收基线

- `REQ-VAR-001`：用户只需从界面理解局部变量和项目变量，系统不得重新展示系统变量、运行上下文或存储模式分类。
- `REQ-VAR-002`：每个执行会话从项目默认值和当前运行方案覆盖值创建独立项目变量副本。
- `REQ-VAR-003`：所有项目函数共享并可修改当前副本；任务结束后释放副本，运行期修改不得写回项目或运行方案。
- `REQ-VAR-004`：项目变量可由 Player Schema 显式绑定，默认不暴露；绑定和重命名使用稳定 `variable_id`。
- `REQ-VAR-005`：项目变量不得跨会话泄漏；需要长期文件时只能通过显式文件函数读取或生成。
- `REQ-VAR-006`：参数和值编辑器使用同一可搜索的结构化引用选择器呈现局部变量和项目变量，按当前期望类型过滤并显示来源、名称与类型。选择只提交稳定 `symbol_id` 或 `variable_id`，不要求复制、粘贴或解析 `$var{}` 等文本记号；大量同名值仍可通过来源、类型和搜索区分。
- `REQ-VAR-007`：系统环境值通过可测试的内置函数、词法局部值或异常对象提供。

验收至少覆盖：局部作用域、跨函数共享、每次运行重新初始化、Player 覆盖优先级、运行期修改不回写、并发会话隔离、稳定重命名、删除引用、非法 Player 绑定和结构化列表控件。

## 10. 已冻结实施边界

- 固定值、局部符号引用与项目变量引用仍使用明确的 ProgramDocument 值节点；检查器通过统一结构化表达式输入器创建它们。键入名称只用于搜索候选，必须经唯一候选确认后转换为稳定词元，不能把未确认文字或 `$var{}` 字符串当作引用事实。
- 项目变量默认值及 Player/IDE 覆盖共用同一 ValueNode、类型注册表、约束和 Control 契约，不建立第二套表单类型。
- 变量创建、修改、删除都使用内容 revision 做乐观并发控制；冲突不静默覆盖。
- 类型变化或删除前扫描 ProgramDocument、Player Schema 和扩展数据的稳定引用；仍有引用时阻止操作并返回可定位的影响列表。
- `文件.*`与`消息.*`拥有独立首版规格，不再作为变量模型的开放问题。
