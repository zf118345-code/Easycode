# 跨平台控件规格

- 状态：Approved
- 范围：Windows UIA、Windows 宿主连接的 ADB UIAutomator、Android 本机 Accessibility
- 关联决定：ADR-068、ADR-069

## 1. 产品语义

前台、函数库、检查器、Player 与日志统一使用“控件”。UIA、UIAutomator 和 Accessibility 仅是宿主适配器名称，不形成三套函数、三种参数或三种用户概念。

官方函数保持四个原子能力：`控件.查找`、`控件.点击`、`控件.读取文本`、`控件.输入文本`。捕获保存可跨运行重新定位的 `control_selector`；查找成功返回只在当前运行和当前目标内有效的 `control_ref`。运行时引用不得进入 ProgramDocument、项目变量默认值或 Player 方案。

## 2. 统一选择器

选择器 Schema 版本为 1，至少包含内部 provider、来源目标、角色/类名和一个稳定身份字段；可选字段包括名称、自动化 ID/资源 ID、文本、内容描述、包名、同类序号、祖先路径和捕获时区域。Windows 优先 automation id/祖先路径，ADB 与 Android 本机优先 resource id/包名/祖先路径；文本和区域只作为受约束辅助，不得把一次捕获坐标伪装成稳定控件身份。

前台只投影“控件名称或文字 · 控件类型 · 来源目标”等可读摘要，不显示 provider、原始 selector、XML、JSON 或 Accessibility 节点对象。三个适配器消费同一值类型和同一四个函数契约。

## 3. 平台适配

| 当前目标 | 内部适配 | 查找 | 点击 | 读取文本 | 输入文本 |
| --- | --- | --- | --- | --- | --- |
| Windows | UI Automation | 是 | Invoke/Selection，必要时按项目策略物理回退 | 是 | ValuePattern，必要时按项目策略物理回退 |
| ADB | UIAutomator XML + 目标输入通道 | 是 | 控件中心触控 | 是 | 聚焦控件后走目标原生输入 |
| Android 本机 | AccessibilityService | 是 | ACTION_CLICK/可点击祖先 | 是 | ACTION_SET_TEXT |

ADB 每次语义查询都从显式绑定的设备序列号取得一份有界 UIAutomator 快照；不能从其他在线设备猜测。Android 本机只能读取当前手机的活动窗口。Windows、ADB 和 Android 本机均在操作前重新定位，不持久保存原生节点句柄。

## 4. 捕获与 Player

- IDE 与 Player 共用 `capture-control` 动作、Control 原子组件、稳定目的地和原子回填语义。
- 三个平台统一使用“目标干净帧 → 点击最深语义控件 → 按父级逐层上移 → 确认”的语义选择器。点击新位置总是重建一条“最深控件到目标根”的候选链；只提供父级动作，不提供容易造成多义性的子级列表。
- 冻结层使用蓝色细框、选区外降噪和“类型 · 名称 · 当前层/总层数”短标签。Windows 桌面与窗口冻结帧按真实物理区域一比一覆盖，进入捕获时不得产生可见缩放或位移；没有物理桌面区域的 ADB/Android 画面才使用最大化、保持比例的居中投影。控件工具条固定为清空、父级、取消、确认；不可用操作保持原位并只降低图标权重，不使用大面积失焦或彩色禁用底。清空后可重新点击，确认只提交当前层选择器。
- Windows 冻结层必须在画面和选择标记之上提供不拦截输入的高对比指针层；EasyCode 橙色细线、深色外描边和中心强调点确保亮/暗画面都可见。不得与系统反色十字光标叠加，也不得只依赖可能被透明顶层窗口、子级命中或系统主题隐藏的硬件光标。移动只更新缓存合成层并按设备像素对齐，不反复触发布局；指针层不得写入资源截图或改变提交坐标。
- 区域和图片框选使用细边框与四角短引导线，不用遮住内容的八个圆形控制点；只有允许多选且实际具备顺序语义时显示序号，单选不得显示“1”。工作区连接后在后台预热捕获宿主、当前目标驱动和首帧；点击捕获不重复等待未变化的会话注册。预热与立即点击发生竞争时只允许一次目标驱动初始化。
- Windows 显式窗口目标从该窗口的 UIA 根向下命中点击位置，因此被 IDE、浏览器或其他窗口遮挡时不会跨到外部控件；桌面目标按冻结帧坐标从顶层顺序排除 EasyCode 捕获宿主与输入穿透系统窗，再绑定遮罩下的实际窗口，不通过隐藏/重显遮罩探测。整窗截图忽略 DWM 不可见阴影边框。ADB 使用当前目标干净帧取点，并在截图期间并行取得同一设备的有界 UIAutomator 快照；Android 本机使用悬浮准备、干净原帧和冻结取点，并在 EasyCode 浮层出现前取得 Accessibility 快照。
- IDE 检查器按当前语句最近的目标作用域显示“当前目标 + 适配器”；ADB 作用域中的控件字段不得启动 Windows UIA 捕获。逻辑目标冻结帧使用与 IDE 窗口/显示器位置无关的居中展示，IDE 跨屏不影响捕获。
- 开发者必须逐字段、逐平台开放 Player 控件捕获，默认关闭。当前平台缺少真实适配或权限时不显示假按钮；权限可恢复时原位说明并引导系统授权。
- 确认前后均校验目标、字段、方案 revision 与目标空间。取消、拒绝、目标变化、无节点和提交失败全部保留旧值。

## 5. 结果与失败语义

- 合法选择器未找到控件：`控件.查找` 正常返回空，不抛异常。
- 选择器结构无效、跨目标引用、权限未授权、驱动不可用和操作失败：结构化异常。
- 当前页面只有 SurfaceView、Canvas、游戏引擎或其他自绘内容，语义树不存在或只有无意义容器：`control.semantic_tree_unavailable`。提示固定说明“当前页面不提供可识别控件，请使用图像、OCR 或坐标”。不得返回屏幕根节点，不得自动降级成坐标点击。
- 已查找的控件随后消失：`control.reference_stale`；运行日志记录 provider、目标和重新定位结果，但不记录输入文本等敏感值。

## 6. 性能与生命周期

- IDE 与 Player 的交互捕获驱动按“宿主所有者 + 项目规范路径 + 目标类型 + 目标身份 + 完整目标签名”复用，所有者之间隔离；每个所有者最多保留 2 个驱动，空闲 5 分钟释放，目标配置变化、捕获失败、工作区关闭或进程退出立即废弃。Runtime 正式执行仍使用自己的运行级驱动，不借用交互捕获池。
- Windows/ADB 捕获先保留原始 RGB 帧，原生窗口通过具名共享内存读取 BGRA；只有刷新、资源保存或兼容回退需要时才编码 PNG。共享内存不可用时自动回退低压缩 PNG 文件，取消、确认、宿主退出与快照过期均清理映射和临时文件。
- 性能报告至少分开记录驱动取得、帧取得、颜色转换、PNG 编码、共享内存准备、原生显示、语义等待和控件解析，不能只记录一个无法定位问题的总耗时。性能字段只进入本机诊断和测试证据，不显示在普通作者界面，也不自动上传。
- 语义树快照有 5 秒单次上限、10000 节点和 64 层硬上限；超限返回明确错误，不阻塞主 UI。
- 快照只在一次捕获或查找中使用；原生 AccessibilityNodeInfo/UIA 对象不得跨线程或跨运行持久化。
- 同一语句的一次 `控件.查找` 只生成一个运行时引用。后续操作重新定位并验证目标，停止运行时清空全部引用。
- ADB 命令使用参数数组、固定远端临时文件和显式序列号，结束后尽力清理；不拼接 shell 文本。

## 7. 验收标准

- `[AC-CTL-001]` 三平台函数目录、检查器、Player 与日志只显示“控件”，内部 provider 不泄露为平权功能。
- `[AC-CTL-002]` Windows UIA、ADB UIAutomator 与 Android Accessibility 均完成捕获选择器、查找、点击、读取和输入的真实宿主闭环。
- `[AC-CTL-003]` ProgramDocument/Player 保存 selector，运行时只保存 session-local `control_ref`；跨目标、重启和过期引用被拒绝。
- `[AC-CTL-004]` SurfaceView/自绘页面返回 `control.semantic_tree_unavailable`，旧字段不变，并提示使用图像、OCR 或坐标；不存在静默坐标降级。
- `[AC-CTL-005]` Android 控件捕获复用悬浮干净帧交互，EasyCode 浮层不进入截图，确认后回到原 Control。
- `[AC-CTL-006]` 自动测试分别覆盖选择器规范化、三适配器重定位、失败分类、发布权限闭包和原子回填；报告区分自动通过、真实 Windows、真实模拟器、真实 Android 手机和环境阻塞。
- `[AC-CTL-007]` Windows 与 ADB 真实捕获均默认框选点击位置的最深控件，可连续切换到每一级父控件，清空/取消保留旧值；显式 Windows 目标被其他窗口遮挡时不得捕获遮挡窗口控件。
- `[AC-CTL-008]` Android 本机冻结画面使用 Accessibility 快照框选最深控件，父级按钮只沿唯一祖先链上移；确认直接保存当前层选择器而不是点击坐标，全屏父控件的标签和确认操作仍保持在可视安全区。
- `[AC-CTL-009]` Windows 与 ADB 连续两次捕获复用同一交互驱动；预热与立即捕获并发时只创建一次驱动。目标配置变化、驱动异常、会话关闭和空闲过期后重建，IDE、Player 与 Runtime 不共享可变驱动实例。
- `[AC-CTL-010]` 原生捕获外观、选择、取消和确认流程不因传输优化变化；正常 Windows 路径不编码 PNG、不把 base64 帧送入前端，控件探测不隐藏遮罩且不会选中 EasyCode 遮罩或输入穿透系统窗。共享内存失败时 PNG 回退仍可完成同一流程。
- `[AC-CTL-011]` Windows 原生捕获在浅色、深色和混合冻结帧上都能看到位于最上层的稳定品牌指针；连续移动不发生明暗反色闪烁，指针不拦截框选/取点、不进入保存资源，繁忙时切换等待状态后可恢复。

## 8. 当前实现与证据

2026-09-02 已完成 Schema、函数契约、编译/平台能力、Windows UIA、ADB UIAutomator、Android Accessibility、IDE/Player Control、发布权限闭包、运行时引用、原子回填和结构化失败的垂直实现。证据记录见 `output/harness/cross-platform-controls-20260902/report.md`。

当前真实宿主结果明确分层：Windows UIA 通过，并在 DDT WinForms 窗口验证“按钮 → 分组 → 窗口”父链；ADB UIAutomator 通过，并在 `emulator-5554` 的系统设置验证“搜索文字 → 搜索栏容器 → 页面容器”父链；微信自绘窗口验证只返回其 Render Pane/窗口而不会越界捕获遮挡窗口。DDT 已改成自包含流程：进入 ADB 作用域后主动启动 `com.android.settings/.Settings`，再执行控件查找；后端重启后的真实运行 `execution_5372140e7a7943c6a64fa36d37749713` 完成 Windows 测试窗口 → 微信 → ADB → 微信四段切换并全部命中。Android 模拟器本机 Accessibility 完成了悬浮准备、干净冻结帧、点击最深控件、连续上移到全屏父级和原子回填；debug-only SurfaceView 页仍按规范提示无语义树。Android 13 物理手机也已使用同一 Accessibility 适配器完成“最深控件 → 唯一父级链 → 全屏父级 → 原子回填”。实现不包含小米或其他厂商专属分支；仍需更多 API/设备覆盖后才能将 `[AC-CTL-002]` 标记为 Android 通用矩阵全部放行。

2026-09-06 完成交互捕获性能切片：目标驱动有界复用、连接后首帧预热、ADB 语义并行预取、Windows UIA 批量属性缓存、桌面遮罩下窗口绑定、原始帧共享内存传输与 PNG 回退均已闭环。自动和当前 Windows/ADB 宿主证据见 `output/harness/capture-performance-20260906/report.md`；Android 本机捕获实现未因本切片改变，仍沿用上述 Android 真机证据与延期矩阵。
