# 操作目标与平台

状态：`Approved`（首版包含 Windows/ADB 与 Android 本机宿主、`target_scope`、串行切换、显式 ADB 序列号绑定和并发边界已冻结；真实宿主与权限仍按 Harness 分阶段验证）

## 1. 概念与边界

- **执行宿主**：承载 ECIR、运行时和驱动的 Player。Windows Player 与 Android APK Player 都属于首个正式版本宿主；允许分阶段开发，但两者未完成前首个正式版本不能放行。
- **操作目标**：视觉、输入和捕获函数实际作用的 Windows 桌面/窗口、Android ADB 设备或 Android 本机。
- **当前目标**：一个执行上下文任意时刻唯一生效的操作目标。

项目声明一个默认目标和零到多个附加目标。Windows Player 可以登记 Windows 与 ADB 目标并在同一 ProgramDocument 运行中顺序切换；Android 本机 Player 只操作当前手机。没有操作目标时，文件、计算、日志和消息等纯逻辑函数仍可运行，视觉与输入函数必须在检查或执行前明确失败。

目标注册表使用判别式强类型定义：`windows / android_adb / android_local` 各自只接受本类型字段，缺失字段、未知字段、重复 ID、重复名称和悬空默认目标均拒绝保存。注册表在 `project.json` 内保持项目事实，但拥有独立于项目其他元数据的规范化内容 revision；GET/PUT、运行解析、捕获和发布始终携带 `workspace_id + generation`，PUT 还必须携带 `expected_revision`，冲突不得自动重试或静默覆盖。

## 2. 目标作用域

ProgramDocument 使用固定 `kind: "target_scope"` 表示目标作用域。该结构至少包含稳定 `statement_id`、类型为 `target_ref` 的目标值和有序子语句列表；界面只投影其含义，不为每种目标新增语句类型。

面向用户的名称统一为“切换目标并执行”，避免要求用户理解“作用域”术语。语句检查器、参数动作与捕获会话必须按当前语句最近的 `target_scope` 祖先解析有效目标，而不是始终使用项目默认目标；右侧明确显示目标名称与真实适配器（Windows UIA、ADB UIAutomator 或 Android Accessibility）。

纵向投影可以显示为：

```text
1  等待 Android 设备「雷电模拟器」· 超时 60 秒  → 模拟器
2  在目标「模拟器」中
3      等待图像「游戏主页面标识」出现
4      点击图像「进入游戏」
```

这段文字只负责展示。目标引用、层级和函数调用分别由 ProgramDocument 的类型化值、`target_scope` 和 `call` 语句保存；示例中的函数名称也不在目标规范中冻结其原子/标准实现。

运行时进入作用域时必须：

1. 解析稳定`target_id`并确认目标在线。
2. 检查 `target_scope` 子语句需要的截图、输入、控件和权限能力。
3. 停止消费上一目标的帧，废弃隐式截图、OCR 和控件缓存。
4. 激活新目标的驱动会话，并把它压入当前目标栈。
5. 在退出、返回、异常或取消时弹出目标栈，恢复上一逻辑目标。

恢复逻辑目标不等于重新激活旧前台窗口。物理输入回退导致的前台窗口策略继续遵守“不恢复旧前台窗口、始终恢复鼠标位置”的规则。

## 3. Windows目标

Windows 窗口优先使用 WGC/DXGI 截图和 UIA/窗口消息输入，按项目策略允许物理输入回退。回退时日志必须记录后台路径失败原因和真实物理操作路径。

- 客户区、完整窗口和自定义区域必须绑定唯一窗口；截图、坐标与输入都以该工作区域为基准。
- 后台操作失败时只有项目开关允许才回退物理输入。
- 全屏幕目标没有唯一窗口身份和可靠定向后台通道，因此固定开启物理点击、键盘、滚动和拖拽。

Windows 宿主控制函数与当前操作目标分开建模：启动应用和等待该进程退出由 Windows Player 宿主执行，不隐式改变当前目标；查找/等待、激活、关闭和读取窗口状态由 Windows 驱动执行并返回有类型窗口引用或状态记录。直接启动只接收经过类型化校验的应用引用和参数，不接收 Shell 命令文本，也不能把 PowerShell、命令解释器或脚本宿主当作官方通用系统命令入口。

进入 Windows 目标作用域后，`窗口.获取当前目标窗口`复用已经解析并复核的目标窗口身份，供还原、激活和窗口管理使用；不得为了取得 `window_ref` 再按标题、PID 或枚举序号寻找同名窗口。`窗口.调整大小`接收客户区尺寸，`窗口.确保完整可见`在不改变尺寸和 Z 序的前提下把窗口外框夹入最近显示器工作区，无法完整容纳时明确失败。

启动模拟器的规范组合是“Windows 宿主启动应用 → 目标服务等待已配置 ADB 设备上线 → `target_scope` 进入 ADB 目标”。不得为了这一组合增加与普通应用启动、目标等待或目标作用域同义的模拟器专用运行机制。

### 3.1 同名窗口捕获绑定

窗口标题规则适合单窗口应用，但不能区分标题相同的多个窗口。Windows 窗口目标因此可以保存一个版本化的捕获绑定。作者在目标字段旁通过与取点、框选一致的图标动作打开全桌面冻结帧，点击目标窗口后只更新当前表单草稿；明确保存后才进入目标注册表。

捕获绑定包含 EasyCode 生成的稳定 `binding_id`、捕获时标题、窗口类名、可读取的可执行文件名，以及仅用于当前进程生命周期快速定位的 HWND、PID 和进程创建时间。HWND/PID 不是跨重启永久身份：运行时必须先验证缓存句柄的全部身份；失效后只允许用标题、窗口类名和可执行文件名等稳定特征重新解析。稳定特征仍命中多个窗口时返回“需要重新捕获”，不得按枚举序号、左右位置或任意首项继续运行。

手工修改窗口标题或标题匹配方式会清除旧捕获绑定，防止界面显示一个规则、运行时使用另一个规则。即时测试重新执行与 Runtime 相同的解析器；成功时短暂高亮实际窗口，失败时保留原草稿并说明“未出现 / 已最小化 / 绑定失效 / 仍有多个候选”。原始 HWND、PID 只进入按需诊断，不作为用户必须理解的主文案。

- `[REQ-TGT-WIN-018]`：两个标题完全相同的可见顶层窗口可以分别捕获为两个目标；当前窗口生命周期内必须按经身份验证的 HWND 精确解析，交换左右位置不得串号。
- `[REQ-TGT-WIN-019]`：句柄已失效或被复用时必须拒绝旧实例；稳定特征仅命中一个窗口时允许恢复，命中多个时要求重新捕获，不使用窗口序号或位置猜测。
- `[REQ-TGT-WIN-020]`：捕获、取消、失败和测试只修改或读取当前草稿；未经保存不得改变项目目标，取消或失败保持此前有效绑定。
- `[REQ-TGT-WIN-021]`：IDE 状态探测、视觉/输入目标驱动和发布后的 Windows Runtime 使用同一个窗口解析器与失败语义。
- `[REQ-TGT-WIN-022]`：窗口捕获复用原生冻结捕获宿主和共享图标按钮；运行中、暂停、已有捕获会话、非 Windows 宿主或点击 EasyCode 自身时明确拒绝。
- `[REQ-TGT-WIN-023]`：作者可把同一窗口捕获契约发布为 Player 目标设置；终端确认后只覆盖当前实例方案中的窗口绑定。运行、环境检查和 Player 字段捕获都使用该有效绑定，歧义时停止并提供重新捕获入口。

## 4. Android ADB目标

ADB 目标面向模拟器和经 ADB 连接的设备。截图与输入走 Android 驱动，不占用 PC 物理鼠标。首版持久化经过开发者明确确认的非空 ADB `device_serial`。IDE 提供按需“扫描设备”，把 `adb devices -l` 的真实可用、离线和待授权设备显示为候选；作者点击可用候选只会填入当前草稿，仍需明确保存。ADB 缺失、扫描失败、超时、无设备、离线和待授权均显示为正常可恢复状态，不伪造设备，也不把扫描当在线测试。Runtime、Capture 和 Player 不得在序列号缺失、离线或改变时自动选择“唯一在线设备”，也不依赖厂商模拟器特例。原序列号离线时目标进入“需要重新绑定”状态；开发者可以为同一稳定 `target_id` 明确更新序列号，引用与 Player 绑定不因此换 ID。

典型单实例流程为：Windows 目标启动模拟器，运行时等待对应 ADB 设备上线，然后进入该 ADB 目标作用域继续执行游戏脚本。该流程不需要额外 Player 实例或消息接管。

## 5. Android本机目标

Android APK 使用 MediaProjection 截图与 AccessibilityService 手势，需要用户授权、前台服务与显式权限状态。Android 本机宿主只登记当前手机目标，不能切换到 Windows 或外部 ADB 目标。Windows IDE 通过 USB/ADB 部署和调试本机测试 APK；仅由 Windows Runtime 调用 `adb screencap/input` 操作设备仍属于 ADB 目标，不算 Android 本机宿主证据。签名 APK 必须在断开数据线并关闭 IDE、后端后独立运行。真实宿主、权限、捕获、输入、调试与打包闭环完成前不得展示为已支持；iOS 与 macOS 不在目标矩阵内。

## 6. 坐标与资源

- 坐标、区域、控件句柄、路径和捕获结果携带来源`target_id`与目标空间版本。
- 一个目标产生的空间值传给另一个目标时，类型检查或运行时必须拒绝并指出来源与当前目标；不得自动按分辨率猜测换算。
- 图片资源可以在不同目标复用；图片不携带默认运行区域，实际识别区域属于函数调用并在当前目标空间解释。
- Capture Session 必须显式绑定目标；目标切换时未完成捕获会话必须取消或在切换前阻止切换。
- 普通视觉调用在开始后从当前目标取得新帧；仅当 ProgramDocument 显式传入帧引用时才允许复用。帧引用不可变并携带来源 `target_id`、目标空间版本和采集序号/时间，所有派生空间结果继承该来源。目标切换会废弃隐式帧缓存，但不会篡改仍被局部符号引用的帧内容；该帧产生的空间结果仍不能用于其他目标或已变化的目标空间。
- Recorder 旁路订阅当前目标时，目标切换、方向/尺寸/DPI 或空间版本变化必须关闭当前录制片段并建立带新来源的新片段；时间线可以连续浏览，但不同片段的坐标、区域和控件结果不能静默互用。录制故障只结束 Recorder，不改变目标作用域或 Runtime 任务。

## 7. 串行与并发

一个运行实例只执行一个当前目标，不提供 Windows 与 ADB 的自由线程并发。需要同时操作多个窗口或模拟器时，用户创建多个 Player 实例，每个实例分别绑定自己的目标，并按需使用`消息.*`传递结构化数据。

多开管理器可以让一个管理实例负责启动模拟器，让多个工作实例分别接管 ADB 设备；这属于多目标并行方案。只启动并继续操作一个模拟器时，使用单实例顺序切换。

## 8. 失败语义

- 目标不存在、离线、重名或绑定不唯一时，切换失败且不改变当前目标。
- 切换后首帧获取失败时，作用域不得执行视觉或输入语句；运行时产生带稳定分类的结构化异常，由现有异常区域处理，未捕获时终止当前运行。只有该失败被契约标记为瞬时、外层异常区域显式开启重试且仍有次数时，才从区域主体开头重新执行；不得由目标驱动自行隐藏重试。
- ADB 中途断开时停止消费旧帧并标记目标离线，不得回退为对模拟器窗口进行坐标点击。
- 已绑定 ADB 序列号离线或失效时必须报告需要重连/重绑；即使当前只有一个其他在线设备也不得自动改绑。
- 目标能力与函数契约不匹配时在编辑检查、发布检查和运行前检查中使用同一错误码与修复说明。
- 日志事件必须包含实例名、`target_id`、目标显示名、驱动类型和切换结果。

## 9. 验收基线

- `REQ-TGT-001`：Windows Player 可以在同一运行实例中从 Windows 目标进入 ADB 目标作用域，并在退出作用域后恢复上一逻辑目标。
- `REQ-TGT-002`：目标切换后，视觉、OCR、控件和输入不得消费上一目标的缓存结果。
- `REQ-TGT-003`：跨`target_id`使用坐标、区域、控件句柄或路径时必须被阻止并指出两个目标。
- `REQ-TGT-004`：Android 本机宿主只能操作当前手机；无目标实例只能执行不依赖目标的函数。显式无目标选择优先于项目默认目标，Compiler 与 Runtime 不得静默继承默认 Windows/ADB 目标；项目仍可通过显式目标作用域临时切换。
- `REQ-TGT-005`：单实例目标操作保持串行；两个目标需要真正并发时必须由两个隔离运行实例执行。
- `REQ-TGT-006`：ADB 断连后不得自动改用模拟器 Windows 窗口继续点击。
- `REQ-TGT-007`：逻辑目标作用域退出不得主动恢复旧前台窗口；发生物理输入时鼠标位置仍必须恢复。
- `REQ-TGT-008`：非当前目标不得继续运行常驻截图循环；空闲目标的驱动资源必须休眠或释放。
- `REQ-TGT-009`：Windows IDE 可以向 USB 连接的真实设备部署/更新 Android 本机测试 Player，并把本机运行日志与普通 ADB 目标日志明确区分。
- `REQ-TGT-010`：签名 Android APK 在断开数据线且 IDE/后端关闭后，可以独立启动并完成一次真实截图、图像/OCR、输入和停止流程。
- `REQ-TGT-011`：MediaProjection、无障碍、通知/前台服务和文件授权被拒绝、撤销或重启失效时，Android Player 必须停止相关动作、说明缺少的权限和恢复方式，不得伪报成功。
- `REQ-TGT-012`：Windows Player 可以直接启动受约束应用、等待该进程退出，并查找/等待、激活、关闭和读取 Windows 窗口状态；这些入口不得执行任意 Shell、PowerShell 或系统命令。
- `REQ-TGT-013`：普通视觉调用自动使用调用开始后的当前目标新帧；显式帧引用可供多个图像/OCR 调用复用同一像素，并保持来源目标与空间版本隔离。
- `REQ-TGT-014`：录制会话在目标或空间变化时建立新片段并保留完整来源；停止/失败录制不取消当前目标作用域或自动化任务。
- `REQ-TGT-015`：目标注册表使用独立内容 revision 和严格判别式 Schema；所有工作区 API、运行解析与 Capture 使用显式工作区身份，删除被 ProgramDocument、项目变量、资源或 Player 引用的目标时返回稳定引用位置并阻止写入。
- `REQ-TGT-016`：ADB 目标只使用作者确认并持久化的显式序列号；缺失、离线或失效时进入可恢复重绑状态，不自动选择其他在线设备。同一目标重绑保留稳定 `target_id`。
- `REQ-TGT-017`：IDE 的 ADB 扫描只返回真实候选和状态；选择候选只修改未保存草稿，未经保存不改变目标，离线/待授权候选不可选且永不触发自动改绑。
- `REQ-TGT-WIN-018..022`：同名 Windows 窗口可以通过捕获绑定精确区分；句柄复用、跨重启恢复、歧义停止、草稿保值、即时测试与共享 Runtime 解析器按 3.1 节验收。
- `REQ-TGT-WIN-023`：两个 Player 实例可以在各自方案中捕获两个同名窗口，互不覆盖；后续视觉与输入均命中本实例绑定。

Harness 至少覆盖：Windows→ADB→Windows 正常切换、嵌套作用域、异常退出、取消、ADB 首帧失败、中途断连、跨目标坐标误用、缓存隔离、无目标逻辑脚本、双实例并发、真实雷电模拟器冒烟，以及 Android 真机部署、权限拒绝/撤销、旋转、后台/前台、断线独立运行和签名 APK 冒烟。模拟器或 ADB 替身不能替代 Android 本机真机证据。

### 当前自动化证据

`control.target_scope` 已从 ProgramDocument 确定性降低到 ECIR，并锁入稳定 `target_id` 与被引用目标定义。进程内 Windows Runtime 已用假 Windows/ADB 驱动验证串行切换、嵌套恢复、首帧失败不提交切换、异常恢复、取消和驱动释放；缺失引用和 Android 本机跨宿主在编译或运行前阻止。

目标注册表函数还完成了普通调用中 `TargetReferenceValue` 的 ECIR 闭包锁定、Windows/ADB 状态重新探测、在线等待、正常超时空值、取消与缺失引用异常。类型化应用切片只允许 Windows 授权 `.exe` 或当前 ADB 目标的包/Activity；窗口与控件使用运行会话内的强引用令牌，防止句柄复用、控件变化或跨目标误操作。IDE 的图片、坐标、区域、路径与控件 Capture 均按当前语句的有效目标路由；具有物理桌面矩形的 Windows 目标按原位置和原尺寸覆盖冻结帧，ADB 等逻辑目标才居中等比展示。ADB 控件捕获使用目标冻结帧取点并解析同一设备的 UIAutomator 树，不会把模拟器 Windows 外壳当成 Android 控件。

2026-09-02 又在真实 IDE 页面和 `emulator-5554` 完成“Windows 测试窗口 → 微信 → ADB → 微信”的端到端冒烟，运行日志记录每次切换、命中、恢复和完成。显式 Windows 目标的控件捕获从该目标 UIA 根向下命中，即使目标被其他窗口遮挡也不会读取遮挡窗口；整窗捕获以真实 DWM 帧为坐标边界，不把不可见阴影边框计入冻结画面。该证据仍不替代 Android 物理手机本机 APK 完成门。
