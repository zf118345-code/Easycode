# EasyCode 首个正式版本阶段门

本文件规定首个正式版本的实施顺序。它不是按日期维护的进度周报；每一阶段只有在需求、实现、自动验证和对应真实宿主证据闭环后，下一阶段才可作为主线目标。局部缺陷可以随时回修，但不得用后续界面包装掩盖前一阶段的能力缺口。

## G1 统一值模型与参数交互

- 所有自由值槽共用强类型表达式输入器，不显示“填写 / 变量 / 计算”来源按钮或“更多操作”。
- 坐标、区域、路径、资源、控件、文件和目标引用支持兼容变量、结果字段与批准的纯值操作；选择、捕获和系统授权只作为同一值槽的快捷动作。
- 列表、字典和记录保留多行组织器，叶子递归复用统一输入，整体也可引用变量或使用纯值操作；枚举保持单纯下拉。
- 新增函数只声明参数契约，不允许复制一套旧参数表单。

放行证据：表达式往返、类型/稳定 ID、无效草稿、捕获回填、枚举约束和全部参数投影自动测试；DDT 浏览器实际编辑；Windows/ADB 捕获动作回归。

## G2 官方基础能力闭包

- 冻结并实现控制流、等待、输入、窗口/应用、图像、OCR、控件、文件/目录、JSON/集合、HTTP、消息、时间、日志、目标和纯值操作的最小完备目录。
- 每个函数具备稳定 ID、参数/返回类型、平台矩阵、失败语义、取消语义、日志与表单投影。
- 用代表性项目证明常见脚本不依赖隐藏源码逃生口；特殊寻路、模型识别等领域能力通过扩展接口实现。

放行证据：目录契约与平台矩阵测试；DDT 中从简单到复杂的组合项目；Windows、ADB 与无目标运行烟测。

## G3 结构化编写与调试闭包

- 完成插入、嵌套、移动、复制、删除、多选、搜索、跳转、撤销/重做和提取项目函数。
- 完成断点、单步、暂停/继续/停止、当前语句、变量/结果查看和结构化错误定位。
- 大项目仍以纵向语句高密度展示，不重新引入画布连线或可编辑源码作为第二事实。

放行证据：结构命令稳定 ID 与撤销对称测试；浏览器键盘/鼠标 E2E；大样例项目人工走查。

## G4 项目持久化与恢复

- 完成结构化自动保存、原子写入、外部冲突比较、历史版本、损坏恢复和崩溃诊断。
- 暂停可以继续当前运行；停止、取消或崩溃后的再次运行创建新运行 ID，从项目入口开始，不猜测恢复旧业务栈。

放行证据：故障注入、磁盘满/权限/并发冲突、恢复选择和日志定位测试。

## G5 Windows 与 ADB 实际运行闭包

- 同一 Windows Player 实例可串行切换桌面/Windows 窗口/ADB 目标，任意时刻只有一个当前目标。
- Windows UIA、ADB UIAutomator、图像/OCR、输入、坐标空间、捕获和 Player 字段动作形成真实闭环。
- 无目标方案在检查、编译和运行前阻止视觉/输入函数。

放行证据：真实 Windows 应用、模拟器和连接设备上的 DDT 项目；跨目标切换、断连、权限和失败恢复证据。

## G6 独立 Player 与 Android 本机闭包

- Windows Player 无系统 Python、无 IDE/开发后端独立运行签名包。
- Android 签名 APK 复用 Player 渲染与 Control，在断开数据线并关闭 IDE/后端后完成权限、捕获、Accessibility 输入、文件和日志闭环。
- Windows/Android 共享语义和组件，不要求像素一致；平台权限与原生宿主保持清晰边界。

放行证据：独立 Windows 包、模拟器与真实 Android 设备离线烟测；发布闭包和源码隔离审计。

## G7 录制、计划、协作与更新

- Windows、ADB、Android 本机完成全部帧/变化帧/诊断录制、浏览、离线分析和导出。
- 完成本地计划、定时批量运行、多实例、LAN 配对/消息/幂等派发。
- 完成可关闭的签名项目更新和 Player 更新；官方托管与作者自托管使用同一客户端契约。

放行证据：真实宿主录制与磁盘保护、系统调度、LAN 双机/多实例、更新关闭零外连及失败回滚。

## G8 性能、长稳与正式发布审计

- 达成大项目编辑、检索、局部校验、启动、截图、内存、磁盘和 1/2/4/8 实例预算。
- 完成 24 小时长稳、资源泄漏、取消/关闭、离线、权限撤销和升级回滚验证。
- 最后统一交互文案、响应式、无障碍和视觉层级；不得删除已闭环能力换取表面简洁。

放行证据：可复现性能报告、长稳报告、三宿主发布矩阵和完整需求追踪表。
