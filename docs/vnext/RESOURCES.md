# 资源系统

状态：`Approved`（资源身份、统一 Capture Session、Player 图片私有覆盖与终端回填边界已冻结）

最近修订：2026-09-01

## 1. 身份、分类与引用

资源由稳定 `asset_id` 标识。显示名、目录、文件名和用途标签可以修改，不影响长期引用。ProgramDocument 使用类型化 `asset_ref` 值节点引用资源；功能扩展只能在自己的版本化命名空间数据中使用同一 `asset_id` 引用契约。不在可编辑源码、显示名或文件路径中建立运行绑定。

`image / ocr / page` 是通用资源根目录和用途提示，三者始终可见、可切换：

- 选择资源、独立录入、参数捕获和控件视觉捕获都复用同一资源管理器。
- 调用入口只传入 `default_category`，只决定初始选中的根目录，不限制允许分类。
- `page` 是通用资源分类，不等同于页面导航扩展已启用；向该目录保存图片不会创建 Page Model、注册 `页面.*` 或启动扫描。

## 2. 元数据与预览

资源检查器展示显示名、目录、用途、原始尺寸、文件大小、哈希、捕获来源、参考目标尺寸、创建/修改时间和真实引用位置。稳定 ID 属于技术信息，只在诊断/复制场景展示，不与常用值争抢位置。

图片的运行识别区域属于具体函数调用，不属于资源本体。资源可记录当初捕获区域作为来源审计，但不在新调用中静默套用。

工作区使用左侧目录、中央网格/列表和右侧元数据/引用。网格只解码可见批次，使用缩略图缓存、渐进渲染和滚动增量加载。

## 3. 选择与 Capture Session

资源选择使用两阶段提交：

1. 单击卡片只更改当前选中项。
2. 双击或点击“应用到参数”后，Resource Service 向原 `document_id + statement_id + parameter_id + revision` 提交结构命令。
3. 命令成功后才退出选择工作区；失败时保留选中图片、原请求上下文和可重试错误。

取点、框选、录图、控件与手势路径捕获统一使用 Capture Session，不同入口使用判别式目的地：

- **IDE Program 目的地**携带 `project_id`、编辑会话、`document_id`、`statement_id`、`parameter_id/value_id`、请求 ID、revision 和当前 `target_id`；确认后由 Program Service 提交结构命令。
- **IDE Resource 目的地**携带工作区身份、请求 ID 和当前 `target_id`，不伪造 Program 字段；确认后由同一 Resource Service 事务保存并刷新注册表，IDE 拒绝确认或刷新失败时撤销该资源事务。当前目录只作为 `image / ocr / page` 的初始选择，保存管理器允许改选最终分类和子目录。
- **Player Control 目的地**携带 `product_id`、`release_id`、已保存方案的稳定 `profile_id + profile_revision`、`control_id`、`action_id`、请求 ID 和当前 `target_id`；确认后只原子更新运行方案或 Player 私有资源覆盖。新建未保存方案不创建临时 Capture 身份；必须先保存并取得单调 revision。该边界以 ADR-060 和 `AC-PLY-CAP-008` 为准。

三种目的地复用同一坐标、区域、图片、控件与手势路径结果类型和宿主协议，但不能互换提交适配器。提交前重新验证全部身份、字段类型、平台能力和权限；语句/字段已删除、项目或方案已切换、会话过期、目标改变或 release 已切换时拒绝错误回填。Player 回填不得修改 ProgramDocument、签名 ECIR、IDE 项目资源或发布包。

Windows 桌面、ADB 与 Android 本机使用不同捕获宿主，但提交同一类型化结果。Android 真机捕获必须处理 MediaProjection、方向变化、应用前后台与系统返回；权限或会话失效时保留原字段、未提交草稿和可重试上下文，不回填旧坐标、空图片或其他字段的结果。Android 本机 Capture Session 是首个正式版本完成门的一部分；Android 控件捕获只有宿主能从真实 Accessibility 节点生成契约认可的选择器时才出现，不作为全设备硬门。

三类宿主共用 Capture Session 状态、目的地验证、选择模型、结果类型与原子提交；不能复用的是 Windows 顶层窗口、ADB 帧源和 Android MediaProjection/悬浮权限等平台适配。桌面与手机都应采用干净新帧、原图冻结、选区外降噪、就近确认、微调和取消保留旧值；不得为了代码复用把 Windows 窗口硬搬到手机，也不得各自实现一套业务提交语义。

运行记录工作区可以把不可变历史 `frame_id` 作为冻结 Capture 来源。界面必须持续显示录制会话、帧时间和目标片段，并只允许取点、框选或录入资源；宿主不得重新截取当前目标。确认后仍经 Resource Service 事务保存，`image / ocr / page` 三个根目录始终可选。历史帧只作为来源证据，不把其坐标空间、权限或目标有效性带入未来运行。

Player 字段捕获由作者按字段、动作和平台显式开放，默认没有任何终端捕获动作。用户开放“截取图片”或“选择图片”后仍必须由终端用户主动发起；它不授予脚本静默捕获能力。有效动作还必须通过字段类型、发布闭包、当前宿主/目标和权限状态检查，完整规则见 [`PLAYER.md`](PLAYER.md)。

## 4. 生命周期与事务

- **导入**：计算哈希并提示重复，不强制去重。
- **重命名/移动**：事务更新注册表和文件事实，`asset_id` 与结构引用不变。
- **替换**：保留 `asset_id`，更新字节与审计元数据，使相关缩略图、识别和回放缓存失效。
- **删除**：先计算 ProgramDocument、Player Schema 和扩展数据引用。存在引用时默认阻止，用户可取消、选择替代资源或在契约允许时显式设为 `unset`；不留悬空路径。

事务失败不得留下“注册表已改但文件未改”或反向半状态；内存上下文和可恢复选择必须保留。

Player 终端选择或截取的图片不写入 IDE 资源注册表。宿主先把候选写入当前 Player 实例的暂存区，验证格式、体积、尺寸和哈希，再与 `control_id` 覆盖引用作为一个事务切换到受控覆盖目录；失败时保留原覆盖/开发者默认资源并清理暂存候选。运行方案只保存私有覆盖引用与必要元数据，不保存原相册路径、临时 URI 或图片字节。

恢复开发者默认图片只移除该字段的覆盖引用，不替换或删除签名发布包内的默认资源。Player 私有图片可以由后台垃圾回收清理，但清理前必须确认不再被任何运行方案引用。普通文件和目录不是资源覆盖；它们继续使用文件规格定义的强类型外部引用，不能因为曾由系统选择器选中就复制进资源系统。

## 5. 编译与发布

编译器从 ProgramDocument、Player Schema 和已启用扩展数据的稳定引用计算资源依赖闭包。ECIR 只保存运行所需的资源 ID/槽位，打包器携带闭包内文件、哈希和平台派生产物。未引用资源不进入 Player。

Android 发布器必须把被引用图片、OCR 模型/字典及其他 Android 派生产物纳入签名 APK 清单，并在打包前验证体积、哈希、许可证和 Runtime 兼容性。Windows 与 Android 发布闭包还必须包含运行所需字体、图标、原生库及其他平台派生产物；任一必需项缺失时在发布或本地加载阶段明确失败，Player 不得在运行时联网补下载。手机在作者调试 Capture Session 中采集的资源通过 IDE Program 目的地和同一 Resource Service 回填 IDE 项目；终端 Player 用户替换的资源只进入该 Player 实例的受控覆盖目录，不反向修改 IDE 项目或签名 Windows Bundle/Android APK。

资源压缩和加密只是交付策略，不宣称绝对不可逆。发布验证清单、实际文件、哈希、目标平台和扩展闭包一致；不一致时阻止发布，不在 Player 中延迟报错。

## 6. 首版需求编号、失败语义与范围

| 需求 | 状态 | 可验证完成条件 |
| --- | --- | --- |
| `REQ-RES-001` | `Approved` | 注册表以稳定 `asset_id` 为事实；显示名、分类、子目录和文件位置变化后引用仍有效，文件与注册表事务一致。 |
| `REQ-RES-002` | `Approved` | 导入、独立录入、参数捕获、视觉捕获、历史帧录入和参数选择均显示固定顺序的 `image / ocr / page`；入口值只作为初始分类。 |
| `REQ-RES-003` | `Approved` | 导入和替换先验证真实图片解码、扩展名、体积和尺寸，再计算字节大小与 SHA-256；同哈希给出重复提示但保留独立资源。 |
| `REQ-RES-004` | `Approved` | Capture Session 保存真实目标、平台、宿主、来源工作区、选择区域、参考尺寸和时间；来源工作区只作溯源，函数运行区域不进入资源本体。 |
| `REQ-RES-005` | `Approved` | 同名冲突、引用检查、移动、重命名、替换、删除和回填形成单一事务；任一身份/revision/引用检查失败都在修改前拒绝或完整回滚。 |
| `REQ-RES-006` | `Approved` | 资源选择两阶段提交；加载/保存错误有原位重试，取消不写入，删除后焦点落到相邻资源或导入入口；窄宽检查器作为可关闭抽屉且关闭后恢复焦点。 |

统一失败语义如下：

- 工作区身份、项目、目标、目的地字段或 revision 过期返回 `409`，保留当前选择和 Capture 上下文；若资源字节已经暂存，必须撤销本次资源事务后再允许重试。
- 注册表、ProgramDocument 或扩展命名空间数据无法读取时，引用影响计算失败关闭；不得把“无法检查”解释为“没有引用”。
- 文件取消选择不产生请求；导入/替换中任一真实图片校验失败不得写注册表或残留文件。批量导入已经完成的前项必须明确报告，不把部分成功伪装成全成功。
- 删除存在引用的资源或目录默认阻止。首版 IDE v6 不提供伪造的“删除并静默清空源码引用”；替换或显式 `unset` 必须由各自的结构命令另行完成。

本节只覆盖 IDE v6 项目资源与 IDE Capture Session。Player 私有图片覆盖、Android 本机 Capture、发布资源闭包和运行时缓存分别由 `PLAYER.md`、Android 规格、发布规格与 Harness 验收，不由本切片的桌面自动测试宣称通过。
