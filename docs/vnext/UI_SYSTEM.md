# EasyCode 统一界面系统

状态：`Approved / Implemented / Browser-verified`  
适用范围：Windows 开发端、Windows Player、Android Player、第一方工作区、扩展贡献页面与扩展函数表单。  
非目标：强迫所有任务采用相同栏数；让 Android 照搬桌面布局；以统一为理由删除领域功能。

## 1. 设计目标

EasyCode 使用同一套可学习的工作台语法：用户切换页面后，应当立即知道当前在哪里、主要内容是什么、如何创建或导入、如何选择对象、在哪里配置详情，以及失败后如何恢复。页面可以因任务不同而采用不同拓扑，但相同角色必须保持相同位置、层级、名称和反馈。

### REQ-UIS-001 共享工作台语法

- 页面标题与页面级主操作属于 `WorkspaceHeader`。
- 导航或对象列表标题属于 `PaneHeader`；搜索、筛选和批量操作属于 `ListToolbar`。
- 当前对象的参数与操作属于 `InspectorHeader` 和检查器正文。
- 页面级操作不能在标题栏、列表栏和空状态中形成三个不同入口；空状态可以调用同一命令，但名称和结果必须一致。
- 两栏任务保持两栏，只有存在独立详情语义时才显示第三栏和最右侧活动按钮。

### REQ-UIS-002 稳定度量

- 应用标题栏 40px，状态栏 24px，活动栏 44px，右侧活动栏 38px。
- 工作区与窗格标准标题栏 40px；需要标题和一行必要说明的工作区允许 56px，但同一角色不得自行取 42、45、46、48、58、64 或 68px。
- 默认控件 32px，紧凑控件 28px；通用触控控件至少 44px，Android Player 触控控件至少 48px。
- 字体角色固定为：页面标题 15px、窗格/对象标题 13px、正文 13px、紧凑正文 12px、辅助信息 11px。9px 与 10px 不得承载用户必须阅读的信息。
- 间距仅使用 4、8、12、16、24、32px 及其语义 token；圆角仅使用共享 token。

### REQ-UIS-003 状态所有权

状态分为整页加载、整页失败、整页空、列表空、筛选空、未选择对象、局部操作中、局部操作失败和成功反馈。每个事实只有一个主展示位置。

- 整页空：主任务区显示原因、下一步和至多一个主操作；无内容的辅助详情栏自动收起或保持静默。
- 列表空：只在列表范围显示；不能同时让中央区要求选择不存在的对象。
- 筛选空：说明当前筛选无结果，并提供清空筛选。
- 未选择对象：详情区用一句话说明选择后能做什么，不重复列表的空状态。
- 加载和失败：使用统一图标、标题、说明、`role=status/alert` 和原位重试；不得以永久空白代替。
- 成功：低风险自动保存使用状态栏；需要用户确认的完成结果使用有时限的工作区通知，不新增阻塞弹窗。

### REQ-UIS-004 动作层级

- 每个视图同时最多一个橙色主操作。
- 页面级创建、导入与运行位于 `WorkspaceHeader` 的动作槽；对象级动作位于行尾、上下文菜单或 `InspectorHeader`。
- 同一命令在菜单、快捷键、空状态和按钮中使用同一名称。
- 纯图标按钮必须有可访问名称和 tooltip；高频且对新手关键的动作使用文字按钮。
- 禁用操作必须在同一控制附近解释原因，不能要求用户猜测前置条件。

### REQ-UIS-005 页面命名与信息克制

- 每个工作区只有一个面向用户的稳定名称；内部模块名、slug、ID、哈希、Bundle 名和实现层术语进入技术信息或诊断。
- 主标题不重复活动栏、面包屑或相邻窗格已经表达的同一事实。
- 空状态、标题和说明不能三次重复“尚未选择”；说明必须回答下一步，而不是描述布局。
- `Agent` 在普通界面显示为“后台计划服务”；`Bundle` 显示为“发布包”，除非位于开发者信息。

### REQ-UIS-006 设计令牌与组件边界

- 第一方界面只使用 `--app-*` 公共令牌；`--ec-*` 作为兼容别名映射到公共令牌，不得发展第二套主题。
- 工作区不得自行声明重复的按钮、输入框、状态页和标题栏视觉规则。
- 扩展只能使用公开的布局槽、Control 组件、状态组件和语义令牌，不得向应用根节点注入全局 CSS。
- 扩展贡献的未知内容必须在受约束容器内滚动、截断和隔离；不能改变顶栏、活动栏和状态栏。

### REQ-UIS-007 响应式与输入方式

- 大于等于 1100px：按任务显示两栏或三栏，宽度可调并持久化。
- 760–1099px：正文常驻，左右辅助栏使用互斥覆盖抽屉。
- 小于 760px 的开发端：保留品牌锚点、总菜单、搜索和当前唯一主操作；不隐藏功能，只改变入口。
- Player 小于等于 760px：单列、触控优先；通用触控目标至少 44px、Android 至少 48px，运行操作保持可见；桌面 Player 保留键盘与鼠标密度。
- 200% 缩放、长中文、键盘、粗指针与无悬浮环境不得丢失操作或产生水平滚动。

### REQ-UIS-008 Player 跨平台一致性

- Windows 与 Android Player 共用字段顺序、标签、默认值、必填、验证、运行状态、日志语义和错误恢复。
- 平台差异只能来自真实能力和输入方式：Android 使用系统权限、触控与安全区；Windows 使用窗口、键盘、文件系统与桌面密度。
- 同一发布表单不能因宿主不同改变业务含义；不可用能力应说明平台原因，不能静默消失。
- Android WebView 必须使用安全区、系统返回、软键盘和生命周期恢复；Windows Player 必须支持窗口缩放与键盘操作。

### REQ-UIS-009 扩展与新页面接入

扩展或新工作区必须声明：稳定名称、任务拓扑、主对象、页面级主操作、列表空/筛选空/未选择/加载/失败状态、详情所有权、窄屏策略、键盘路径、权限与危险操作。未声明不得接入活动栏。

扩展可使用：

- 两栏或三栏工作区骨架；
- 标题、工具栏、列表、检查器和统一状态；
- 强类型 Control、确认对话框和工作区通知；
- 应用语义令牌和受约束图标。

扩展不得：

- 创建第二套顶栏、活动栏、状态栏或主题；
- 用技术 ID 作为主标题；
- 用右键菜单承载唯一功能入口；
- 在没有选择对象时展示可操作的伪详情；
- 以自定义 CSS 覆盖宿主控件语义。

公开实现边界：`frontend/src/vnext/uiSystem.ts` 定义并校验 `WorkspaceUiContractV1`；`frontend/src/vnext/components/ui/index.ts` 是第一方页面和宿主渲染器可使用的共享组件出口。扩展只提交版本化声明，不能直接导入或替换应用壳层。

### REQ-UIS-010 内容密度与表单节奏

统一不只指相同颜色和边框，也包括内容之间稳定的亲疏关系。页面不得用局部 `margin` 和任意行高重新发明密度。

- 单行导航或对象列表使用 28px 紧凑行；需要更宽点击区但仍只有一行内容时使用 32px 默认行；只有确实存在标题和第二行有效信息时才使用 44px 富信息行。不得为了“显得重要”把单行项目做成 48px。
- 表单分为四级：15px 页面标题、13px 分组标题、12–13px 字段标签、11px 辅助说明。分组标题不得比字段标签更小；辅助文字不得代替字段标签。
- 分组标题到首个字段为 10px，标签到控件为 5px，相邻字段为 12px，分组之间为 18px。分隔线位于分组间距中，不能紧贴下一字段标签。
- 帮助说明只在用户作出正确决定所必需时常驻，并紧贴其所属标题或控件；低频原理、运行机制和技术信息进入问号帮助或“其他/说明与限制”，不能插在标题与首个输入框之间。
- 组件只能拥有自身内部节奏；父容器负责组件之间的间距。父子同时添加顶部间距造成的“双倍空白”视为缺陷。
- 占位符展示期望格式或可直接仿写的示例；默认值直接展示实际生效值，不使用“默认配置”“无结果”等需要二次理解的替代词。

### REQ-UIS-011 表单层级与字段几何

作者表单与 Player 表单使用同一套可辨认的层级，但桌面与触控端可以使用各自的控件高度。

- 一级表单区块只用于当前任务的主要阶段，例如“参数”“结果”“基本信息”。一级标题使用 13px 分组标题，标题到首个字段固定 10px；相邻一级区块之间使用 18px 节奏，并只在区块边界出现分隔线。
- “高级参数”“说明与限制”“步骤备注”属于当前一级区块的低频折叠组，使用 28px 折叠行和 12px 字段字体，不得伪装成第三种分组标题。禁止使用无法说明内容归属的“其他”“更多设置”。
- 字段内部固定为“字段标签 → Control → 就近错误或必要说明”。标签到 Control 为 5px，错误/说明到 Control 为 4px；父区块与字段不能同时添加首项顶部间距。
- 普通字段之间不画满宽分隔线，依靠 12px 间距分组；分隔线只区分一级区块、危险审核或独立事务。字段标签不得紧贴上一条分隔线。
- 桌面检查器的输入框、选择框和同一行图标动作统一为 32px；单行内容必须保持一行、截断并可查看完整值，不得因类型尾注或动作按钮挤压而长高。多行 Control 只有契约明确允许多行时才扩展。
- 检查器字段使用按 Control 语义决定的唯一自适应几何：开关、短状态等自身宽度稳定且不会挤压操作的紧凑 Control 使用一行 `字段标签 | Control`；文本、数值、枚举、目标/资源引用、带字段动作的 Control 和结构值默认使用 `字段标签` 在上、`Control | 字段动作` 在下。帮助、校验错误和真正的第二份业务信息继续位于 Control 下方。页面不得自行按截图宽度决定布局，紧凑与纵向归类由共享 Control 契约统一投影。
- 字段组使用普通 `div/label` 和可访问名称建立语义；不得依赖 `fieldset/legend` 的浏览器特殊排版承担常规字段标签。单选集合等真实组合仍可使用 `fieldset/legend`。
- 返回绑定是与参数并列的一级区块；结果派生动作紧随返回 Control。步骤备注是低频折叠组，不与“返回”争夺一级层级。
- 任何共享字段修复必须覆盖：紧凑开关、普通值、必填错误、资源/目标选择器、同排动作、长中文、返回绑定、折叠高级参数和窄检查器。只修复单个函数截图不算完成。

### REQ-UIS-012 表单信息克制与即时验证

表单只常驻展示会改变本次任务结果、且用户当下必须决定的内容。可用能力不能因为隐藏说明而失去入口，但实现细节也不能冒充业务参数。

- 一级字段分为三类：必填业务输入直接可见；有安全且稳定默认值的调优项按使用频率留在主区或“高级参数”；运行时内部字段不得进入普通表单。图像资源、目标、文件与目录等稳定对象使用直接选择/捕获 Control，不使用自由文本或表达式输入器伪装资源选择。
- 图像与 OCR 的常用主区只保留图片/目标文字、区域和会显著改变结果的阈值；语言、预处理、检查间隔、稳定帧、显式帧等低频项进入“高级参数”。日志内部分类、调度实现策略等普通作者不应决定的字段保持内部化。
- 常驻说明只保留三种：不说明就容易填错的格式、不可逆后果、与直觉不同的默认行为。按钮下方不得再用一句话复述按钮名称；精确结果或不可用原因在动作执行后原位出现，低频解释放入 `title`、问号帮助或诊断。
- 表单内非主要、非危险且位于 Control 之外的文字动作统一使用 `app-inline-action`：28px、Lucide 图标加文字、静止时透明、悬停时弱边框与底色。与 Control 共同完成一次字段输入的动作使用独立的 `app-field-action`，不得把可点击文字塞进输入框外观。对话框提交/取消、页面主操作、标签页、列表行和纯图标工具不套用该样式。
- 图像/OCR 作者表单提供“测试当前画面”：一次采集一张不可变帧，使用与 Runtime 相同的资源、区域、相似度、语言和预处理适配器；图像类只查找并标出匹配，不执行点击或等待。OCR 返回处理后的实际裁剪图、文字和匹配结论，使灰度、二值化、阈值与反色可以在运行前调整。
- 图像测试无论命中与否都同时显示本帧最高相似度和当前阈值；没有可比较像素时明确显示“相似度不可用”，不得用 `0%` 冒充。可选画面引用清空后在同一 Control 显示“自动获取最新画面”，并真正保存为空值。
- 测试参数含运行时变量时不得用猜测值伪造预览，应就近说明需要运行流程验证；Android 本机目标只能在对应 Player 宿主测试，开发端不得把 ADB 或浏览器结果冒充本机证据。
- 只供读屏器使用的重复标签使用全局 `sr-only`，不得因为局部组件漏写样式而重新成为可见文字。

### REQ-UIS-013 Control 尾注、字段动作与结构化值

右侧检查器必须让用户仅凭外观分清“当前值”“被动说明”和“可以点击的动作”，并由同一强类型契约决定复杂值采用何种编辑方式。

- Control 边界内只允许当前值、实际生效的默认值、单位或不可交互状态。类型名、字段数量和“编辑内容”等动作不得伪装成输入值或尾注；类型由字段标签、帮助和无障碍描述承接。
- 单位或状态尾注使用不可交互的 `app-control-adornment`，颜色弱于值且不响应悬停。字段动作统一置于 Control 外侧，使用 32px 的 `app-field-action` 与 Control 等高；图标、tooltip 和可访问名称必须明确说明“选择、捕获、编辑”等真实动作。同一字段在 280px 检查器内也保持单行、等高且不溢出。
- 只有当前作者表面具备真实、类型安全且事务一致的适配器时才渲染字段动作。聚焦事务中的嵌套文件/目录字段在作者引用闭环完成前只允许通过 `@` 选择兼容的已有值，不得显示会提交裸路径、绕过整值保存或点击后失败的假选择按钮；Player 运行时动作不能被 IDE 误投影为作者动作。
- 命名 Record 的作者方式由注册表声明，不由页面按字段数量临时猜测：小型可构造 Record 使用 `inline_record`；列表行使用 `row_list`；深层列表、字典、JSON 或复杂 Record 使用 `focused`；运行时结果/句柄使用 `reference_only`；只能由宿主采集的值使用 `capture_only`。IDE 与 Player 消费同一声明。
- `inline_record` 在当前检查器中直接展开为紧凑字段，不再先显示一个假输入框再打开第二张表单。同一 Record 内连续叶字段采用 8px 行间距，Record 与相邻参数仍遵守 12/18px 层级节奏，不使用卡片套卡片；条件字段只在其前置值成立时出现。OCR 预处理默认显示灰度化、二值化和反色，只有开启二值化时显示 0–255 阈值。
- 条件表达式直接使用完整的表达式 Control：布尔值、比较、且/或/非、变量与字段都在原字段内输入并由候选补全。不得再为同一个条件附加“组合条件”按钮或打开只有一行相同 Control 的弹窗；只有有界集合、字典、JSON 或深层 Record 等确有独立事务的内容才使用聚焦编辑层。
- 只有一行无法清晰表达、并且需要独立保存/取消事务的 `focused` 或有界集合才使用摘要加外置编辑按钮。浮层宽度由内容决定：紧凑约 440px、普通约 560px、深层集合上限约 720px；不得设置使四字段内容被迫长高的固定最小正文高度。窄于 620px 时横向贴合视口、高度仍按内容增长，只有内容达到视口上限时才内部滚动；同时完整处理初始焦点、Escape、未保存确认、背景隔离和关闭后的焦点归还。
- 是否打开浮层由信息密度与事务边界决定，不由“这是结构值”决定。能在字段本体完成的编辑不得另开浮层；能合并为一个 Control 与同排动作的步骤不得再添加选择模式、确认页或中间摘要。
- 一个结构值只能同时出现一种编辑投影。禁止同时展示“整值输入”和字段树，也禁止递归卡片嵌套。超过首屏可读范围的列表或字典采用分段、折叠或有界渲染；切换会丢弃非空子树的类型前必须明确确认。
- Program 快照必须携带其中所有命名 Record 与字段的稳定展示名。目录暂不可用时保留现有值并显示可恢复错误，不得退化成“字段 1”“字段 2”、裸字段 ID 或可提交的任意 JSON。
- 结构化值编辑是单次事务：叶字段只修改本地草稿，保存时一次替换根值，取消时不产生 Program 命令。未来为嵌套字段接入选择/捕获时，返回结果也必须先写入该草稿，再随根值保存；不得直接修改文档后再让浮层显示一份过期副本。

### REQ-UIS-014 活动栏双模式与共享左侧导航

- 开发端活动栏只有两种宿主渲染模式：`compact` 为 44px 图标栏，`labeled` 为图标加稳定工作区名称的文字栏。两种模式共享同一工作区清单、排序、选中、计数、禁用和键盘语义，不能维护两套导航。
- 顶部品牌/项目图标是模式切换入口；“视图”菜单和命令搜索同时提供可发现的等价命令。模式属于当前设备用户偏好，不写入项目、ProgramDocument 或发布包；首次使用默认为文字模式，已有偏好可恢复，存储不可用时安全回到文字模式。
- 工作区按钮仍负责切换并展开侧栏；再次点击当前工作区只收起侧栏，不改变活动栏模式。窄宽时侧栏覆盖主区，活动栏标签可自动回到紧凑投影，但不得覆盖用户保存的偏好。
- 所有第一方工作区和受控扩展工作区必须组合 `NavigationPane / PaneHeader / ListToolbar / ObjectListItem` 公共原语。标题、可选有效备注、动作组、32px 搜索、28px 紧凑行、选中态、悬停态、计数和背景使用同一令牌；页头动作即使包在动作组容器中也必须由 `PaneHeader` 统一命中。不得复制工作区专属的搜索框、列表选中背景、橙色标识、侧栏内边距或标题按钮 CSS。
- `NavigationPane` 标题区动作统一为 28px 纯图标按钮，不显示“新建、导入、刷新”等文字；每个按钮必须使用同一 Lucide 图标体系，并同时提供准确的 `title` tooltip 与可访问名称。动作含义由图标、顺序和悬停说明承接；不得由页面自行恢复带字按钮、描边按钮或另一种尺寸。工作区主标题和中间内容区不受此纯图标规则影响。
- 列表的父子层级由缩进和展开图标表达。父级不得因缩进反而位于子级右侧；子级字号不得大于父级；当前对象使用统一的弱橙背景和左侧 2px 直线标识，标识位置、长度、粗细和端点均由共享原语唯一持有，不允许各页叠加圆角、内阴影、边框或另一套背景。

### REQ-UIS-015 单一底部反馈面板

- 开发端只允许一个可调高度的 `BottomFeedbackPanel`。它用同一标签条承接“输出”“当前值”“问题”，三者数据与语义保持独立，但不再生成三个外壳、三个高度或三套关闭按钮。
- 活动栏的运行入口打开“输出”，状态栏问题计数打开“问题”，运行暂停或显式查看值打开“当前值”；再次触发当前标签可收起面板。顶部“视图”菜单与命令搜索提供相同入口。
- 外壳唯一持有面板高度、拖拽条、背景、标题/标签、通用动作和关闭状态。各标签正文必须 `height: 100%` 填满剩余空间，禁止固定 210/270px 子高度、重复顶边框或制造未命名黑色空区。
- “输出”是按时间发生的运行事件，“当前值”是暂停/执行快照，“问题”是可定位和修复的作者诊断。相关不等于混为同一列表；空状态必须分别说明怎样产生内容。
- 底部面板打开后不能遮住状态栏；关闭后高度偏好仍保留。键盘、屏幕阅读器和 200% 缩放下均能切换标签、关闭、调整高度并返回原触发入口。

### REQ-UIS-016 右侧检查器的唯一信息语法

右侧检查器服务于“确认对象 → 完成本次决定 → 立即验证或保存”的短任务，不得被实现层的数据结构拆成多张松散表单。程序、资源、项目变量、运行目标、Player、回放、扩展和计划的右侧区域都组合相同的 `InspectorHeader / InspectorBody / InspectorSection / InspectorField / InspectorDisclosure / InspectorFeedback` 原语；领域页面只提供标题、字段、动作和状态。

- `InspectorHeader` 的主标题只显示当前对象或动作的稳定业务名称。完整语句摘要、资源哈希、asset ID、statement ID、路径和其他内部身份不得进入主标题；确有排错价值时只进入复制 ID、tooltip 或诊断详情。可选元信息只承接一条短状态或当前结果绑定，并保持单行截断。
- 正文只有四种可见层级：一级任务区块标题、字段标签、按需反馈、低频折叠行。禁止用卡片标题、无标题分隔线、说明文字或“其他/更多”再发明平级层次；同一一级区块不得仅因一个辅助动作拆成第二个区块。
- 常规编辑顺序固定为“参数或基本信息 → 结果或领域状态 → 低频折叠”。测试、选择、捕获、派生条件等辅助动作放入所属区块标题或字段同排动作；动作的加载、阻塞、失败和结果紧邻原动作原位出现，不创建独立的“测试区”或重复说明。
- 一级区块使用共享边界和节奏；字段继续遵循单行优先。最后一个区块不得为了视觉留白增加额外底边距。检查器宽度为 280–360px 时，32px Control 与字段动作保持等高；仅在可用内容宽度小于 220px 或契约明确多行时纵向回落。
- `primary / advanced / contextual / internal` 是参数披露的唯一来源。主要字段常驻，高级字段进入所属区块唯一的“高级参数”折叠行，条件字段随前置值出现，内部字段完全不投影。步骤备注、技术信息和危险审核各自使用已定义的低频、诊断或危险语义，不得混入普通参数层级。
- 资源、变量、目标等稳定引用在 Control 中优先显示目录提供的人类名称；稳定 ID 只作为持久化与命令身份。目录暂不可用时保留已保存展示名或显示可恢复的“名称暂不可用”，不得把长 ID 当作正常值或标题回退。
- 共享修复必须覆盖空、加载、禁用、必填错误、保存中、保存失败、冲突、目录暂不可用、测试阻塞、测试失败与成功结果；键盘焦点、Escape、折叠状态、窄宽和长中文均不能改变业务语义或丢失草稿。

## 3. 阶段计划

### UI-26A 共享骨架

建立标题、工具栏、状态和按钮的公共组件与令牌；迁移开发端八个工作区，不改变领域功能。

### UI-26B 状态系统

逐页清理重复空状态，统一加载、失败、禁用、保存和通知；覆盖初次使用、空数据、筛选无结果和网络/宿主失败。

### UI-26C 视觉度量

清除工作区的任意字号、高度、间距和第二套 token；保留经说明的领域特例。

### UI-26D 响应式和无障碍

收束窄屏顶栏，验证覆盖抽屉、200% 缩放、键盘、焦点、粗指针和长中文。

### UI-26E Player 与扩展

迁移 Windows/Android Player，共享状态和 Control 外观；为扩展页面建立公开接入组件和可拆卸样例。

### UI-26F 冻结验收

在 1920×1080、1440×900、1024×768、760×720 与 200% 缩放下走查全部工作区；验证 Windows Player 和 Android WebView 宿主可完成相同表单任务。自动化、浏览器、Windows 宿主和 Android 真机证据分开记录。

### UI-26G 微观密度与节奏

以资源分类单行列表作为紧凑密度基准，统一对象列表、表单分组、字段标签、控件、说明和分隔线之间的关系；逐页检查是否存在 48px 单行列表、11px 分组标题、标题与控件双重间距，以及不必要的常驻说明。

### UI-26H 条件与左栏最终收口

- 范围：程序结构条件字段，以及程序、资源、项目变量、运行目标、Player、运行记录、运行中心和扩展的长期左栏。
- 验收：`如果/否则如果/条件循环/监听条件` 在原字段内完成表达式输入，旁边不存在打开相同条件表单的按钮；深层集合等真实事务仍可进入聚焦编辑层。
- 验收：八个第一方左栏共享 40px 页头、统一动作、32px 搜索、6px 列表内边距、28px 紧凑行或由内容明确声明的 44/52px 行，以及同一条无圆角 2px 选中标识。页面局部样式不得改变这些计算值。
- 失败语义：共享目录或字段候选暂不可用时保留当前值并原位报错，不回退到冗余弹窗；动作禁用时保持布局，不用第二套按钮外观表示失败。
- 范围外：不改变 `ProgramDocument`、运行语义、Player 发布契约、资源结构或各工作区的领域功能；多行运行记录和真实两行目标仍保留其语义密度。

### UI-26I 左栏标题动作纯图标冻结

- 范围：程序、资源、项目变量、运行目标、Player、运行记录、运行中心和扩展的 `NavigationPane` 标题动作。
- 验收：所有可见标题动作计算尺寸均为 28×28px、14×14px Lucide 图标、4px 组间距，无常驻描边和底色；默认统一使用次级文字色，悬停切换共享弱底色与主文字色，按下切换共享 active 底色，键盘聚焦使用同一弱底色与焦点环，禁用统一为 35% 不透明度且不改变布局。
- 验收：每个动作均有唯一、具体的 tooltip 和可访问名称；禁用状态保持图标可辨认，不改变布局，不用隐藏按钮制造跳动。
- 失败语义：缺少明确图标或可访问名称的新增动作不得接入标题区；页面局部 CSS 不得覆盖共享纯图标投影。
- 范围外：不隐藏空状态、正文、对话框或工作区主标题中的文字按钮，不改变任何动作的命令、权限和禁用条件。

### UI-26J 视觉诊断与可选画面恢复

- 范围：所有内置图像原子/标准函数的“测试当前画面”、运行日志，以及图像/OCR 的可选“使用画面”字段。
- 验收：命中显示实际相似度与阈值；未命中显示阈值过滤前的最高相似度与阈值；等待到期保留本轮最有诊断价值的真实分值。清空显式画面后保存为“自动获取最新画面”，重新载入不恢复旧引用且不产生必填错误。
- 失败语义：模板无法与画面形成有效比较时显示“相似度不可用”；不伪造 `0%`、不把未命中改成异常，也不为诊断再次扫描画面。

## 4. 完成标准

- 相同角色的计算样式在不同页面一致，不允许只看源码类名宣称统一。
- 用户在任意工作区五秒内能指出页面名称、主内容、主操作和详情入口。
- 空、加载、失败、禁用、成功状态均存在真实可复现证据。
- 新页面和测试扩展只组合公共骨架即可符合规范，不复制整套 CSS。
- Windows 与 Android Player 的业务字段、状态和恢复一致，平台差异有明确理由。
- 任何功能仍可通过页面、菜单、快捷键或上下文菜单找到；统一不得导致功能阉割。
- 任取五个不同工作区，相同层级的列表行、分组标题、字段标签和输入控件应能对应到同一语义 token；不得依赖截图碰巧相似。
