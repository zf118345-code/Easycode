# Windows Player 多实例控制台

状态：`Implemented / targeted verification passed`

关联决定：ADR-114、ADR-115、ADR-118。

## 1. 任务卡

- 主要用户：在同一台 Windows 电脑上运行多个游戏或业务账号的 Player 操作员。
- 次要用户：需要排查单个实例故障的脚本开发者。
- 触发：用户已经安装一个或多个签名 Player 产品，并希望同时配置、观察或控制多个隔离实例。
- 期望结果：日常只面对一个桌面窗口；从左侧选择实例后，在原位置完成该实例的方案、目标捕获、环境检查、运行和日志查看。
- 频率与紧迫度：每天高频；选错实例、误运行或多个实例相互污染属于高代价错误。
- 前置条件：交互式 Windows 用户会话、已登记签名产品、可用 WebView2；需要 GUI 自动化时控制台与实例工作进程具有相同权限级别。
- 可观察成功：每个实例拥有独立进程、端口、数据目录、WebView 数据、方案、窗口绑定和运行；切换实例不丢草稿、不新开可见窗口；暂停、继续和停止只影响目标实例。
- 恢复：实例工作进程失败时保留方案与其他实例，允许原位重启；独立 Player 窗口作为显式恢复与诊断入口。

## 2. 产品边界

控制台是 Windows Player 的宿主控制面，不是 IDE，也不是第二套 Runtime。控制台进程只枚举当前用户 Player Hub 中已经登记的签名安装和实例，并为被选择的实例启动或复用一个隐藏的独立 Player 工作进程。

每个工作进程仍运行现有 Player-only API、Bundle Loader、Runtime、Capture、更新和日志闭包。控制台不得把多个实例装入同一 Bundle Manager、Runtime 或 WebView 数据目录，也不得读取 ProgramDocument、工作区、作者发布或扩展开发接口。

正常多实例入口使用一个原生 WebView2 控制台窗口。独立 Player 窗口继续存在，但只作为单实例恢复和诊断动作，不再是正常多开时必须管理的窗口数量。

## 3. 目标旅程与信息架构

1. 用户从已安装产品快捷方式或 IDE 运行中心打开 Player 控制台。
2. 左侧显示按产品归属的实例列表、真实运行状态和必要错误；首个可用实例自动选中。
3. 首次选择实例时显示短暂“正在启动实例”，随后在中右区域直接显示该实例原有 Player 表单与运行面板。
4. 用户在所选实例中选择或保存方案、捕获同名窗口、执行环境检查并运行。
5. 切换左侧实例只切换可见投影；已连接实例和未提交表单草稿不重载。
6. 运行中的列表行提供暂停和停止；暂停实例提供继续和停止。开始运行仍位于所选实例的运行面板，因为它依赖当前方案、目标、校验和危险操作确认。
7. 工作进程失联只把该实例标记为“需要重启”；其他实例保持可用。用户可以原位重启或显式打开独立窗口诊断。

桌面宽度不低于 1000px 时，左侧实例栏固定为 236–280px，中右区域由现有 Player 响应式布局占满。窄于 1000px 时实例栏可收为覆盖抽屉，但不能销毁实例页面或清空草稿。

## 4. 稳定需求

- `[REQ-PLY-CONSOLE-001]` 正式 Windows Player 提供独立 `.exe --player-console` 入口；该入口不要求命令行传入某一个 `.ecplayer`，只消费当前用户 Player Hub 的已验证注册表。
- `[REQ-PLY-CONSOLE-002]` 控制台选择实例时必须启动或复用独立 Player 工作进程；不同实例使用不同系统分配 loopback 端口、数据目录、日志、图片覆盖、WebView2 数据和 Runtime。
- `[REQ-PLY-CONSOLE-003]` 控制台只显示实例列表和所选实例的原 Player 页面，不复制方案、Control、窗口捕获、预检、运行或日志实现。切换实例不得重新加载已经连接的实例页面。
- `[REQ-PLY-CONSOLE-004]` 列表行必须显示 `未启动 / 正在启动 / 就绪 / 运行中 / 已暂停 / 失败 / 需要重启` 等真实状态；暂停、继续和停止只发送到该实例当前运行 ID。无当前运行时不得显示可执行的伪控制。
- `[REQ-PLY-CONSOLE-005]` 开始运行保留在所选实例运行面板；不得从列表行用隐式默认方案启动，避免跳过目标、参数、危险操作和 revision 校验。
- `[REQ-PLY-CONSOLE-006]` 普通独立 Player 继续拒绝任何框架嵌入。只有由控制台启动的工作进程可以把精确控制台 loopback origin 列为 `frame-ancestors`，并且仍拒绝其他来源。
- `[REQ-PLY-CONSOLE-007]` 用户通过标题栏关闭或 `Alt+F4` 显式退出控制台时，宿主必须先查询所有实例的真实运行状态。没有活动任务时直接停止全部工作进程并退出；存在运行、暂停或排队任务时显示一次应用内确认，取消保持窗口和任务不变，确认后向全部活动实例请求停止、在有界时间内回收全部工作进程，再关闭控制台和宿主进程。任一停止准备失败时必须保留可见窗口并说明实例与恢复动作，不能先隐藏窗口。进程崩溃、系统强杀或断电不解释为用户同意停止，也不得删除方案或实例数据。
- `[REQ-PLY-CONSOLE-008]` 控制台必须允许创建同一已安装产品的隔离实例，并保留“打开独立 Player”恢复动作；实例创建失败、签名复验失败、启动超时和端口失联均原位保留列表并给出重试。
- `[REQ-PLY-CONSOLE-011]` 实例栏顶部的“新建”是一次完成的直接动作：按当前选中产品创建并选中新实例，由 Hub 原子生成该产品内最低可用的“实例 N”名称；不得要求用户先填写名称，也不得留下无法关闭的半完成表单。
- `[REQ-PLY-CONSOLE-012]` 每个实例提供明确删除动作。运行中、暂停中、排队中或被本地计划/批次引用的实例必须阻止删除并说明解除方式；空闲实例删除使用 revision 防止陈旧点击，并把默认数据目录移入本机恢复区而非不可逆清空。删除当前实例后选择相邻实例，不影响其他工作进程。
- `[REQ-PLY-CONSOLE-009]` 已登记产品的正常快捷方式默认打开控制台并聚焦该产品；如果安装登记失败，快捷方式必须回退为直接打开该签名产品的独立 Player。
- `[REQ-PLY-CONSOLE-010]` 便携交付目录中的 `EasycodePlayer.exe` 与随包启动脚本在无显式运行参数时，必须先校验并登记所在签名分发，再进入控制台并聚焦该产品；工作进程、显式单实例参数和维护命令不得触发这条默认分派。登记失败时保留可诊断原因并回退单实例 Player，不能出现双击无界面。
- `[REQ-PLY-CONSOLE-010]` 控制台和工作进程不得引入 IDE/作者 API、固定端口、跨实例共享可变状态、自动截图轮询或任务运行遥测。

## 5. 状态与失败语义

- 加载：实例列表使用工作区加载状态；不显示空白壳。
- 空：说明尚未登记 Player，并提供明确的安装/登记提示，不提供无后端的“新建项目”。
- 启动：只锁定当前实例的连接动作；其他实例仍可选择。
- 运行：参数与捕获由实例原 Player 自己按既有契约锁定；控制台只显示状态和允许的运行控制。
- 冲突：同一实例只允许一个工作进程；重复选择必须复用，不重复启动。
- 失联：保留实例和方案摘要，标记“需要重启”，提供原位重启和独立窗口。
- 关闭：标题栏关闭和 `Alt+F4` 属于显式退出。无活动任务直接完整退出；有活动任务先确认，确认后停止全部任务与工作进程再退出，取消则不改变现场。停止失败时窗口保持可见。异常崩溃不冒充显式退出，残留工作进程仍按原有孤儿检测和终态回收规则处理。

## 6. 验收

- `[AC-PLY-CONSOLE-001]` 两个实例从同一个原生控制台连接后，进程、端口、数据根和嵌入 URL 均不同，控制台只有一个可见主窗口。
- `[AC-PLY-CONSOLE-002]` 在实例 A 保存方案或捕获窗口后切到 B 再切回 A，字段、revision 和页面位置不因切换重载；B 不取得 A 的数据。
- `[AC-PLY-CONSOLE-003]` A 运行时可从列表暂停、继续、停止；B 保持原状态。列表动作与实例内运行面板最终收束到同一运行状态。
- `[AC-PLY-CONSOLE-004]` 工作进程崩溃、端口失联、启动超时和签名失败只影响对应实例，并可原位重启；其他已连接实例不中断。
- `[AC-PLY-CONSOLE-005]` 普通 Player 响应 `X-Frame-Options: DENY / frame-ancestors 'none'`；控制台工作进程只允许精确控制台 origin 嵌入。
- `[AC-PLY-CONSOLE-006]` Player-only Web 只包含 `player.html`、`capture.html` 和 `console.html` 及其编译资源，不包含 IDE `index.html`、源码或 source map。
- `[AC-PLY-CONSOLE-007]` 从安装快捷方式启动控制台，在无 IDE、无开发后端环境完成实例创建、选择、方案保存、窗口捕获、预检、运行、暂停、继续、停止和日志查看。
- `[AC-PLY-CONSOLE-008]` 真实 Windows 宿主验证：空闲控制台关闭后没有控制台或工作进程残留；两个实例中至少一个运行时点击关闭先显示活动实例数，取消后任务继续且窗口不消失，确认后全部运行进入终态、全部工作进程和控制台进程退出；注入停止失败时窗口保留并显示可恢复错误。异常退出、UAC 权限一致、两扇同名目标窗口分别绑定以及一个实例失败不影响另一个实例仍分别验收。
- `[AC-PLY-CONSOLE-009]` 连续点击新建三次直接得到不重名的实例并逐次选中新实例，界面不出现名称录入中间态；空闲实例经确认可删除并可从恢复区找回数据，活动或被计划引用的实例不能被删除。

## 7. 范围外

- 把多个实例放入同一 Runtime 进程；
- 云端设备列表、遥测、远程桌面或公网控制；
- 在实例列表行隐式选择默认方案并直接开始任务；
- 在控制台中编辑 ProgramDocument、函数、资源或发布设置；
- 用控制台替代独立 Player 的恢复和诊断入口。

## 8. 当前验证证据

- 自动化：控制台 API、安全边界、进程复用、安装/分发、Hub 入口和构建共 46 项后端测试通过；实例切换与定向控制共 6 项前端测试通过。
- 前端：TypeScript 类型检查、共享 UI 契约和 Player-only Vite 构建通过；产物仅包含 `player.html`、`capture.html`、`console.html` 及编译资源。
- Windows 原生冒烟：签名 Player EXE 以一个 1240×780 原生控制台窗口连接两个隔离实例；实例进程、loopback 端口和数据根均不同，两个工作页面只允许精确控制台 origin 嵌入。
- 生命周期：控制台异常退出后可见原生窗口立即回收，两个无任务工作进程在宽限期内退出，未留下候选测试进程。显式确认关闭的新语义正在按本规范补充自动化与真实宿主证据。
- 显式关闭专项：单实例与多实例确认路径的前端测试、控制台停止全部 Worker 的服务测试、原生关闭握手源码契约及 Player-only API 白名单通过；重新冻结的 Windows 候选完成空闲 `WM_CLOSE → WebView 确认 → ASGI 清理 → Player/原生宿主退出` 冒烟，关闭后交付目录可立即改名。多活动实例的真实业务任务确认关闭仍保留在发布候选完成门。
- 尚待发布候选完成门：真实账号任务的运行/暂停/继续/停止、两扇同名目标窗口分别绑定、显式关闭的取消/确认/失败三条路径，以及断开 IDE/开发后端后的最终离线验收。
