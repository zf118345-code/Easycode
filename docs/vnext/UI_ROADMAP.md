# EasyCode UI 优化路线

状态：UI-26 已完成并通过浏览器验证  
适用范围：首个正式版本的开发端、Windows Player 与 Android Player  
非目标：页面拓扑、浏览器 DOM 专用自动化、iOS/macOS、商业授权界面

## 总体原则

- 功能先于装饰：任何已有能力不得因界面精简而消失；低频能力进入菜单、命令或高级区域。
- 顶部菜单负责全面，当前页面只保留高频动作和当前对象操作。
- IDE 与 Player 复用 Control、字段契约、状态和错误语义，但按桌面与移动端分别编排页面。
- 同一种对象保持相同的选择、编辑、捕获、确认、错误恢复方式。
- 业务确认、成功和失败提示使用 EasyCode 自身组件；系统权限授权仍使用系统界面。
- 插件使用受约束的贡献槽位，不允许任意破坏应用外壳和基础交互。
- 每阶段只做一次完整审查和一次针对性修正，避免无终点的视觉打磨。

## 阶段与验收

当前进度：UI-1 至 UI-26 已完成。UI-21 把“信息必须挣得位置”写入设计约束：同一事实只保留一个主展示位置，ID、哈希、路径、适配器名称与采集来源等技术信息改为按需查看；工作区不再默认套用三栏，运行目标在宽屏采用“目标列表—设置”两栏，资源技术元数据折叠，普通继承目标、函数库逐行插入按钮和扩展列表包 ID 不再常驻。全局屏蔽浏览器原生右键菜单；文本输入器提供应用内复制、剪切、粘贴与全选，语句右键复用同一组对象操作，已有函数与文件夹业务菜单保持不变，空白区域不凭空制造命令。

UI-22 从真实用户任务继续收敛信息：语句检查器不再重复函数库入口；项目变量默认只展示名称、类型和初始值，说明、范围、正则及候选值完整保留在可识别已设置状态的折叠区；Player 不再重复绑定来源；资源搜索与空状态移除稳定 ID、元数据等实现措辞；运行记录只常驻采集时间、画面和目标，帧空间版本、片段及文件大小进入技术信息；扩展页优先展示函数用途、参数、适用目标、状态和权限，函数 ID、宿主模块、执行超时及声明贡献进入开发者信息。无图像/OCR回放语句被修正为正常空目录，不再产生 422 控制台错误，非法分析请求仍严格拒绝。全量前端 106 个测试文件、544 项测试、类型检查、lint、生产构建、回放目录后端测试与 Impeccable 两阶段扫描通过；DDT 在 1440×900 与 760×820 完成程序、资源、变量、Player、运行记录和扩展真实浏览器走查，最终浏览器控制台 0 警告、0 错误。UI-22 晚于 G16 冻结产物，仍须在 UI 冻结后重新构建最终候选。

UI-23 已完成参数信息克制与自然输入垂直切片：共享函数契约声明主要、高级、条件和内部参数，所有自由值槽获得类型化 placeholder/帮助；普通文字可以直接混入变量和纯值结果，持续时间可以由数值变量与单位构造；结果绑定只能选择兼容局部变量或新建局部变量。用户编辑引用时统一使用可复制的普通 `[]`，只读详情与流程正文以不写回数据的半框强调动态片段；等待值、赋值、条件和返回绑定使用同一语义投影。函数库也直接投影同一契约语句，以未配置的参数名作为半框占位（例如“等待⌜时长⌟”），分类只负责归组，技术限定名继续可搜索但不与主名称并列展示。危险与会改变数据的选项继续按上下文显式出现，不以隐藏换取假简洁。前端全量 106 个测试文件、552 项测试、类型检查、生产构建和 Impeccable 扫描通过；相关 Python 契约、Player、纯值运行时与 Android 交付 134 项测试通过。隔离项目完成混合文本、变量持续时间、时区占位符、高级设置、结果绑定、函数库技术名搜索和左中右语义一致性的真实浏览器操作；Android 真机本机输入仍沿用最终发布阶段的独立证据门。

UI-24 完成应用外壳最后一轮结构收口：移除顶栏重复的项目/工作区面包屑；函数标题和语句搜索只占中央流程列，右侧检查器保持独立表头；最右侧新增检查器活动按钮。左侧活动图标统一承担工作区切换和左栏开关，所有工作区继续共享一个持久化宽度；低于 1100px 时左右辅助栏改为互斥的覆盖式抽屉，不压缩或共同遮住正文。状态栏严格收口到 24px 并固定在网格末行，消除底部空白带。函数目录撤销标签上方的“控制结构”专区，把结构条目并入“官方”并按“流程控制 / 变量 / 消息”归类；变量入口进一步按真实任务拆成“新建局部变量”和“修改变量”，后者只列出插入位置可见的局部变量与项目变量，同时保持底层强类型结构命令不变。前端 106 个测试文件、556 项测试、类型检查、lint 和生产构建通过；真实浏览器验证左栏 260→320px 正向拖拽、资源/程序共享宽度、900px 覆盖抽屉正文宽度不变、360px 检查器抽屉、左右抽屉互斥和状态栏贴合视口底边。证据位于 `output/playwright/easycode-program-wide.png` 与 `output/playwright/easycode-program-narrow.png`。

UI-25 统一工作区详情栏、目录层级和结果绑定：资源、回放、扩展、计划与 Player 的第三详情栏由外壳最右侧活动按钮统一控制，窄屏统一为覆盖抽屉，页面内部不再重复按钮；两栏任务页保持两栏。官方函数领域标题大于等于子函数字号，子函数在展开图标之后缩进。目标范围在流程正文只用语义文字与克制颜色区分，不显示装饰图标。调用返回绑定收敛为一个输入框：留空不保存，普通名称新建局部变量，`@`/`[` 选择类型兼容的已有局部变量。函数契约为全部 215 个输入参数提供能说明实际值或格式的默认文案与 placeholder，禁止“默认配置”“无结果”等空洞措辞；视觉文案与无障碍名称共用同一语义。前端 107 个测试文件、558 项测试、类型检查、lint 与生产构建通过，契约后端 22 项测试通过；真实浏览器逐页验证程序、资源、运行记录、计划、扩展和 Player 的统一详情栏，以及 900×820 覆盖抽屉、返回值 `@` 补全和时区真实默认值，控制台 0 警告、0 错误。证据位于 `output/playwright/easycode-ui25-library.png`、`output/playwright/easycode-ui25-player-detail.png`、`output/playwright/easycode-ui25-player-narrow.png` 与 `output/playwright/easycode-ui25-final-program.png`。

UI-26 已把跨页面一致性从视觉约定提升为公共组件和接入门槛：共享工作区骨架、按钮、图标按钮、输入、列表项、检查器字段、Control 与反馈状态使用统一组件和令牌；开发端与 Player 共享字段契约和状态语义，但保留符合桌面/移动输入方式的布局。`ui:contract` 与 Impeccable 反模式检查阻止页面重新复制局部样式。真实浏览器逐页走查程序、资源、变量、目标、Player、运行记录、运行中心和扩展，检查器批量态覆盖 1680×940 与 1280×720，无障碍门和开发端/Player 生产构建通过。权威需求、允许模板、平台差异和完成标准见 [统一界面系统](UI_SYSTEM.md)。

### UI-1 应用外壳与导航（已完成）

- 顶部菜单包含完整命令，支持鼠标与标准键盘导航。
- 工作区按“创作、运行与维护、诊断”分组，常用入口优先。
- 顶部操作按窗口宽度逐级压缩，不能遮挡、横向溢出或失去可访问名称。
- 左侧栏、右侧检查器和底部面板方向一致、尺寸可调且合理持久化。

### UI-2 值与参数编辑（已完成）

- 普通值、变量、表达式和函数结果使用统一值输入体验。
- 坐标、区域、列表、字典和结构化对象使用组合 Control，同时允许合法变量与表达式。
- 枚举保持直接选择；只有契约允许动态值时才出现动态入口。
- 帮助、补全、类型、错误和来源就地显示，不恢复“计算值”二级迷宫。

### UI-3 流程与函数编辑（已完成）

- 函数库、结构化语句、选择、插入、移动、批量操作和检查器形成完整闭环。
- 条件、分支、循环、异常和监听在不依赖连线的前提下保持层级清楚。
- 长函数、长名称、错误、断点和当前执行位置均可快速定位。

### UI-4 捕获器与运行目标（已完成）

- Windows、ADB 与 Android 本机统一“进入捕获—选择—调整—确认/取消—原子回填”心智模型。
- 图像、坐标、区域、控件、文件和录制共享视觉语言，并保留平台能力差异说明。
- 权限缺失、目标断开、控件树不可用和采集失败均有项目内恢复路径。

### UI-5 Player 制作与运行（已完成）

- 作者配置与终端表单使用同一字段契约；桌面和移动端分别响应式编排。
- 开放捕获、权限、运行、暂停、停止、计划与更新均具有明确状态和失败恢复。
- Android 悬浮采集优先展示目标原画面，EasyCode 控件在截图瞬间隐藏。

### UI-6 业务工作区（已完成）

- 资源、变量、目标、运行记录、计划、扩展和 Player 均使用适合任务的列表/详情或对话框布局。
- 空白、加载、无权限、离线、冲突、部分失败和大量数据状态完整。
- 扩展函数与官方函数清楚区分；插件只能进入声明过的工作区、命令、设置与诊断槽位。

### UI-7 引导、帮助与最终打磨（已完成）

- 首次使用、快捷键、命令搜索、上下文帮助和错误文档可互相到达。
- 完成键盘、焦点、对比度、缩放、中文长文本和屏幕阅读器检查。
- 完成密度、排版、图标、动效和主题的最终统一，不改变已冻结工作流。

### UI-8 启动性能与生产加载（已完成）

- 首次打开只加载应用外壳和当前工作区；运行记录、计划、扩展与 Player 等低频工作区按需加载。
- 工作区首次加载有一致的就地等待状态，失败后可重试，不出现空白画面。
- 生产构建不再产生可避免的单块体积警告，并验证工作区切换不会丢失状态或命令入口。

### UI-9 核心工作区可读性与密度（已完成）

- 程序目录、语句正文、层级提示和检查器在紧凑布局下仍有清楚的主次关系，不依赖极小或低对比文字传达必要信息。
- 长函数名、长语句和跨目标说明可快速辨认；截断内容有可达的完整名称，不挤压主要操作。
- 未选择语句、窄窗口和 125%/150% 缩放时，编辑区与检查器保持合理空间利用，不产生遮挡或水平溢出。

### UI-10 反馈、确认与恢复路径（已完成）

- 业务成功、失败和确认只使用 EasyCode 内部反馈面，不调用 Windows 默认弹窗；系统权限和 Android 前台服务通知保留系统要求的原生入口。
- 错误使用可立即感知的语义并提供恢复动作，普通状态更新保持安静，不能让同一结果同时出现多份提示。
- 对话框和抽屉覆盖键盘退出、焦点圈定与返回原触发点；破坏性操作明确影响范围且不会因误触直接执行。

### UI-11 表单 Control 与术语收口（已完成）

- 普通参数保持统一输入器；列表、字典、JSON 和命名结构仅在需要逐项编辑时进入结构化界面，不恢复固定值/变量/计算三模式。
- 枚举继续直接选择，捕获动作使用具体名称；比较、空值和数值失败语义一致，不偷偷写入零值。
- 高级能力保留在类型补全、结构化子项和帮助中，初级用户无需先理解内部 AST 或计算目录。

### UI-12 跨端 Player 终端收尾（已完成）

- 以真实手机宽度审查 Player 的页面切换、字段填写、捕获动作、权限状态、运行反馈和底部主操作。
- 捕获入口和普通字段保持同一 Control 语言，但触控目标、安全区和移动端滚动按 Android 约束单独编排。
- 桌面 Player 与 Android Player 共享语义和字段状态，不强行共享会损害移动端空间的整页布局。

### UI-13 全工作区一致性与发布前视觉回归（已完成）

- 逐页核对标题、列表、详情、空状态、表单、菜单、对话框和底部状态的层级与术语，优先消除同义不同形和无意义重复。
- 对共享 Control、按钮、焦点、禁用、错误和长文本状态做跨工作区回归，修复会影响实际操作的尺寸、遮挡、方向和响应式问题。
- 以代表性桌面与窄屏尺寸完成最终视觉证据；只处理可验证的问题，不在本阶段重做已冻结的领域工作流。

### UI-14 关键任务链与实际操作摩擦（已完成）

- 从程序选择、参数编辑、检查、运行、诊断跳转到发布与 Player 配置，按连续任务而非孤立页面检查上下文是否丢失。
- 记录每条路径中的必要点击、重复确认、不可解释术语和失去返回位置问题，只删减不承载业务语义的步骤。
- 分别验证鼠标与键盘主路径；项目数据修改必须可撤销或在隔离测试项目完成，不以破坏 DDT 数据换取演示结果。

### UI-15 最终响应式矩阵与边界状态（已完成）

- 在 1920×1080、1440×900、1024×768、700×700 和 600×700 重走应用外壳与代表性工作区，核对遮挡、溢出和最小可操作尺寸。
- 检查加载、空白、错误、禁用、长中文、长路径与大量列表的边界状态，保证状态发生变化时布局不跳出可视区域。
- 整理最终截图与自动/浏览器/宿主证据边界；本阶段只修真实回归，不把未执行的真机能力写成视觉验收通过。

### UI-16 视觉一致性与信息密度收口（已完成）

- 在不改变冻结工作流的前提下，统一页面标题、分区标题、说明文字、标签、控件和状态的层级，消除依赖过小字号或大片空白形成的假密度。
- 逐页检查列表行高、表单节奏、边框数量、强调色使用和空状态位置；高频操作优先，低频信息保持可达但不抢占视觉注意力。
- 对开发端、桌面 Player 与 Android Player 的共享 Control 做视觉对照，以同语义同反馈为准，不强求跨平台像素完全相同。

### UI-17 大型项目密度与定位（已完成）

- 使用既有 1,001 个项目函数、10,000 条语句与 10,000 个资源固定数据集，真实检查搜索、滚动、选择、跳转和返回位置，不重新生成或污染 DDT。
- 覆盖长中文名称、长路径、同名前缀、筛选无结果、快速连续选择和窄屏抽屉；信息允许截断，但完整值必须可通过焦点、悬浮或详情获取。
- 检查虚拟列表滚动位置、选中状态和焦点在刷新或切换详情后不发生意外跳转，并为可复现缺陷补齐交互测试。

### UI-18 发布前任务流验收与 UI 冻结（已完成）

- 在 DDT 上按普通作者顺序复走“选函数→配值→检查→运行/诊断”和“资源定位→Player 开放→终端填写/捕获”两条主链，确认上下文、焦点和返回位置连续。
- 核对顶部菜单、命令搜索、快捷键、页面内高频入口与禁用原因一致；只修阻断、重复、歧义或不可恢复问题，不再扩大视觉风格范围。
- 输出最终桌面/窄屏截图和残余环境边界，完成 UI 代码冻结；Android 系统权限页、真机执行和生产签名仍沿用发布门，不以浏览器外观验收代替。

### UI-19 Codex 风格任务聚焦与目标语义（已完成）

- 宽屏保留函数库、流程和检查器三栏；中窄屏只常驻流程，把函数库和检查器分别作为显式抽屉，避免辅助面板永久侵占主任务空间。
- “项目默认目标”和“当前语句实际目标”分开显示；跨目标语句明确标注继承或覆盖关系，不再用“当前目标”混指两层状态。
- 删除重复入口、提升函数名称与数量的可读性，并让空检查器提供可执行的下一步；不改变 ProgramDocument、目标解析或运行语义。

### UI-20 视觉系统与流程语义收口（已完成）

- 全应用使用同一组正文、辅助文字、占位符、错误色和字号令牌，消除各工作区自行继承或局部覆盖导致的视觉漂移。
- 活动栏按任务阶段分组，状态栏只保留作者当前需要判断的状态；格式版本与 revision 继续可查，但不长期争夺注意力。
- 普通函数调用保持安静，结构语句和目标作用域仅通过克制底色、字重与缩进线建立层级；选中、运行和失败状态继续保持可区分。
- 本阶段不重排资源、目标、Player 和扩展的领域布局；少量数据空间利用率、跨工作区目录结构和检查器 Control 深度统一分别进入后续结构阶段。

### UI-21 信息克制、任务布局与应用内右键菜单（已完成）

- 所有常驻信息必须回答“用户现在据此做什么决定或操作”；同一事实只允许一个主展示位置，技术标识与来源降级为悬浮提示、折叠技术信息或诊断内容。
- 按任务选择布局，不把“左列表—中展示—右详情”当成页面模板；运行目标宽屏采用列表与设置两栏，资源、Player 与扩展只保留当前任务需要的层级。
- 最终桌面容器全局阻止浏览器原生右键菜单；输入器提供 EasyCode 文本命令，语句右键复用移动、复制、提取与删除等对象操作，其他业务对象保留领域菜单，空白处保持安静。
- 右键菜单不得成为低频命令垃圾箱；只有当命令与指针下对象直接相关、结果可撤销或影响明确时才进入。

### UI-24 工作台边界、侧栏开关与目录归类（已完成）

- 顶栏不重复当前工作区；中央函数工具条不得跨入检查器，检查器由独立右侧活动按钮控制。
- 点击其他活动图标切换并展开对应左栏，再次点击当前图标收起；所有工作区共享一个宽度，窄屏使用覆盖抽屉。
- 控制结构、赋值和消息监听在“官方”标签下按用户任务归类，界面合并不能改变 ProgramDocument 的结构命令语义。
- 状态栏固定为 24px；宽屏、窄屏、拖拽方向、焦点恢复和实际可见区域必须用真实浏览器尺寸验证。

## 固定验证矩阵

每阶段至少验证：

- 1920×1080、1440×900、1024×768、700×700；Windows 125% 与 150% 缩放。
- 鼠标、纯键盘、长中文名称、空白/加载/错误/禁用状态。
- 页面无水平溢出，焦点可见，隐藏文字后按钮仍有可访问名称和提示。
- 对涉及终端的阶段，分别记录 Windows、模拟器/ADB、Android 真机证据。

## 完成定义

自动测试全绿只是基础。阶段完成还必须包含真实浏览器操作、代表性尺寸截图、关键任务走通和失败状态检查；未验证的平台能力明确标记为“未验证”或“受环境阻塞”，不得写成已完成。
