# 结构化值与纯计算表达式

`color` 固定值允许直接填写 `#RGB`、`#RRGGBB` 或 `#RRGGBBAA`；输入器将其编译为强类型 `color` Record，而不是字符串。颜色变量与结果继续通过 `@` 引用，运行时取色使用官方函数 `颜色.读取`。

## 1. 定位

值表达式负责回答“一个参数、赋值、条件叶或返回值怎样由已有值计算出来”。它是 `ProgramDocument` 中递归、强类型、无副作用的值结构，不是保存到项目中的公式字符串、源码或 Python 片段。IDE 可以提供看起来像单行输入框的结构化表达式投影：用户键入文字、引用名和运算符后，只有在类型与引用解析成功时才提交为稳定值节点；未完成文字只存在于当前编辑草稿，不成为第二个程序事实。

底层必须允许所有已经批准的纯值操作完整递归组合，避免项目在复杂坐标、文本、时间、集合和条件取值场景中遇到人为能力墙。界面负责把复杂结构摘要、折叠或提取，不得通过限制表达能力来换取表面简洁。

```text
用户看到：
点击位置 · 根据窗口中心和按钮偏移计算

ProgramDocument：
point_add(
  window_center,
  point(x = button_offset_x, y = 12)
)
```

用户通过统一输入器、候选和类型化 Control 配置值；可以输入可读的括号、引号与运算符，但不会接触内部操作 ID，也不会把输入文字保存成源码。

## 2. 值来源

一个值节点可以来自：

- 显式未配置状态 `unset`；
- 文本、整数、小数、布尔、时间点、持续时间、坐标、区域等常量；
- 局部符号、项目变量、资源、目标、控件、实例等稳定引用；
- 命名记录成员、列表项、字典值或可选值；
- 记录、列表、字典等结构化值构造；
- 基于以上已有值继续组合的纯值表达式。

每个持久化、可配置的值节点拥有稳定 `value_id`。节点移动和结构化提取默认保留 ID，复制产生新 ID；显示摘要、折叠状态和所在屏幕位置不是长期绑定键。

## 3. 完整递归组合

批准进入核心表达式注册表的纯操作可以把其他兼容值表达式作为输入，且结果可以继续成为上层表达式输入。完整目标至少覆盖：

| 领域 | 纯值能力 |
| --- | --- |
| 数值 | 加减乘除、余数、取整、范围限制、最小/最大值和明确数值转换 |
| 文本 | 组合、替换、截取、大小写、去空白、长度和格式化 |
| 时间 | 时间点与持续时间的加减、差值、分量读取和明确时区转换 |
| 几何 | 坐标/区域构造、偏移、缩放、中心/边界读取和参考尺寸换算 |
| 选择 | 根据无副作用条件选择两个兼容值、为可选值提供显式默认值 |
| 结构 | 命名记录成员、列表项、字典值、记录/列表/字典构造与不可变更新 |
| 集合 | 已冻结的筛选、转换、排序、分组和统计，遵循 `COLLECTIONS.md` |
| 类型 | 契约批准且结果明确的安全转换，不做隐式真假或静默损失转换 |
| 引用 | `core.file_ref_child.v1` 从已授权 `DirectoryReference` 与安全相对位置派生能力不扩大的 `FileReference`；不访问文件系统 |
| JSON | `core.json_parse_text.v1` 把文本确定性解析为 `optional<json>`；非法 JSON 返回无结果，不静默猜测类型 |

递归组合没有面向产品的人为浅层上限，也不规定“超过 N 层就必须改写”。一个兼容的纯计算只要通过类型、引用、循环和资源预算检查，就能被 ProgramDocument 表达并由 ECIR 执行。

基础转换与几何语义固定如下：`core.value_to_text.v1` 只接收文本、有限数值、百分比、布尔、日期/时间、持续时间和枚举等基础标量，使用跨平台稳定格式；布尔输出小写 `true/false`，日期/时间使用 ISO 值，持续时间输出不带单位的毫秒数，有限小数使用不依赖区域设置的十进制文本；不得把资源、目标、文件或其他引用对象的内部结构串行化成文本。`core.text_to_int.v1` 与 `core.text_to_float.v1` 会去除首尾空白并按相同 ASCII 数字语法严格解析完整文本，整数还必须处于 64 位有符号范围，小数必须有限；解析失败返回正常无结果，不返回 `0`，也不抛出业务异常。`core.text_split.v1` 要求非空分隔符并保留开头、中间和结尾的空项，`core.text_join.v1` 只接收文本列表，因此两个 Runtime 不会因宿主语言默认拆分行为不同而产生漂移。`core.point_scale.v1` 与 `core.rect_scale.v1` 分别缩放横纵坐标及区域尺寸，并保留来源目标、空间版本等附加坐标元数据；跨目标使用仍由类型和来源检查阻止。

## 4. 与普通函数的边界

官方、项目和扩展函数即使返回简单值，也必须作为独立 `call` 语句出现并先绑定结果。截图、OCR、等待、输入、文件、消息、目标访问、随机数、当前时间读取以及其他可能失败、阻塞、访问外部状态或产生副作用的行为不能隐藏在值表达式里。

扩展不能注册私有表达式语法或把任意 Python 表达式塞入值节点。需要自定义算法时，扩展提供带强类型契约的普通函数；需要复用结构化纯计算时，开发者可以把它提取为赋值或返回值明确的项目函数。

表达式操作由核心版本化注册表治理。新增操作必须声明稳定操作 ID、稳定 `operation_input_id`、输入/输出类型、空值规则、确定性、求值顺序、来源目标传播、跨平台语义、ECIR 降低方式、诊断和测试，不能只增加一个前端选项。注册表版本和内容哈希进入确定性编译、缓存与发布签名输入。

## 5. 类型、可选值与条件选择

每个节点在编译前都有确定类型。左右输入不兼容、可能丢失信息的隐式转换、缺失序号/键以及跨目标空间值混用，都必须定位到具体 `value_id` 并在运行前处理。

可选值成员访问采用两种用途一致、失败语义不同的写法：无结果属于正常业务分支时，先用“有结果”条件收窄，并只在成立分支读取成员；无结果代表当前流程前提被破坏时，可以在需要该成员的参数或表达式中直接读取。直接读取是强类型的严格成员访问，不把无结果转换为假值、空字符串、零或伪造坐标；Runtime 求值到空来源时必须以稳定 `runtime.optional_empty` 结构化异常停止当前运行，并把错误定位到消费该值的语句。需要在无结果时继续计算时，用户必须显式配置默认值。条件选择只计算被选中的分支，并要求两个分支能归一到同一结果类型。它不允许把普通函数调用藏进任一分支。

结构化集合的类型、快照、不可变更新和 JSON 边界以 [`COLLECTIONS.md`](COLLECTIONS.md) 为准。

## 6. 编辑投影与提取

参数 Control 使用统一的结构化表达式输入器，不再要求用户先在“固定值 / 已有值 / 计算值”三个常驻模式之间做实现层选择。输入器围绕当前类型化值槽同时提供：直接填写、插入局部或项目变量、插入已有结果及其安全成员，以及组合核心纯操作。键盘输入、候选点击和就地帮助是同一 ProgramDocument 值树的不同编辑投影，不能形成三份平行数据。

这套输入器适用于所有自由值槽，不局限于条件：函数参数、赋值、返回值、列表项、字典键和值、结构字段以及纯值操作输入都按同一规则递归复用。列表、字典和结构化对象保留各自的多行组织器；组织器只负责增删、排序和层级，能使用统一输入器的叶子继续复用它。坐标、区域、路径、资源、控件、文件和目标引用仍保留选择、捕获或系统授权等专用动作，但值本身使用同一个类型化输入表面，可输入 `@` 选择兼容变量/结果或使用已批准的纯值操作；专用动作回填的也是同一个值槽，不能再出现“填写 / 变量 / 计算”来源切换。契约枚举是作者对行为模式的固定选择，只显示单纯下拉，不提供变量或纯值操作入口；其所在结构的其他自由子字段不受影响。

坐标和区域的直接值采用明确构造写法，例如 `坐标(480, 320)` 与 `区域(100, 80, 640, 360)`；也可使用 `[局部 · 登录按钮].中心`、`坐标.偏移([局部 · 登录按钮].中心, 10, 20)` 等引用或派生值。界面不得把坐标/区域拆成只能填写数字、不能引用结果的封闭表单。

统一输入器不再设置“更多操作”或第二套聚焦表单。直接值、稳定引用、成员访问、四则运算、比较、布尔组合以及核心批准的纯值操作，都通过同一输入表面编辑；纯值操作使用类型化的 `命名空间.操作(参数…)` 投影，例如 `文本.替换(@公告, "旧", "新")`、`数值.四舍五入(@耗时, 2)` 和 `列表.追加(@副本, "经验副本")`。输入文字只是未提交草稿，确认后必须解析、绑定并保存为原有强类型值节点，不能把公式字符串写入 ProgramDocument。

输入表面在只读与编辑状态之间不得改变所在布局：进入编辑只出现光标、补全和就近诊断，不增加确认、取消、变量或操作按钮。单行值使用 Enter 提交、Escape 恢复和有效失焦提交；多行文本保留 Enter 换行并使用 Ctrl+Enter 提交。输入中的草稿可以暂时不完整或暂时不是字段最终类型，父级已保存值的旧诊断在编辑期间不得继续把输入框标红；只有用户确认或有效失焦时才校验完整结果。确认失败必须原样保留草稿和焦点，不能阻止后续字符、恢复旧值或静默提交半成品；中文输入法组合期间的 Enter 只交给输入法。参数标题旁的帮助按钮按当前期望类型展示写法和示例。键入 `@` 时只列当前作用域中的变量与结果本体，不把任意层级字段提前平铺；选中一个结构化值后键入 `.`，才按其类型契约列出当前层的直接字段，选择结构字段后可继续键入 `.` 逐级进入。未收窄的可选结果仍显示并允许选择真实字段，同时就近说明“直接使用时若无结果，本次运行会在该语句失败；若无结果是正常分支，请先判断有结果”。进入成立分支后，同一字段不再显示该风险说明。键入命名空间和 `.` 还可以打开类型兼容的纯操作补全，键入 `(` 后显示参数名称和类型。补全、帮助和完整语法文档都从同一版本化操作注册表投影，不能维护手写的第二份能力清单。

完整操作名称、参数顺序和用途见自动生成的 [`EXPRESSION_SYNTAX.md`](EXPRESSION_SYNTAX.md)。

顶层文本字段默认把无明确表达式触发的内容解释为普通文本，因此普通日志、路径和消息不要求双引号。纯操作的文本参数使用成对引号以消除逗号、括号和运算符歧义；输入器可以自动补齐。中文和 ASCII 句号、逗号、括号及引号可以作为编辑别名，但规范化只能发生在字符串外部。显示名称和本地化别名只用于草稿绑定，持久化仍使用稳定操作、输入槽、符号和字段 ID。

字符串槽还允许把普通文字与已确认的引用/成员/纯值结果写在同一输入面中，例如 `当前体力为 [项目 · 当前体力]`。普通文字片段保持文本字面量，非文本基础标量先经 `core.value_to_text.v1`，各片段再经 `core.text_concat.v1` 连接；引用对象、资源和其他不允许转文本的类型继续给出就地错误。它只是既有值树的输入与摘要投影，不增加 `template` 持久化节点。持续时间输入中的 `毫秒 / 秒 / 分钟` 是类型化单位，例如 `[局部 · 等待秒数] 秒`，不能按普通字符串连接或依赖宿主区域设置解释。普通方括号 `[]` 是用户可输入、可复制的正式引用语法；只读界面可以用半框视觉强调动态片段，但不得把装饰字符写回项目数据。

Program Service 返回文档快照时，从同一权威注册表按当前文档实际引用内容投影展示元数据：纯操作包含中文短名、规范 `命名空间.动作` 名和各稳定输入槽的中文参数名，命名记录包含记录类型与字段的中文名。加载、结构命令、撤销和重做都返回同一契约，因此中央摘要、检查器、聚焦编辑和刷新后的页面不会各自维护名称表。内部稳定 ID 只允许出现在复制 ID、诊断详情或开发日志中；展示元数据缺失时应显示明确不可用状态并阻止误编辑，不能把内部 ID 降级成界面文字。

引用输入必须经候选确认或由 EasyCode 自己复制的稳定词元恢复；同名、歧义或当前作用域不可用的文字不得在失焦时静默猜成引用。确认后的词元显示来源、名称和必要的类型提示，底层只保存稳定 ID。直接文字按当前期望类型解释；无明确期望类型的赋值先推断并显示类型，用户确认后再形成局部符号契约。

条件根使用期望结果为布尔值的同一输入器，可投影比较、全部满足、任一满足和取反；“并且 / 或者 / 非”既可键入，也可从可访问操作入口插入。布尔条件允许先插入整数、文本、日期等可比较的纯操作作为中间操作数，再继续输入 `==`、`!=`、`>`、`<` 等比较符；编辑中的草稿不得因为尚未形成完整布尔值而被阻止或覆盖，只在用户确认或有效失焦提交时验证最终结果是否为布尔值。逐步使用候选、从 EasyCode 复制后粘贴以及直接粘入完整表达式必须走同一套按需目录解析；粘贴不得依赖此前是否点击过候选。目录初次打开不默认选择第一项。普通函数、I/O、等待或目标访问即使在搜索中被发现，也只能提供“插入独立语句并引用结果”的结构化动作，不能伪装成内嵌表达式。

简单与复杂纯计算使用同一输入器和类型化补全；提交后以可读词元和折行摘要展示。集合固定值仍由多行容器管理增删与排序，高阶筛选、转换、排序和分组可以使用带类型化逐项作用域的表达式语法。中央语句只显示业务摘要，不展开整棵值树。

用户可以把复杂子树显式提取为：

- 一条独立的“计算并赋值”语句；或
- 一个返回单一值的项目函数。

提取是可撤销的结构化重构，不是能力限制。提取前必须证明作用域、求值次数、条件选择的惰性边界、可选值收窄、空值、错误时机和来源目标保持等价；无法证明时不提供该提取目标，并解释原因，不能让普通确认框放行语义变化。被移动的现有值节点必须保留 `value_id`，替换原位置的新引用节点获得新 ID；Player 绑定随同一项目事务原子迁移，无法迁移时整个重构回滚。

稳定 ID 生命周期固定为：修改同一值的载荷保留当前 ID；包装现有节点时旧节点作为子节点保留 ID、包装器获得新 ID；解包时被提升子节点保留 ID、包装器 ID 失效；重排或移动子树保留全部现有 ID；深复制递归生成新 ID；删除后的 ID 不复用；撤销/重做恢复原对象、ID、引用与 Player 影响状态。切换来源或操作类型时，当前位置根 ID 是否保留由“同一类型化配置槽”规则决定，删除的后代不能被新子树冒用。

## 7. Player 精确绑定

Player 设计器可以暴露完整参数，也可以只暴露表达式中的某个可配置值节点。作者侧绑定契约显式区分参数根覆盖、嵌套值覆盖、入口参数、项目变量、资源和目标等类别；嵌套绑定使用稳定 `function_id + statement_id + parameter_id + value_id`，不依赖摘要文字、树路径或当前层数。Compiler Service 为每个已发布 `control_id` 生成签名 ECIR 覆盖槽；Player 运行端只认识 Control 与覆盖槽，不读取 ProgramDocument。

Player 运行方案只覆盖开发者明确发布的签名值槽，并继续接受原类型、约束、Control 和平台能力校验。它不能改变操作符、来源种类、引用目标、值树结构或未发布节点。父节点与其后代不能在同一 Player Schema 中形成重叠覆盖；设计器必须定位冲突并要求开发者选择一个层级。重排、折叠、显示名修改和不相关节点插入不得破坏绑定；复制节点不会意外继承原 Player 暴露。过期或类型指纹不兼容的运行方案阻止运行，不能静默回退开发者默认值。

## 8. 安全与性能边界

系统仍需要技术安全门，但这些门由 Harness 根据真实数据形成高位预算，不作为普通用户的表达能力分级：

- Program Service 拒绝直接或间接循环引用；
- 增量类型检查和摘要生成只重算受影响子树；
- Compiler Service 对节点数量、递归深度、编译时间和生成 ECIR 体积设置可诊断、可测试的保护预算；
- Runtime 对集合规模、内存、取消和长计算设置安全检查点；
- 接近预算时先提示摘要、提取或扩展函数建议，超出预算时精确定位高成本子树；
- 预算值由基线硬件、极端样例和 Android 目标验证后冻结，不在产品规格中伪造任意小上限。

## 9. 需求

- `[REQ-EXP-001]` ProgramDocument 使用递归、强类型、无副作用值节点表达参数、赋值、条件叶和返回值；用户可以在统一输入器中编辑尚未提交的临时文字，但项目不保存公式文本、源码或其他平行事实。
- `[REQ-EXP-002]` 所有持久化可配置值节点拥有稳定 `value_id`；移动保留、复制重建，诊断、调试和 Player 可以定位具体节点。
- `[REQ-EXP-003]` 直接值、已有值和纯值操作使用同一类型化来源模型；所有自由值 Control 以布局稳定的统一结构化表达式输入器编辑并提交结构化命令，不显示确认/取消/“填写、变量、计算”来源/更多操作按钮，不生成平行字段或持久化字符串公式。资源、控件、坐标、区域、路径、文件和目标引用可并列提供专用选择/捕获动作，但动作只回填同一值槽。自由文字只有解析为唯一、类型兼容的稳定节点后才能提交；固定候选枚举只接受契约字面值。
- `[REQ-EXP-004]` 核心批准的数值、文本、时间、几何、选择、结构、类型和集合纯操作允许完整递归组合，且在 IDE、Compiler、ECIR 与 Player 中语义一致。
- `[REQ-EXP-005]` 普通官方、项目和扩展函数、I/O、等待、目标访问和其他非纯行为不能嵌入值表达式。
- `[REQ-EXP-006]` 表达式严格按类型检查，不允许隐式真假转换、静默损失转换或跨目标空间值混用。未收窄可选值的成员访问是显式的严格消费语义：来源为空时跨 Runtime 统一抛出 `runtime.optional_empty` 并停止当前运行，不得伪造默认值；存在性条件收窄继续用于把无结果作为正常业务分支处理。
- `[REQ-EXP-007]` 条件选择只求值被选分支；可选值默认必须显式配置，并保持正常无结果与异常分离。
- `[REQ-EXP-008]` 扩展不能增加私有表达式语法；新的核心纯操作必须具备版本化契约、跨平台降低和 Harness 证据。
- `[REQ-EXP-009]` 界面通过摘要、折叠、面包屑和聚焦管理复杂度，不以浅层嵌套上限缩减底层能力。
- `[REQ-EXP-019]` Program 快照按引用携带操作、输入槽、记录类型和字段的权威中文展示元数据；所有用户表面复用该投影，缺失时显示明确不可用状态，内部稳定 ID 不得作为中文名称的回退值。
- `[REQ-EXP-020]` 字符串槽可以在一个输入面组合普通文字、稳定引用、成员和纯值结果，并确定性降低为文本转换与拼接值树；持续时间可以由数值表达式与毫秒/秒/分钟单位构造。两者均不得保存公式或模板源码，且必须在 Python 与 Android Runtime 中等价执行。
- `[REQ-EXP-021]` `@` 补全只显示作用域内的变量和结果本体；字段只能在选中结构化值后通过 `.` 按当前层逐级展开。未收窄可选结果的真实字段目录必须可发现、可提交，并说明直接使用的空值失败语义及可选的“有结果”分支写法；所有自由值 Control 复用同一规则。
- `[REQ-EXP-022]` 值目录必须按注册表版本与哈希返回全局语法发现契约，包含固定命名空间、全部核心纯操作的搜索元数据与兼容状态、当前类型直接值示例、运算符和参数枚举；输入器、帮助、生成文档和 Harness 不得维护平权手写目录。
- `[REQ-EXP-023]` `Ctrl+Space` 在任意自由值输入位置打开零记忆目录；`@`、值后的 `.`、命名空间与 `命名空间.`、操作参数位置和已有操作数分别触发值、字段、操作、参数/枚举和运算符候选。所有候选支持键盘选择、关闭并恢复输入焦点。
- `[REQ-EXP-024]` 明确搜索到但不能作为当前字段最终值、也不能作为其合法中间操作数的纯操作可以保留可见，必须原位禁用并说明适用结果类型。布尔字段中的可比较纯操作必须允许作为中间操作数插入，并提示用户继续输入比较符；未完成草稿只在确认或有效失焦提交时报告最终类型错误，不得在输入过程中阻止字符、恢复旧值或伪装成已提交。输入器不得插入无法由当前目录解析和类型检查的语法；目录加载失败时保留直接值草稿并显示可恢复说明，不得伪造候选。
- `[REQ-EXP-025]` 每个可执行核心纯操作都必须具备可生成的命名空间、规范语法名、用途、参数标签、搜索关键词、示例与结果类型提示；操作集合、发现目录、解析器和语法参考之间的漂移使放行失败。普通函数和扩展函数不进入值语法，扩展不得贡献私有表达式语法。
- `[REQ-EXP-010]` 提取计算值或项目函数只在作用域、次数、惰性、空值、错误和来源语义可证明等价时可用；绑定在同一可撤销事务中迁移，无法无损完成时不提交并解释原因。
- `[REQ-EXP-011]` Player 可以按稳定值节点精确暴露嵌套值；Compiler 为稳定 `control_id` 生成签名覆盖槽，重排、改名和无关编辑不破坏绑定，运行端不读取 ProgramDocument。
- `[REQ-EXP-012]` 循环引用、节点/深度预算、编译时间、ECIR 体积、内存和取消由 Harness 安全门治理；预算不能被宣传为产品表达能力上限。
- `[REQ-EXP-013]` 每个核心纯操作及其输入槽使用稳定 ID；操作注册表版本与内容哈希进入编译、缓存、锁定和发布签名输入。
- `[REQ-EXP-014]` Player 只能覆盖开发者发布的签名值槽，不得注入新操作、结构或引用；父子重叠绑定和过期运行方案必须在运行前阻止。
- `[REQ-EXP-015]` `core.file_ref_child.v1` 使用稳定操作/输入槽 ID，只能在输入目录授权根内派生相对文件引用，输出能力不得大于输入能力且求值时不接触文件系统。
- `[REQ-EXP-016]` `core.json_parse_text.v1` 使用稳定操作/输入槽 ID，把文本解析为 `optional<json>`；非法文本产生正常无结果，资源预算或内部实现故障产生结构化诊断。
- `[REQ-EXP-017]` 基础值转文本、文本严格解析、文本拆分/连接及坐标/区域缩放必须采用上述确定性语义，并在 Windows 与 Android Runtime 中产生相同值、正常无结果或稳定错误；引用对象不得通过通用转文本泄露内部载荷，几何操作不得丢失来源空间元数据。
- `[REQ-EXP-018]` 全部已验证核心纯操作必须可由同一输入器的 `命名空间.操作(参数…)` 语法和上下文补全创建、编辑及往返格式化；帮助、补全和完整语法参考由权威注册表投影。普通函数、I/O 和任意代码不能借该语法内嵌。

### 当前闭环证据

核心纯值注册表以稳定操作 ID 与稳定 `operation_id.input.<name>` 输入槽为编译事实。当前已验证闭环覆盖数值四则/范围/转换、基础标量稳定转文本、文本严格解析为可选整数/小数、文本组合/替换/截取/大小写/去空白/长度/保留空项拆分/连接、正则分组与首个整数提取、日期/时间/日期时间解析/格式化/加减/差值、可选值检查与默认、条件选择、点偏移、点/区域缩放与区域中心、常用不可变列表和字典查询/更新/聚合，以及 JSON 文本解析和路径查询/不可变更新。Compiler 校验操作存在性、精确输入槽和基础输入/结果类型，Windows 与 Android Runtime 对解析无结果、非法格式、时区混用、空分隔符、除零、越界、重复键与集合预算返回一致结果或结构化错误；缩放操作保留附加来源空间元数据。

集合项/序号/键值局部作用域已经由强类型 `SelectorValue` 闭环：绑定拥有稳定 `symbol_id`、封闭角色与显式值类型，嵌套作用域按 ID 遮蔽，Compiler 降低为不含调用能力的 selector ECIR，Runtime 只在集合操作的固定快照行内求值。筛选、转换、按依据稳定排序、分组、查找、任意/全部判断、匹配计数和索引建立已从注册表 `planned` 提升为 `executable`；目录只投影注册表真实可执行项。表达式中的静态子值可由 Compiler 生成非重叠签名 Player 槽，绑定不依赖显示名或可见树路径。

统一输入器已把普通值、稳定引用、成员、比较、布尔组合、纯操作及集合逐项作用域解析回上述既有值节点。浏览器只在进入编辑时请求当前期望类型的目录；用户进入嵌套操作参数后，输入器再按该参数类型按需请求目录，不递归预取无关类型。

`core.file_ref_child.v1` 已形成 Windows 执行闭环，并与 Android Runtime 共用稳定槽 `directory / relative_path`。它只从 `directory_ref<read/read_write>` 派生 `file_ref<read>`，或从 `directory_ref<create/read_write>` 派生 `file_ref<write>`；输出只保留单项所需能力。求值只验证跨平台安全相对位置并生成词法/延迟引用，不调用 `realpath`、读取目录或创建文件；Windows 在实际 I/O 前解析重解析点并验证授权根，Android 由私有目录或 SAF 宿主逐段解析并验证树边界。删除、移动来源与执行引用不得由该操作派生，必须通过对应的显式授权入口取得。

## 11. 明确非目标

- 不把可编辑公式字符串、Python 表达式或任意文本反向解析结果保存为程序事实；允许输入器把当前临时文字解析为既有的强类型核心节点。
- 不允许为了让界面简单而只支持固定两层或少数硬编码组合。
- 不把普通函数调用包装成看似纯值的隐藏表达式。
- 不要求用户为每个简单计算创建临时变量或项目函数。
- 不在本阶段冻结具体中文操作名、图标、像素尺寸和默认展开层数。
