# 结构化集合与外部 JSON

状态：`Approved`（记录、列表、字典、JSON、集合纯计算与运行语义已冻结；具体 Control 排版和性能预算由实现与 Harness 在不改变语义的前提下确定）

最近修订：2026-09-01

## 1. 用户心智模型

- **记录**是一项固定结构的数据，类似表格中的一行；字段由契约声明并使用稳定 `field_id`。
- **列表**是一批有顺序的同类数据，允许重复，内部类型为 `list<T>`。
- **字典**使用动态键查找同类值，键唯一且没有业务顺序，内部类型为 `map<K,V>`；需要顺序时使用列表。
- **JSON 数据**承接外部结构未知的数据。脚本可以验证并转换为记录、列表或字典；未转换的 JSON 使用专用路径操作，不能伪装成强类型记录。

列表和字典可以包含记录及其他集合，但普通强类型集合不能混放无共同类型的任意值。固定字段使用记录，动态键使用字典；未知外部数据使用 JSON。运行值不允许形成循环引用。

## 2. 完整目标场景

副本计划使用 `list<副本配置>` 表达，每项包含名称、启用状态、体力下限、优先级和最大次数。IDE 与 Player 可以把同一 Schema 投影为可排序表格、重复卡片、固定集合多选或开发者批准的字段表单。函数返回的全部图像匹配、OCR 行、消息收件明细、路径点和领域数据也使用有类型列表。

账号配置等“已知键后直接查找值”的数据使用字典，例如 `map<实例引用, 账号配置>`。字典读取缺失键返回可选值；记录字段拼写错误在编辑期诊断，不退化为运行时动态键查找。

## 3. 列表能力

完整目标支持：

- 创建空列表、常量列表、项目变量默认值和由函数、文件、消息或扩展返回的列表；
- 判断为空、数量、包含、首项、末项、按序号读取和查找首个匹配项；
- 添加、前置、插入、替换、删除、清空、重排、合并和去重；
- 筛选、排序、倒序、截取、逐项转换、字段提取、展平和按位置组合；
- 任意/全部判断、匹配计数、求和、平均、最小、最大、分组和按字段建立索引；
- 使用循环依次处理，并提供当前项、当前序号、是否首项和是否末项等局部符号。

按序号读取、首项、末项和查找首项在不存在结果时返回明确空状态。相等、排序、去重和聚合只对类型注册表声明支持的元素类型出现；不支持的操作在检查器中不可选，并在编译前诊断。

## 4. 字典能力

完整目标支持：

- 创建、读取、判断键存在、新增、覆盖、删除和清空；
- 取得全部键、全部值和键值项列表；
- 按键值项循环，并提供当前键和当前值局部符号；
- 合并字典并明确选择冲突时保留旧值、采用新值或报告错误；
- 把记录列表按字段建立字典，或把字典转换为键值记录列表；
- 对键值项执行类型允许的筛选、转换、分组和统计。

字典键必须是类型注册表批准的稳定标量，例如文本、整数、枚举或稳定引用；记录、图片帧和可变集合不能直接成为键。字典不承诺遍历顺序，任何依赖顺序的流程先转换为列表并明确排序。

## 5. 结构化集合计算

筛选、转换、排序、分组和统计属于正式的结构化值计算。ProgramDocument 把它们保存为有类型的集合表达式，由赋值、参数或返回值消费；用户通过中央摘要和右侧表单配置，不书写 `filter/map/reduce`、匿名函数或 JSON 片段。

集合表达式创建受限局部符号，例如当前项、当前序号、当前键和当前值。筛选使用已经冻结的条件树；字段提取、排序依据和逐项转换使用完整递归纯值计算。表达式内部不得调用识图、等待、输入、文件、消息、目标、项目函数或扩展函数。需要这些行为时，脚本使用显式循环和独立调用语句；纯计算即使复杂也不强制提取，开发者仍可为复用或可读性主动提取为项目函数，或由独立扩展函数承接自定义算法。

列表和字典值采用不可变值语义。用户执行“向列表添加”或“覆盖字典键”时，运行时把新集合赋给目标局部/项目变量；实现可以使用持久化数据结构和结构共享，不能因为安全语义无条件复制大型集合。

## 6. 循环与修改

循环开始时固定输入集合快照。循环体修改原变量不会改变本轮尚未处理的项；下一次进入循环才读取新集合。需要持续消费新增项目的业务使用明确队列或条件循环，不能依赖遍历中修改集合的偶然行为。

消息按值传递集合；接收方修改自己的值不改变发送方。任务启动时创建项目变量会话副本，任务结束后释放，不把集合修改写回开发者默认值或 Player 运行方案。

## 7. JSON 互操作

`文件.读取JSON`和消息/接口扩展可以返回 `json_value`。完整目标提供对象、数组、标量、路径存在、路径读取、路径设置、路径删除和遍历能力。路径不存在返回可选值。严格 I/O 函数中的 JSON 语法错误、编码错误，以及违反声明 Schema 的转换属于结构化异常；显式使用纯值探测操作 `core.json_parse_text.v1` 时，非法文本按其契约返回正常无结果，便于先判断再处理。两种入口必须在检查器中使用不同文案，不能静默互换。

开发者可以声明目标记录/集合 Schema，把外部 JSON 验证并转换为强类型值。转换报告定位字段路径、期望类型和实际值；转换成功后，后续脚本使用成员选择器、集合 Control 和静态检查。任意 JSON 不直接成为 Player 的无约束业务表单。

## 8. IDE、Player 与调试

- 简单列表使用逐项编辑、多选或标签；记录列表使用虚拟化表格或重复卡片；字典使用键值表格；嵌套集合使用可展开子表。
- Control 声明最小/最大项数、唯一性、排序、允许键、字段约束、新增/删除/重排权限和平台动作。开发者决定 Player 可以修改哪些字段和结构。
- 调试器展示集合类型、数量、少量预览和按需完整查看；筛选、排序和分组记录输入/输出数量及依据，不把全部大型值刷入日志。
- 大型编辑与运行集合使用虚拟化、有界预览、增量验证和取消；视频帧、无限事件或超大文件流使用独立流式能力，不伪装成已完整加载的列表。
- 坐标、区域、控件和帧等带目标来源的值放入集合后继续保留来源；从集合读取不能绕过跨目标检查。

## 9. 验收要求

- `[REQ-COL-001]` 记录、列表、字典和 JSON 在 Schema、检查器、ProgramDocument、ECIR、Runtime 与 Player 中保持同一类型含义。
- `[REQ-COL-002]` 列表保持顺序并允许重复；字典键唯一且不提供隐式业务顺序。
- `[REQ-COL-003]` 缺失序号、键或查找结果返回明确空状态；类型错误和非法集合操作不能伪装为空结果。严格 JSON I/O/Schema 转换中的无效 JSON 返回结构化异常；只有开发者显式选择 `core.json_parse_text.v1` 时，非法文本才按该纯值操作契约返回正常无结果。
- `[REQ-COL-004]` 筛选、转换、排序、分组和统计使用结构化集合表达式，并只引用当前项/键值和无副作用值计算。
- `[REQ-COL-005]` 需要 I/O、等待、目标观察或普通函数的逐项处理使用显式循环，不得隐藏在集合表达式中。
- `[REQ-COL-006]` 循环遍历固定快照；循环中修改原变量不得改变当前剩余迭代项。
- `[REQ-COL-007]` 集合更新具有不可变值语义，运行时可以结构共享但不能产生跨变量或跨消息的隐式联动修改。
- `[REQ-COL-008]` Player 使用同一类型与约束生成列表、记录和字典表单，不要求终端用户编辑 JSON。
- `[REQ-COL-009]` 外部 JSON 可以按声明 Schema 转为强类型值，失败报告精确字段路径；未知 JSON 继续使用专用操作。
- `[REQ-COL-010]` 排序、相等、去重、聚合和字典键能力只对已声明支持的类型开放。
- `[REQ-COL-011]` 大型集合编辑、调试和 Player 表单采用虚拟化与有界预览；流式数据不物化为无上限列表。
- `[REQ-COL-012]` 集合中的空间值保持来源目标并接受与单值相同的跨目标校验。

## 10. 已冻结边界与实施细节

集合能力和语义按本文件冻结。集合纯计算遵循 [`EXPRESSIONS.md`](EXPRESSIONS.md) 的完整递归组合和 Harness 安全门，不另设产品级浅层嵌套上限。具体投影文案、项目数据表的字段设计流程、Control 默认布局、集合大小预算和实施批次属于实现与测试预算，不得新增第二套数据模型、改变运行语义或缩减本文件定义的目标能力；若确需改变这些边界，必须通过新的架构决策和需求编号重新审批。

当前实现以 `SelectorValue` 承载受限词法绑定。列表选择器只创建稳定的“当前项/当前序号”符号，字典选择器只创建稳定的“当前键/当前值”符号；显示名允许内外层相同，引用始终按 `symbol_id` 解析，因此嵌套选择器可以遮蔽显示名而不会串用值。选择器只能位于注册表声明的 `predicate / transform / key_selector` 输入，内部仍是普通递归纯值树，不能保存或执行普通函数、I/O、等待和目标访问。

当前自动闭环已覆盖 `list_filter / list_map / list_sort_by / list_group_by / list_flatten / list_zip / list_find_first / list_any / list_all / list_count_match / list_index_by`、`map_filter / map_map_values / map_group_by` 与 `json_validate_schema`。实现固定输入快照、短路查找/任意/全部判断、稳定排序、缺失首项返回可选空值、索引重复键结构化错误、100,000 项运行预算和每 256 项取消检查；10,000 项专项基线已通过。JSON Schema 使用无远程引用、无 I/O 的可移植严格子集，覆盖类型、对象字段/必填/额外字段、数组项目/唯一性、组合条件、枚举/常量、文本和数值约束；无效 Schema 与数据不匹配分别产生结构化错误，后者包含精确路径。

Compiler 为动态表达式中最大的非重叠静态子树生成 `value_id` 签名覆盖槽；IDE Player 来源目录只展示这些真实槽，运行时按 `function_id + statement_id + parameter_id + value_id` 校验并覆盖本次 ECIR 深拷贝。槽表、纯值注册表版本与内容哈希都进入 ECIR revision 和发布完整性签名。上述结论是 Windows 本机自动化证据，不替代 Windows/ADB Player 或 Android 本机真实宿主验收。
