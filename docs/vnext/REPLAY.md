## 1. 首版范围与边界

首个正式版本必须在 Windows、Android ADB 和 Android 本机提供同一高层语义的帧录制与离线回放。开发者可以在 IDE 中录制独立目标或把录制附加到调试运行；Windows 与 Android Player 可以按运行方案保存录制设置，并在任务开始前向终端用户显示真实状态。录制默认关闭，任何 Player 录制都必须由终端用户主动开启或确认到当前运行方案 revision，作者不能通过更新静默开启。

“完整回放”指保存可验证的目标帧序列，并在目标离线后浏览、比较和重新执行已声明为可回放的图像与 OCR 分析；它不表示重新执行输入、文件、消息、网络或其他外部副作用，也不恢复旧调用栈、目标现场或中断任务。UIA/Accessibility 控件树不是像素帧的一部分，首版不伪装成能从帧中重建控件现场；若未来需要控件回放，必须另行设计版本化控件快照。页面导航不因回放进入首版，`page` 仍只是通用图片资源目录。

录制只覆盖当前运行目标的工作区，不录制无关桌面、其他窗口或设备内容。目标切换时，同一录制会话建立新的目标片段并保留各自的 `target_id`、空间版本与时间线，不能把不同目标的坐标或区域合并到同一空间。

## 2. 录制模型

Recorder Service 管理以下稳定对象：

- `recording_session_id`：一次录制会话，记录产品/项目、运行、实例、开始与结束状态、录制策略和存储策略。
- `recording_segment_id`：同一目标与空间版本内的连续片段；目标、方向、尺寸、DPI 或空间版本变化时关闭旧片段并建立新片段。
- `frame_id`：会话内单调序号的不可变帧，保存像素内容哈希、采集时间、目标时间、像素尺寸、方向、DPI、目标与空间版本。
- `marker_id`：用户标记、运行语句标记、失败证据或丢帧/背压标记，只引用帧与运行事件，不修改帧。
- `analysis_run_id`：一次离线分析，固定输入帧集、ProgramDocument/ECIR、资源、官方函数契约、OCR 模型/字典和分析配置版本。

每个已保存帧使用无损像素编码；“无损”不等于允许无限缓冲。写盘使用有界队列，来不及持久化的采集必须生成带起止序号与原因的丢帧事件，不能伪造为连续帧序列。会话终态固定区分：已完成、用户停止、用户取消、磁盘保护停止、权限失效、目标失效、驱动失败和进程中断。

## 3. 录制策略与资源保护

首版支持三种策略：

1. **全部帧**：保存录制宿主在会话期间交付的每一帧；用于时序排查与完整离线分析。
2. **变化帧**：按确定性变化判定只保存发生可见变化的帧，同时记录被合并的帧数与时间跨度。
3. **诊断**：保留有界的最近帧环形缓冲，并在失败、断点或用户标记时提交前后证据片段。

录制设置至少包含策略、目标、最大持续时间、最大本机空间和磁盘保护阈值。具体默认数值由 Harness 在基线硬件与真实 Android 设备上冻结；任何默认值都不得允许录制耗尽系统盘或应用沙箱。达到时长、配额或磁盘保护阈值时只停止录制并记录原因，不能擅自停止正在运行的自动化任务。

Recorder Service 独立于图像/OCR 分析 Worker，使用有界缓冲、批量索引和可取消写入。停止、Esc、权限撤销、驱动失败、应用进入后台和进程结束均只能关闭资源一次。未启用录制时不启动帧订阅、编码器、索引器或清理轮询。

## 4. 不可变录制事实

录制会话只保存目标帧、帧序、时间、像素与目标元数据、运行/语句标记、丢帧/背压事件和用户标记。图像、OCR 或其他分析结果不写回录制数据。

录制目录包含版本化会话清单、分段索引、逐帧内容哈希和会话级校验摘要。缺帧、重复序号、哈希失配、截断索引或不支持的格式版本必须显示为损坏/不完整，不能继续生成看似可信的分析结论。删除录制属于本机数据管理操作，不修改项目、发布包、ProgramDocument 或运行日志。

## 5. 可重现的分析快照

每次分析使用用户当前选定的项目模型和契约重新计算结果，不依赖旧分析缓存。分析开始前，Replay Service 先生成不可变、按内容寻址的 `AnalysisInputBundle`：IDE 分析保存本次使用的规范化 ProgramDocument 与编译产物，Player/已发布分析保存签名 ECIR；两者按实际依赖闭包保存资源字节、官方函数契约、OCR 模型/字典、分析参数和对应官方回放实现。这个快照只用于重现实验，不成为当前可编辑项目或发布源码。一份可重现的分析报告必须链接：

- 录制会话 ID、精确帧范围、帧序列哈希和目标元数据；
- `AnalysisInputBundle` ID 与完整哈希，以及其中的 ProgramDocument `document_id + revision + content_hash` 或已发布 ECIR `release_id + content_hash`；
- 资源清单与实际文件哈希；
- 官方函数契约、OCR 模型/字典、`easycode.lock`、ECIR 和编译器版本；
- 分析函数、参数、区域、阈值、平台实现版本和耗时结果。

修改 ProgramDocument、函数契约、资源、区域或阈值后可以对同一帧集重新分析。新分析生成新的 `AnalysisInputBundle`、`analysis_run_id` 与版本链，不覆盖旧报告，也不回写帧、ProgramDocument 或资源。相同输入、契约和实现版本必须产生规范化等价结果；实现若不能保证确定性，报告必须明确标记，并不得宣称可重现。清理输入快照前必须展示哪些报告会从“可重现”降级为“仅可查看既有结果”；不能只保存 revision/hash 却宣称将来一定能恢复已经不存在的字节。

## 6. 离线回放能力

- 浏览本机录制会话、目标片段、帧时间线、运行标记、用户标记和明确的缺帧区间。
- 逐帧、跳转、倍速浏览、关键帧缩略图和相邻/指定帧像素比较；大录制使用虚拟化时间线和按需解码。
- 对单帧或帧集运行已发布为“可回放”的官方图像与 OCR 分析，展示命中证据、文字、错误、单帧耗时与集合统计。
- `image / ocr / page` 三个根目录在历史帧录入资源时始终可选；`page` 中的图片按普通资源参与已声明分析，不激活页面导航或专用扫描。
- 把历史帧送入冻结 Capture 宿主，从已有画面取点、框选和录入资源；界面持续显示“历史帧”，不得偷偷重新截取当前目标。
- 从分析结果定位原帧、目标片段、实际资源/契约版本和对应运行事件；从运行错误也能反向打开相关历史帧。

首版只有官方图像/OCR 函数中声明为无外部副作用、输入完全来自帧/资源/参数且提供专用回放实现的函数可以进入离线分析。第三方 Python/原生扩展即使自称无副作用，也不能进入首版回放 Worker；开放扩展回放前必须先具备无法取得目标、输入、文件、消息和网络能力的独立隔离契约及恶意实现 Harness。输入、等待真实时间、目标切换、文件、消息、网络、更新和任意扩展副作用函数一律不能在回放工作区执行；界面不显示假运行按钮，服务端也拒绝绕过界面的直接请求。

## 7. 工作区与 Player 交互

IDE 的“运行记录”工作区采用三栏结构：左侧是按项目/日期/目标筛选的录制会话，中间是帧查看器与虚拟化时间线，右侧是帧元数据、标记、比较和分析检查器。单击会话或帧只改变选择；删除、导出、创建资源和启动分析使用显式动作。录制中的会话显示持续时间、已用空间、丢帧和停止原因，不用模拟进度。

Player 的录制设置进入运行方案或诊断设置，不常驻挤占主表单。开始运行前只在录制已开启时显示策略、目标和预计空间边界；运行中以克制状态点显示录制、空间和丢帧状态，并提供“停止录制但继续任务”。Android 小屏在独立“运行记录”页面浏览与导出，不把桌面三栏压缩到单列首屏。

录制默认只保存在当前设备。导出固定区分两种模式：默认“画面与报告”只包含所选帧、时间线元数据、既有报告和校验清单，不包含 ProgramDocument、ECIR、资源或 `AnalysisInputBundle`；高级“可重现分析包”才包含用户明确选择的 `AnalysisInputBundle` 及其代码/ECIR、资源、模型和参数依赖。导出前必须逐类展示会话时间、目标、大小、敏感画面、项目逻辑、资源和参数范围；秘密值不能被默认带出，排除必要依赖后包必须降级标记为“仅可查看”或“不可完整重现”。平台不自动上传录制，更新、托管或普通遥测也不能取得录制内容。

## 8. 生命周期、清理与兼容

录制数据位于 IDE 测试环境或 `product_id + Player instance` 隔离的本机数据目录，不进入项目目录、Git、`.ecplayer`、Android APK 或在线更新内容。清理策略只能删除已关闭且不再被导出/分析任务使用的会话；活动会话、用户锁定会话和仍被分析报告引用的会话必须明确提示影响。

Windows、ADB 与 Android 本机使用相同会话/帧/分析契约。Android 额外保留方向、显示尺寸、MediaProjection 会话与前后台变化；回放不要求连接原手机，也不能把旧帧当作当前权限或目标仍有效的证明。应用被系统终止后保留已完整提交的帧与“进程中断”终态，不自动恢复录制或旧任务。

## 9. 崩溃诊断边界

运行时持续追加结构化日志。有外部副作用的操作使用同一 `operation_id` 记录开始与完成/失败。诊断包在可取得的范围内包含项目/发布版本、运行/实例/目标 ID、稳定 `function_id + statement_id + value_id` 与可读字段路径、ECIR 调试映射、扩展/契约版本、消息 ID、最后动作、异常和失败截图或诊断录制片段。

只有“开始”而没有终态的动作标记为“结果未知”，不推断成功或失败。首版不根据日志或录制自动恢复旧调用栈、目标现场或监听事件；重启后的新任务使用新运行 ID 从入口开始。

Android 本机诊断在系统允许的范围内额外记录设备型号、Android/API 版本、应用版本、Runtime/扩展 ABI、屏幕方向与像素尺寸、MediaProjection/无障碍/前台服务/文件授权状态、前后台状态，以及最后帧或无法取得帧的原因。诊断导出遵守脱敏与发布权限，不把授权令牌、签名秘密或用户未批准的完整文件带入证据包。

## 10. 首版需求

- `[REQ-REPLAY-001]` Windows、ADB 与 Android 本机均能创建、停止、取消并恢复浏览本机录制会话，且使用同一版本化会话/帧契约。
- `[REQ-REPLAY-002]` 全部帧、变化帧与诊断三种策略具有确定行为；每个保存帧像素无损，任何未保存区间均以丢帧事件呈现。
- `[REQ-REPLAY-003]` 目标、方向、尺寸、DPI 或空间版本变化建立新片段；不同片段的空间值不能静默混用。
- `[REQ-REPLAY-004]` 时长、空间、磁盘保护、背压、权限、目标和进程故障进入明确终态；停止录制不停止自动化任务。
- `[REQ-REPLAY-005]` 录制帧、索引与哈希不可变；损坏、截断和版本不兼容不能生成伪可信分析报告。
- `[REQ-REPLAY-006]` 离线工作区支持时间线浏览、帧比较、官方图像/OCR 分析及从历史帧取点、框选和录入资源；像素帧不承诺重建控件树。
- `[REQ-REPLAY-007]` 每次分析保存不可变、按内容寻址且包含实际重现依赖的 `AnalysisInputBundle` 并生成新报告；相同确定性输入产生规范化等价结果，分析不得回写任何输入。
- `[REQ-REPLAY-008]` 首版回放只执行已声明的官方无副作用图像/OCR 分析函数；第三方扩展、所有目标操作、I/O、真实等待和副作用函数在回放工作区不可执行，直接请求同样被拒绝。
- `[REQ-REPLAY-009]` IDE 与 Player 的录制默认关闭；Player 只能由终端用户主动开启或确认到当前运行方案 revision，更新不能静默开启。
- `[REQ-REPLAY-010]` 未启用录制时零帧订阅、编码、索引和清理轮询；启用后内存、CPU、写盘与磁盘占用受 Harness 预算约束。
- `[REQ-REPLAY-011]` 录制默认只留在当前设备，只有用户显式导出后才能离开；默认导出不包含分析输入快照，高级可重现导出必须逐类披露并显式选择 `AnalysisInputBundle`，两种包都包含校验与隐私清单。
- `[REQ-REPLAY-012]` 录制与回放不修改或注册为 ProgramDocument/ECIR Schema、函数目录或程序运行语义；只读分析快照可以包含其实际字节，但不引入崩溃续接、页面导航或第二套运行语义。

## 11. 验收基线

Harness 至少覆盖：三种录制策略、帧哈希与顺序、目标/方向/尺寸切换、主动停止与取消、有界队列、人工制造背压、低磁盘、配额耗尽、权限撤销、驱动/进程中断、异常退出后的索引恢复、损坏与截断检测、长期录制资源占用、相同输入重放确定性、版本变化报告分叉、历史帧 Capture、服务端拒绝副作用与第三方回放实现、Player 同意与更新不静默开启、两种导出的内容差异、校验与隐私扫描，以及 Windows、ADB 和至少两档真实 Android 设备上的性能与生命周期冒烟。

录制能力、浏览工作区、离线分析、历史帧 Capture、Player 控制、数据清理、导出和跨平台真实宿主未全部通过前，首个正式版本不得放行。
