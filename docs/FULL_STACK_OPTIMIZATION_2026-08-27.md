# EasyCode 前后端深度优化审计与执行计划

> 审计日期：2026-08-27  
> 适用范围：EasyCode IDE、Player、Capture Host、FastAPI API、执行引擎与子项目数据链路  
> 原则：先保证正确、可恢复、可解释，再优化架构、性能和视觉细节；所有结论必须由测试或可复现实验支撑。

## 1. 目标

本轮不是一次表面换肤，也不以“大文件变小”作为唯一成功标准。最终目标是：

1. 用户在流程、函数和页面地图之间编辑时不丢数据，不因隐式状态或异步竞态得到错误结果。
2. 前端每个入口都具有明确用途、统一反馈和可预测的键鼠行为；视觉层级服务于高密度 IDE 工作。
3. 后端路由、领域服务、执行引擎、设备适配和持久化边界清晰，错误不会被吞掉或伪装成成功。
4. 高频路径只做必要工作：画布拖动不刷新资源预览，纯逻辑节点不截图，视觉测试不因无关状态反复触发。
5. PC、模拟器、ADB 真机、多开和 Player 的能力降级可见、可解释、可阻止。
6. 建立可以反复执行的质量门禁，使后续新增节点和能力不会重新引入同类问题。

## 2. 不可破坏的约束

- 保留 Vue 3 + Vite + Pinia 与 FastAPI + Python 的总体技术路线，不为追求“原生感”进行无收益的框架迁移。
- 保留原生 Capture Host 处理桌面级低延迟交互，Vue 负责业务编辑和资源管理的边界。
- 不迁移或猜测已明确废弃的旧项目格式；当前 Schema 是唯一真实来源。
- 当前工作区存在尚未提交的大型重构，所有修改必须增量实施，不回滚、不覆盖不相关用户改动。
- 任何后台截图、后台输入或 ADB 投递失败都不能伪报成功；物理输入回退仍由用户显式授权。
- 弹窗处理与页面寻路保持独立；非视觉、非输入节点不触发页面或弹窗扫描。
- 自动保存是默认契约。模式切换、函数切换、关闭/隐藏页面前必须刷新待保存状态。
- UI 图标统一使用 Lucide；不使用 Emoji 充当交互图标。日志正文可保留语义性符号，但必须有结构化级别。
- 不以一次全量自动格式化制造巨大 diff；静态检查按风险和模块逐步收敛。

## 4. 审计发现

### P0：必须先修复的正确性问题

1. `VisionService.test_image_recognition()` 的实时测试分支使用 `np.array()`，但模块没有导入 `numpy`。模板预览分支正常，用户点击“测试识别”时可能直接 500。
2. `GraphExecutor` 在任务循环中定义的 `_edge_jump()` 闭包引用可变循环局部变量 `out_edges`。函数调用帧延迟消费跳转映射时可能读取后续节点的出口，属于低概率但严重的错误路由风险。
3. `CapabilityService.invoke()` 的后台 Worker 闭包引用每次重试都会被重新赋值的 `capability_context` 与 `response_queue`。超时 Worker 尚未退出而进入下一次重试时，旧 Worker 可能把结果投递到新队列，造成串次、假成功或错误超时。
4. 模式、函数或工作区切换必须统一执行“刷新表单状态 → 保存当前文档 → 验证工作区代次 → 切换数据源”。任何入口绕过该协议都可能重现编辑丢失。

### P1：用户信任、错误语义与安全边界

1. 远程协调器当前允许任意 `urllib` scheme。应只接受明确的 `http/https`，拒绝 `file:` 和自定义协议，并在配置阶段而非发送阶段报告错误。
2. API 路由中存在大量 `except Exception -> HTTPException(str(e))`。需要建立领域错误到 HTTP 状态码的统一映射，保留异常链和日志关联 ID，避免同一错误在不同入口表现不同。
3. 后端存在多处宽泛异常吞掉后继续运行的路径。允许降级的地方必须记录“能力不可用”的结构化原因；不允许降级的地方必须终止当前操作。
4. 前端自动保存、捕获、运行和资源事务的错误提示必须区分：用户输入错误、目标状态冲突、可重试基础设施错误、不可恢复数据错误。
5. 删除、移动、导入和捕获保存必须保持资源索引、节点引用、区域元数据与撤销事务一致，不能只改文件系统。

### P2：架构与性能债务

#### 前端

- `CanvasView.vue`、`CanvasPage.vue`、`IdeLayout.vue` 同时承担渲染、手势、选择、路由、快捷键、保存协调和宿主通信，职责边界过宽。拆分应以可测试的行为域为单位，而不是机械拆文件。
- 画布事件需统一成 Pointer Event/RAF 批处理；拖动时只更新选择集和受影响连线，其他节点、缩略图与自动布局冻结。
- 全局事件监听、轮询和定时器要通过统一生命周期工具管理，保证组件卸载、项目切换和 HMR 后不残留。
- 六处深度监听需要逐个改为字段级变更或版本号触发，避免大图结构每次输入都深遍历。
- 资源预览缓存只由资源 ID、资源版本和预处理参数失效，不能受节点位置、选择状态或变量修改影响。
- 左右面板标题、工具区和空状态应遵循单一层级：外壳有标题则内容不重复；内容自带标题则外壳保持无标题。
- 81 处 Emoji/符号需区分“日志文本”与“UI 图标”；UI 中逐步替换为 Lucide，日志保留文本语义并减少装饰噪声。

#### 后端

- `executor.py` 约 1900 行，已形成执行循环、函数调用帧、弹窗、页面稳定、智能跳转、输入准备等多个变化原因。应抽取无状态策略和会话对象，保留单一调度入口。
- 捕获、输入、Android 流、OCR 和模板匹配应通过运行时能力接口返回统一结果，不让节点执行器直接猜测提供器差异。
- 多实例运行应继续强化进程隔离、资源租约、有界队列和背压；单实例故障不能污染其他实例。
- SQLite 的消息/计划 claim 已使用参数化值，动态内容只有由代码生成的 `?` 占位符；保留实现并添加说明/测试，避免为消除误报改成更差的逐条更新。
- 同步 CPU/IO 重任务不得直接阻塞 FastAPI 事件循环；路由需要明确委托到线程/进程 Worker 或后台任务。
- 服务级全局单例必须具有清晰的启动、停止、清理和测试重置协议。

### P3：一致性与维护成本

- 清理 Ruff 中不会改变语义的未使用导入、异常链、上下文管理器和导入顺序，但按模块提交、按模块测试。
- ESLint 五个格式警告清零，并把 lint/build/test 纳入统一质量脚本。
- 更新过期架构文档中的节点数量、组件名称和已删除概念；文档描述必须来自当前代码，而不是历史设计。
- 为性能测试固定数据集与硬件信息，避免“感觉变快”成为验收标准。

## 5. 目标架构

### 5.1 前端分层

```text
View / Panel
  └─ domain composable（交互协议、生命周期、派生状态）
      └─ Pinia domain store（项目事实状态）
          └─ API client（工作区身份、错误归一化、取消/超时）
              └─ FastAPI contract
```

- 组件只负责可见结构与局部交互，不直接编排多个后端事务。
- Store 保存项目事实状态；短暂手势、弹窗开关和 hover 状态留在组件/组合式函数。
- 模式/函数切换、自动保存、资源变更与执行控制分别有唯一协调器。
- 所有后端请求经 API 层，并携带活动工作区身份，禁止组件内原始请求。

### 5.2 后端分层

```text
Router（协议与鉴权）
  └─ Application service（用例、事务、错误映射）
      ├─ Domain service（蓝图、资源、执行、捕获、Player）
      ├─ Runtime ports（Capture / Input / OCR / Android）
      └─ Repository / Store（JSON 原子写、SQLite 事务、密包）
```

- Router 不包含业务分支和持久化细节。
- Application service 负责一次用户操作的完整事务与补偿。
- Runtime port 统一能力、投递结果、验证结果和降级原因。
- Executor 只编排节点与控制流，具体页面扫描、弹窗策略、输入验证由独立协作者承担。

## 7. 测试矩阵与验收标准

| 领域 | 核心场景 | 验收标准 |
| --- | --- | --- |
| 自动保存 | 表单输入后 Enter、点击画布、切模式、切函数、关闭页面 | 最终值落盘；切换后重载不丢失；旧工作区响应不能覆盖新项目 |
| 画布 | 创建/连线/断线/多选/拖动/复制粘贴/撤销 | ID 唯一、内部连线保留、首节点正确接入、无孤立幽灵边 |
| 函数 | 契约、局部变量、调用、返回端口、重试 | 参数类型明确，出口映射稳定，超时 Worker 不串次 |
| 页面地图 | 页面识别、随机弹窗、智能跳转 | 只评估 page_state；弹窗不进入寻路；无特征节点不污染候选 |
| 资源 | 录入、移动、删除、恢复、重名 | 三目录始终可选；索引/区域/节点引用事务一致；不静默覆盖 |
| 捕获 | 最小化、遮挡、后台帧、历史帧 | 获取完整新鲜帧或明确阻止；坐标只在工作区内；退出释放宿主 |
| 输入 | 后台输入、ADB、物理回退 | 返回真实投递状态；回退只在授权时发生；后置条件可验证 |
| Player | 配置、实例、环境、诊断、恢复 | 状态机一致；秘密脱敏；单实例失败不影响其他实例 |
| 性能 | 拖动画布、视觉循环、多开 | 无无关预览请求；队列有界；指标可见；没有资源随时间持续增长 |

## 8. 性能预算

- 普通表单输入到 UI 反馈：目标小于 50ms；保存异步且不阻塞输入。
- 常驻 WGC 热帧获取：以现有约 2–3ms 为回归基线；冷启动单独记录。
- 画布拖动：目标 60 FPS；高密度场景允许降级但不得低于 30 FPS 且不触发资源请求。
- 高频视觉节点：每轮只捕获一次帧，同帧预处理和 OCR 结果共享。
- API 普通元数据请求：本机 P95 目标小于 100ms；长任务立即返回任务 ID。
- 所有队列有界；达到上限时明确丢弃策略和指标，不允许无限积压。

## 9. 已完成迭代记录

### 迭代 1：正确性与可信错误

- 修复视觉测试缺失 NumPy 导入、函数调用出口闭包捕获和能力重试 Worker 串次。
- 远程协调器只接受 HTTP/HTTPS，拒绝文件协议和未知 scheme。
- API 客户端可读取 FastAPI 结构化 `detail.message`，不再向用户显示 `[object Object]`。
- 蓝图和执行路由的意外异常在本地记录完整堆栈，并给前端返回不泄露本地路径的 `error_id`。
- 后台输入失败、ADB 不可用、捕获失败和物理回退继续遵守显式能力结果，不伪报成功。

### 迭代 2：自动保存与工作区隔离

- 自动保存快照延后到防抖真正执行时生成，连续输入不会每次深克隆大型图。
- 元数据、工作流、页面地图和完整保存共享一条串行写入队列；跨域保存不能乱序覆盖。
- 立即重试成功会清除对应错误，失败计数始终在 finally 中恢复。
- 项目切换先刷新表单和保存队列，再切换 workspace generation；旧请求不能写入新项目。
- 全局变量和批量画布操作按真实数据域保存，页面地图批量编辑不再误写主流程。

### 迭代 3：画布与视觉热路径

- 画布鼠标移动由 RAF 合并；拖动时使用轻量正交连线，松手后恢复完整避障。
- 新增节点渲染对象缓存，未变化节点在其他节点拖动时保持对象身份，不重绘图片、端口和内容卡片。
- 图像预览只响应图片引用、已提交的灰度参数和手动刷新；无图片时零视觉请求。
- OCR 预览只在明确参数提交后刷新，独立运行日志输出实际识别文字。
- 外部项目变化改为 30 秒兜底检查，并保留窗口重新聚焦时立即检查，不再成为画布常驻热路径。

### 迭代 4：后端文件与目录热路径

- 项目变更中间件使用显式路由分类；运行、暂停、捕获心跳、预热等请求不再触发项目目录扫描。
- 高频文档保存只更新变更文件的 size/mtime 指纹；资源树事务才完整扫描模板、脚本和能力目录。
- 版本历史新增轻量 `index.json`，常规列表和保存不再解析最多 100 份完整蓝图；缺失、损坏或发现外部快照时自动重建。
- 项目文件、Player 配置、配置方案和执行恢复点统一采用 UUID 临时文件、fsync 和原子替换。
- Player 配置方案写入串行化；备用加密密钥通过完整临时文件加原子硬链接发布，避免并发初始化生成不可解密数据。

### 迭代 5：前端信息架构与视觉

- 移除区块及其持久化/显示逻辑，避免无执行语义的第二套分组模型。
- 三模式只由左侧活动栏切换；函数库先展示列表，选择函数后进入画布，契约放在右侧函数检查器。
- 去除顶部与画布重复面包屑和项目标题；外壳标题与内容标题只保留一层。
- 节点类型在列表与检查器使用中文 Schema 标签；主操作图标统一 Lucide。
- 函数契约抽成真正 Vue 子组件，修复动态渲染导致 scoped CSS 不生效的原生灰色控件。
- 工具浮层、全景图、检查器、菜单、空状态、圆角和焦点环统一到当前石墨黑/暖橙设计令牌。

### 迭代 6：架构与质量基础设施

## 11. 仍需真实设备验收的边界

以下不是已知代码失败，而是当前机器自动测试无法替代的硬件/第三方条件：

- 不同显卡驱动下 WGC、DXGI、PrintWindow 对遮挡、最小化和独占全屏的实际能力。
- 2/4/8 个真实模拟器同时开启时的 CPU、GPU、内存、ADB serial 唯一性和最大稳定实例数。
- 真实 Android 设备的编码器差异、断线重连和长时间 PyAV 解码稳定性。
- 只接受 Raw Input/DirectInput、带保护画面或反作弊的软件；这类目标必须在接单前做能力探测。
- PyInstaller 最终 EXE 在一台未安装 Python 的干净 Windows 机器上的安装包级验收。

这些场景必须记录硬件、驱动、分辨率、DPI、模拟器版本和运行时指标后再给出承诺；不能用单元测试结果替代设备验收。
