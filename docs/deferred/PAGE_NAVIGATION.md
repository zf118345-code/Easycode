# 页面导航（延期立项记录）

状态：`Deferred`（不属于首个正式版本，不授权实现）

最近修订：2026-08-31

本文件保存已经撤出活动规格的历史方案，仅供未来立项时复盘。当前产品不交付页面导航包、工作区、`页面.*` 函数、Page Model、扫描服务、拓扑投影或 Player 依赖。`image / ocr / page` 仍是通用资源分类，`page` 只表示资源保存位置。

未来若重新引入页面导航，必须新建功能规格、架构决策、失败语义和端到端 Harness，并重新审查领域模型与跨平台闭包；下文不得作为当前实现、完成门或兼容性合同。

## 历史方案（不构成当前规格）

### 1. 定位与边界

页面导航随 EasyCode IDE 分发，但是按项目默认关闭的官方功能扩展，不是通用程序模型的必选组成。它只解决“观察当前页面、规划导航路径、执行页面转换并验证结果”这一领域问题。

项目启用扩展前，IDE 必须说明将新增的工作区、函数、项目数据和发布依赖，并由用户明确确认。未启用时必须同时满足以下“五个零”：

1. **零入口**：不显示页面工作区、页面命令或页面模型创建入口。通用资源系统的 `page` 根目录不是扩展入口，始终保留。
2. **零函数**：不向函数注册表贡献 `页面.*` 函数与相关契约。
3. **零后台**：不启动 Worker、页面观察、帧扫描、轮询或缓存预热。
4. **零运行依赖**：不进入编译输入、ECIR 或 IDE 调试运行闭包。
5. **零 Player 污染**：不进入 `.ecplayer` 依赖闭包，不增加 Player 包体或启动开销。

`image / ocr / page` 是通用资源分类，三个根目录在所有资源选择、录入和捕获入口始终可见、可切换。在 `page` 中保存普通图片不会自动启用页面导航扩展，也不会创建 Page Model。

### 2. Page Model 是唯一业务事实

页面扩展使用版本化、确定性 JSON 持久化 `PageModel`，数据位于扩展包 ID 的项目命名空间中。精确目录和线格式随扩展 Manifest 一并冻结，但必须满足：

- 页面、观察条件、页面级组合方式、出口、覆盖弹窗和恢复策略只在 Page Model 中维护一份。
- 每个页面、特征、出口和覆盖规则使用稳定 ID；显示名、分组和图上位置不是运行键。
- 页面级决定“全部满足 / 任一满足”；单个特征不重复保存 AND/OR。
- 观察条件通过已注册、有类型的图像、OCR 或控件契约表达，不保存可编辑源码或自由表达式字符串。
- 出口动作引用项目函数，或使用与 ProgramDocument 相同的类型化语句片段；不引入第二套动作节点 Schema。

拓扑图是 Page Model 的派生投影。重建、自动布局或删除视图元数据不得改变页面识别或导航关系。若保存节点位置、折叠和视口，它们只能进入可删除的视图元数据，不得进入 Page Model 的业务语义。

### 3. 运行闭环

```text
目标的新鲜帧 / 控件信息
          ↓
页面观察：命中 / 未知 / 冲突
          ↓
路径规划：当前页面 → 目标页面
          ↓
执行一个出口的 ProgramDocument 动作
          ↓
获取新鲜帧并验证预期页面
          ↓
继续 / 重试 / 重新规划 / 明确失败
```

- 观察器只评估 Page Model 中的页面，不把普通函数或图像操作误当页面候选。
- 每个出口可包含多条动作；出口成功不以“已点击”代替目标页面验证。
- 观察输入必须来自当前 `target_id` 的新鲜帧；目标切换、帧过期或扩展禁用会取消本次导航。
- 未知、多页面冲突、无路径、出口动作失败、目标验证失败和重试用尽是不同的结构化错误，日志不得合并为“跳转失败”。
- 编译器只把当前项目已启用页面扩展的契约、Page Model 和运行闭包纳入 ECIR 依赖。

### 4. 覆盖弹窗与中断

随机弹窗是对当前页面的覆盖/中断，不是普通 BFS 节点，也不因复用相同关闭图片而生成错误页面关系。

首版至少保留以下不变式：

- 覆盖规则必须显式属于 Page Model，而不是潜入普通图像扫描。
- 处理覆盖弹窗时不并发执行另一条界面操作流。
- 处理结束后必须重新获取新鲜帧、重新观察并决定继续还是重新规划。
- 自动扫描频率、显式处理入口、优先级和失败恢复在页面专题中冻结；本规格不将旧实现默认提升为新契约。

### 5. 编辑、禁用与发布

- 首期优先使用结构化列表和检查器编辑 Page Model；拓扑图在同一模型和命令协议稳定后提供派生浏览或受约束编辑。
- 禁用、更新或卸载前检查 ProgramDocument 中的 `页面.*` 调用、出口动作引用、Player Schema、资源和其他扩展引用。存在引用时默认阻止，并给出稳定 ID 定位。
- 项目关闭扩展后不删除尚未处理的命名空间数据；它们保留为明确的已禁用数据，但不被编译或运行。
- 发布前验证扩展版本、Page Model Schema、契约、所有页面资源、出口动作和目标平台支持；任一闭包不完整时阻止发布。
- Android 本机发布使用当前手机的本机帧、图像/OCR观察和 Android 输入函数执行出口；Page Model 本身不分叉出第二份 Android 模型。引用 Windows UIA 控件特征、Windows-only 出口函数或缺少 Android 运行模块时，发布器按稳定 ID 定位并阻止 Android APK。

### 6. 回放与可观测性

离线回放使用不可变录制帧，并明确链接分析时的 ProgramDocument revision、Page Model revision、资源哈希、函数/扩展契约版本、扩展锁和编译器版本。分析结果是可重建产物，不写回帧、ProgramDocument、Page Model 或资源。

结构化日志至少记录扩展包 ID、Page Model revision、当前/目标页面 ID、规划出口 ID、观察结果、动作 `statement_id`、重试/重新规划原因和耗时。

### 7. 验收要求

- `[AC-PAGE-OFF-001]` 新项目默认关闭页面扩展，五个零在 IDE 空闲、编译、调试和 Player 发布中均有可重复证据；`page` 通用资源目录仍可正常使用且不激活扩展。
- `[AC-PAGE-MODEL-001]` 编辑 Page Model 后重建拓扑图，页面、出口和运行行为不变；删除视图元数据也不改变行为。
- `[AC-PAGE-RUN-001]` 未知、冲突、无路径、出口失败、目标验证失败和覆盖打断展示不同错误与可定位证据。
- `[AC-PAGE-REPLAY-001]` 相同帧集和相同链接版本生成确定性分析结果；任一契约或模型版本不同时报告明确标识。
- `[AC-PAGE-AND-001]` 使用图像/OCR特征与 Android 兼容出口的固定 Page Model 在 Android 真机完成观察、规划、执行和目标验证；Windows-only 特征或出口在生成 APK 前被阻止。
