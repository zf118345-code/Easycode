# EasyCode 规格讨论路线图

状态：`Approved / Closed`（首版会改变实现路线的产品与架构问题已经关闭；本文保留讨论顺序与实施回查规则）

最近修订：2026-09-01

本路线图回答“先讨论什么、后讨论什么、还剩多少关键轮次”。它不承诺固定日期；每次大方向决定后更新状态、合并重复问题并重新估算。产品事实仍以 `PRODUCT.md`、`ARCHITECTURE.md`、`design.md`、`TEST_HARNESS.md`、`DECISIONS.md` 和 `docs/vnext/*.md` 为准。

## 1. 总体顺序：先大后小

后续讨论不得从单个输入框、函数名字或视觉间距倒推整体架构，固定按以下层级推进：

```text
产品目标与非目标
        ↓
核心领域对象与唯一事实来源
        ↓
编译、运行、扩展与跨平台边界
        ↓
领域能力模型（变量、控制流、目标、消息、资源等）
        ↓
IDE / Player 工作区与端到端任务流
        ↓
Control、默认值、命名、文案、尺寸与视觉细节
        ↓
Harness、实施切片与发布门
```

上层未冻结时，不用下层局部原型作长期承诺；下层发现上层缺陷时，明确退回对应层，不用补丁掩盖。

## 2. 讨论规则

1. 每轮只关闭一个会改变领域模型、运行语义、扩展边界、Player 契约或主要交互的问题。
2. 新增用户可见概念、函数、模式或入口前，先证明 ProgramDocument 普通语句、项目函数、项目变量、Control 或现有扩展点无法表达。
3. 先冻结能力、数据流、失败和生命周期，再统一函数命名、字段布局和视觉；示例摘要不是持久格式承诺。
4. 可以共享实现但语义不同的动作保留独立契约；语义相同的功能不因入口不同复制后端。
5. 数值上限、缓存大小、编码集合和内部路径等低风险参数由 Harness 形成推荐表，在最终冻结前集中快速审批，不逐项占用架构轮次。这些数值只用于解析、编译、运行和内存安全，不得反向缩减已冻结的产品表达能力。
6. 每轮结束更新细分规格、ADR、验收要求和本路线图；关键未知项不得只留在聊天记录。
7. 全部关键问题关闭后执行跨文档和需求追踪审查，再由用户确认是否从 `Proposed` 升为 `Approved`。

## 3. 已冻结的大方向

| 过去候选 | 当前结论 |
| --- | --- |
| 流程画布、可编辑中文源码、结构化表单并列 | ProgramDocument 是项目函数唯一可编辑事实；中央为纵向语句投影，右侧为 Control；无用户源码编辑 |
| AST 作为文本中转层 | 不维护用户语言、词法和解析器；ProgramDocument 直接持久化强类型结构 |
| IDE 与 Player 各自解释流程 | 同一 Compiler Service 生成确定性 ECIR，IDE 调试与 Player 执行同一语义 |
| 原子、标准、项目、扩展四个普通入口 | 用户按用途寻找官方/项目/扩展函数；原子/标准只作为实现与治理分类 |
| 调用能力单独存在 | 取消；Python/原生实现经强类型扩展函数进入普通函数注册表 |
| EasyCode 内置 Python 编辑器 | 取消；外部 IDE 开发，EasyCode 负责骨架、导入、契约、测试和发布闭包 |
| 页面拓扑是每个项目核心入口 | 首个正式版本取消页面导航与拓扑；`page` 只保留为通用资源分类，未来有明确需求时重新立项 |
| 系统/上下文/配置/持久变量 | 前台只有局部变量与项目变量；环境值用函数，长期数据用文件 |
| `存储.*` 和租约 | 取消；显式 `文件.*`，普通脚本不暴露租约 |
| `任务.确保完成` 特殊函数 | 取消；保留为“先观察—必要时执行—执行后验证”的项目函数编写模式 |
| 多套捕获页面 | 统一 Capture Session 与 Control 动作 |
| Windows/ADB 各自业务语义 | ProgramDocument/ECIR 统一；目标驱动与能力不同，单实例可串行切换 Windows/ADB |
| 崩溃自动续接 | 首版取消；保留诊断，重新运行从入口开始；主动暂停可在同一进程继续 |
| 消息完成等于业务完成 | 已读只表示接收脚本取得数据；业务结果由项目函数判断 |
| 精简核心就必须减少用户可用函数 | 核心原语保持最小；官方目录可以提供经多项目验证的高频标准组合，且不新增第二套运行语义 |
| Android 本机只是模糊预留 | Android 本机属于首个正式版本完成门；签名 APK 必须脱离电脑独立运行并通过真机 Harness，未完成前不显示可用入口；iOS/macOS 不在范围内 |
| 独立 Player 只表示不安装 Python | Player 本地优先；无公网项目携带完整闭包，不依赖公网、IDE、EasyCode 云或单独后端；LAN/公网能力由真实依赖显式分级，失败局部隔离 |
| 商业授权必须随首版一起做 | 首版只做包签名与完整性，不显示收费激活入口；商业授权作为重要后续独立切片，完整设计后再接入 |
| 大型脚本更新仍靠作者逐个重新分发 | 首版提供可关闭的在线更新；IDE、Player 应用与项目内容分层，更新失败不影响当前有效版本 |
| 更新分发只能依赖 EasyCode 云或完全交给作者 | 官方托管作为默认主路径，同时开放同一签名 Feed 给自建 HTTPS 对象存储/CDN；VIP/付费额度后续单独设计 |
| 作者只能提示更新或可以远程中断任务 | 支持可选/强制更新；强制策略带签名和宽限，只约束新任务，绝不打断运行或暂停现场 |
| 终端要么被迫自动更新，要么可以绕过所有强制策略 | 可选更新的检查/下载/应用由终端分别控制；已验证强制策略不可绕过，宽限期内仍由用户择时；作者关闭更新时零入口、零外连 |
| 稳定更新只能一次性全量或依赖追踪设备的云端分群 | 可选更新使用本机匿名确定性分桶，支持白名单、百分比、暂停/继续和全量；无运行遥测，强制更新不分组 |
| 应用/窗口控制全部交给扩展或开放任意系统命令 | 官方提供受约束的应用启动/退出等待和 Windows 窗口查询/操作；任意 Shell、PowerShell 与系统命令仍只能通过权限明确的扩展进入 |
| 视觉函数始终共享隐式截图或每次都要求手动取帧 | 普通调用自动取得新帧；需要同一时刻分析时显式取得不可变帧并复用，所有结果保留来源目标 |
| 查找未命中和等待到期都算异常 | 二者是正常明确空结果；资源、权限、目标、平台和驱动/扩展故障才是结构化异常 |
| 函数跟随安装版本自动升级或永不演进 | 项目锁定稳定 ID、契约版本与指纹；兼容更新和破坏性迁移都显式确认，旧项目保留可构建路径 |
| HTTP 文件传输塞进普通请求或全部交给扩展 | 普通文本/JSON 请求、multipart 文件上传和原子文件下载是三个独立原子能力；文件流式读写且不进入 ProgramDocument 值或整块内存 |
| 完整录制/回放留到以后或只保留失败截图 | 首版必须完成 Windows、ADB、Android 本机的三种帧录制、历史时间线、官方图像/OCR 离线分析、历史 Capture、两种显式导出和真实宿主 Harness；像素帧不虚构控件树回放 |
| 目录功能以后扩充或递归删除复用普通删除 | 首版提供七项 `目录.*` 能力；递归删除是独立危险函数，使用授权根、作者审核、IDE/Player 实际执行确认、保护根与越界防护；复制/移动不合并覆盖既有目录 |

## 5. ProgramDocument、函数与扩展阶段结论

ProgramDocument 作为唯一事实，以及“值和逻辑能表达多复杂”已经冻结。函数和扩展治理也已关闭：具体函数集合不得从旧节点名机械搬运，扩展不得绕过版本化清单、信任、锁定和发布闭包。

ProgramDocument 语义阶段已关闭以下产品级问题：

1. **已冻结**：条件同时支持布尔值、类型化比较与 `all/any/not`，禁止隐式真假转换和副作用。
2. **已冻结**：函数只有一个逻辑返回；多字段使用命名记录，无结果使用明确可选值，确认“有结果”后访问成员。
3. **已冻结**：普通函数不嵌套；含普通调用或副作用的逻辑先调用并绑定结果，参数允许基于现有值的确定性、无副作用、可递归纯值计算。
4. **已冻结**：记录、列表、字典与 JSON 边界明确；筛选/转换/排序/分组/统计属于集合表达式，I/O 与普通函数逐项处理使用快照循环。
5. **已冻结**：所有批准的纯值操作可完整递归组合；界面用摘要、折叠、聚焦和可撤销提取管理复杂度，不设产品级浅层上限。
6. **已冻结**：持久化值节点拥有稳定 `value_id`；纵向投影、检查器、诊断、调试和 Player 可以安全定位嵌套值，技术预算只作 Harness 安全门。

阶段 C 已冻结“最小运行核心 + 经筛选的官方标准函数”：高频组合可以改善普通用户效率，但不得增加隐藏运行机制或按行业堆积函数。规范目录固定为 [`vnext/FUNCTIONS.md`](vnext/FUNCTIONS.md) 的 60 个稳定函数；扩展固定使用 [`vnext/EXTENSIONS.md`](vnext/EXTENSIONS.md) 的 `easycode-extension.json` v1、`easycode.lock` v1 和密封运行产物。应用/窗口、视觉新帧/显式同帧复用、正常无结果与异常、异常区域可选重试，以及普通 HTTP/文件上传/文件下载三项独立网络能力均已冻结。后续改变这些基线必须新增或取代 ADR，不能由实现便利静默扩张。

## 6. 每阶段完成门

- 用户可见概念、对象和入口列清楚，不存在同义重复。
- 唯一事实、稳定 ID、持久化和编译输入明确。
- 成功、失败、取消、暂停、超时、禁用和平台不支持有明确结果。
- IDE、Runtime、Player、扩展和 Android 本机契约不矛盾。
- 关键决定写入 ADR；需求有稳定 ID 和可验证验收项。
- 没有会改变下一阶段实现路线的开放问题。

## 7. 动态调整规则

- 新例子只影响当前领域：加入当前阶段，不越级修改 UI 细节。
- 新决定推翻 ProgramDocument、ECIR 或扩展信任：退回阶段 A/B 并更新所有权威文档。
- 新需求可由普通项目函数组合：不新增平台函数，只记录标准函数候选。
- 同一问题连续两轮仍抽象不清：制作最小结构模型或交互原型，再继续审批。
- 用户出现讨论疲劳：低风险项采用推荐默认表批量审批，只保留高风险问题逐个确认。
- 实施发现代码事实冲突：不让旧实现反向修改目标；若事实揭示目标不可行，停止对应切片并回到规格。
